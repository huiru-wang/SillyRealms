# SillyRealms · 产品总纲

> 状态：产品方向及范围，2026-11-01；不表示功能已经实现。返回[文档索引](README.md)。

## 产品定位

SillyRealms 是一个**以世界为核心、以持续叙事为基础、可按需引入记忆与状态能力的本地优先 LLM 交互前端**。用户选择世界、开局与参与方式，使用自己配置的模型持续推动故事。无需把每个故事强行变成数值模拟；长篇叙事的细节与连续性始终是核心体验。

**核心旅程：** 选择世界 → 选择开局/身份 → 开始并持续互动 → 查看或调整故事 → 从选定路线继续。

## 产品对象与体验

| 对象 | 用户理解与职责 |
| --- | --- |
| 世界卡（World Card） | 可创建、导入、编辑、发布的世界内容及加载条件：角色、场景、开局、世界资料和可选规则；不能控制 Prompt 节点顺序与角色 |
| 世界实例（Session） | 一次独立的故事历程；保留世界定义快照及其全部故事发展可能性 |
| 消息与分叉 | 用户在历史 User 消息处明确创建世界分叉，从其前一条 AI 消息新增另一条 User 路径；单点最多三条。聊天始终进入一条真实叶子的最新消息，世界线总览只显示压缩拓扑 |
| Context | 世界卡筛选候选内容，预设定义 Prompt 节点的唯一排列和角色，按当前世界线历史组装最终输入并提供构建依据 |
| 预设与模型连接 | 保留一套只读、不可删除的基础默认预设（10 个固定节点）；自定义预设保留基础节点并支持重排、启停与新增文本节点，再绑定用户模型/API 连接 |
| 记忆和状态 | 可选能力：作者在世界卡中定义简洁状态字段，Opening 可覆盖初始值；运行时 Agent 依据叙事结算并在每条 Entry 保存完整状态快照，不替代叙事本身 |

世界卡可发布严格递增的**两段内容版本**。已有世界实例不会自动跟随更新；用户可选择手动同步，新的设定只影响之后的互动，已发生的剧情保持不变。角色卡兼容与导入能力不能被误认为完全等同于 SillyTavern。

## 世界实例、会话与消息的核心交互

**导航路径：** 世界卡库 → 世界实例列表 → 聊天主界面 ↔ 全局世界线视图。可以另设跨世界的「最近会话」快捷入口，但不会创建第二种会话实体。**一个世界实例即一局 Session**，拥有完整的 Entry 消息树；世界线只是其中某条真实历史路径，不是独立会话。

- **进入实例**：选择世界卡后查看已有世界实例，也可选择开局、身份和必要配置创建新实例。点击已有实例，恢复 `active_leaf_entry_id` 对应的上次活动世界线，**默认进入其最新消息**，仅加载最近约 30 条祖先消息；不恢复历史中间阅读位置。
- **聊天为主界面**：只显示活动叶子的一条祖先路径；向上滚动分页读取更早消息，向下只是浏览已经加载的内容。AI 消息实际存在 2～3 条直接 User 后续时展示 `2/3`、`3/3` 分叉标记；历史 User 提供「创建世界分叉」和编辑入口。
- **世界线负责导航**：全屏预览压缩后的 Root / Fork / Branch Start / Leaf 拓扑；普通中间消息不加载正文，只在连线上显示隐藏数量。选择真实叶子可高亮其路径，但不允许从中间 Entry 进入聊天，也不提供在总览里展开整段消息。
- **预览与切换分离**：在全局世界线中临时选中某个真实叶子只改变高亮；点击「进入这条世界线」或明确提交新历史分叉，才更新持久化的活动叶子。进入后清理旧分页、回到新叶子最新消息；不存在独立的临时阅读世界线。
- **滚动与定位**：聊天仅支持向上查询更早祖先，向下滚动不产生新的历史查询；不提供任意消息定位窗口或历史中间进入。向上插入消息保持视觉锚点，用户读旧消息时新生成内容不强制滚到底部。长篇聊天与全局拓扑均不一次性拉取所有消息正文。
- **消息操作边界**：历史消息可编辑但不自动重生成后代；只允许当前路线最后一条 AI 消息重生成或续写；暂不提供删除消息。

完整的页面组织、最新页读取、仅向上游标、压缩世界线总览和显式叶子选择以[会话领域设计](design/session.md)为准；SQL/API 见[存储](technical/storage.md)。

## 产品形态

- **本地服务 + 浏览器 UI，H5 / 移动端体验优先**，同时适配桌面与平板。
- **本地优先**：世界、故事、预设和配置保存在用户自己管理的设备；不依赖 SillyRealms 云服务。
- **模型自选**：可使用用户配置的远程模型服务；手机经局域网访问电脑服务时电脑需保持运行。
- 世界卡与预设具备导入导出需求，数据备份与资源管理另行规划。

## 交付阶段

**首期 MVP 目标：** 管理世界卡、选择并发布世界、创建实例并从活动叶子最新页恢复聊天、提供不可删除的基础 Prompt 预设及自定义节点编排、管理模型/API 连接、生成流式回复及移动端交互；**包含基础真实世界分叉、压缩拓扑预览、明确选叶子并回到该叶子末尾、只向上分页及历史正文基础编辑**。消息从第一天保留完整 Entry 父子树，但客户端不提供任意消息定位。

**后续体验：** 任意 Entry 直接定位、消息搜索及跳转、双向历史窗口、可缩放完整世界线画布/长链正文展开、AI 帮答行动项、更复杂的 AI 重生成/续写、历史压缩/记忆、跨设备阅读位置恢复。历史 User 分叉与基础历史编辑已在会话领域确定；**消息删除不开放**，历史编辑不自动重生成后代。

**未来探索：** 长期记忆、结构化状态的实际运行实现、资源管理、独立原生 App、云端或多设备协同；世界卡状态定义及 Opening 覆盖的设计已明确，但不表示状态引擎已在首期实现。
