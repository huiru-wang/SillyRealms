## 实际验证了什么

- 最小文字 JSON 与完整 ZIP 经过生产导入接口导入，并成功创建会话。
- 完整示例的两个开局都能显示对应正文与初始状态。
- 介绍组件、正文中的港口插图、角色图片与手记在浏览器中正常加载。
- “看看信封”按钮将行动填入输入草稿，再由玩家发送。
- 实际发送两轮行动，叙事完成；第二轮购买热茶后，保存的 `coins` 为 `10`，手记显示 10，回复附有行动建议。
- 重新打开会话后，对话与 10 枚银币仍可读取。
- 1360 × 900、390 × 844 和 320 × 740 浏览器视口没有检测到主页面或舞台的横向溢出；窄屏手记可以展开、收起。
- 本轮浏览器检查没有捕获到未处理的 JavaScript 异常，示例图片均已加载。

窄屏检查使用桌面 Chromium 的视口模拟，尚未代表所有手机系统、软键盘与浏览器的实机验证。

## 状态更新的真实边界

第一轮询问信封时，模型写出了线索，但没有提交状态更新。第二轮购买热茶成功更新了银币，线索列表仍为空。截图与动图保留了这个结果。

这说明 **正文中出现一件事，不等于相应状态已经保存**。作者应核对状态处理结果、状态规则、启用的预设及后续上下文。静态检查只能确认结构、引用和组件依赖，不能保证模型每一轮都按创作意图行事。排错步骤见[状态与玩法](../creator/state-and-rules.md)和[常见问题](../creator/troubleshooting.md)。

## 复现

按[快速体验](../getting-started.md)导入示例，并使用“渡轮靠岸”开局：

1. 点击“看看信封”，确认草稿后发送。
2. 再明确支付两枚银币购买热茶，等待回复与状态处理完成。
3. 核对正文中的交易、状态处理结果与手记中的余额。
4. 重新打开会话，确认保存结果；缩窄窗口后展开手记。

录制使用临时测试世界、会话与预设副本，没有把凭据、运行配置或会话数据打入可分享的世界卡。
