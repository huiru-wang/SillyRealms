# 世界卡开放 OTA 协议 v1

本页定义公开发行源与 SR 本地更新的现行契约。作品发行信息使用世界卡 0.2 的 `data.publication`，目录协议使用独立的 `schema_version: 1`；作者内容版本为稳定数字三段，三者不能混用。字段定义见[世界卡格式](world-card.md#作品发行信息)，实际发版步骤见[作者发行指南](../creator/world-publishing.md)。

公开发行源只需要固定 JSON 地址和各版完整文件。创作者、社区或第三方可以使用任意公开 HTTPS 域名和路径，也可以让动态 API 返回相同结构；客户端不要求官方域名、provider 类型、注册中心、Hub、Discord、账号或专用上传服务。

## 三种地址

| 地址 | 内容与用途 |
| --- | --- |
| `publication.homepage` | 面向人的作品页面，可选 HTTP(S) |
| `publication.update_url` | 面向程序的固定公开 HTTPS 全版本目录，可选；跨版本保持稳定 |
| `versions[].artifact.url` | 对应某一明确版本的完整原始 ZIP/JSON，公开 HTTPS |

目录及发行文件必须无需登录、Cookie、API Key、验证码或浏览器脚本即可直接 GET。可以使用固定查询参数，不能依赖短期签名。HTML 下载介绍页、网盘分享页或代码托管的文件浏览页不能代替原始 JSON/ZIP。

检查由 SR Server 发起；浏览器只访问自己的 Server，因此作者源无需为此配置浏览器 CORS。目录与 ZIP 可以来自不同公开 HTTPS 域名。每次请求及重定向均执行网络目标检查，拒绝凭据、片段和本地/私网等非公开目标，不能借更新源访问玩家内网。

## 远端请求

1. 对 `update_url` GET，成功响应为 HTTP 200 和目录 JSON 本身，不包裹本地 API 的 `success/data`。
2. 从完整目录中按完全相等的 `version` 选择唯一条目。
3. 对选中条目的 `artifact.url` GET，取得该版原始 ZIP/JSON 字节；以目录中的大小和 SHA-256 核对实际结果。
4. SR 在本地执行导入校验和覆盖。发布源不提供远程执行安装的接口。

建议目录与 JSON 卡使用 `application/json`，ZIP 使用 `application/zip`；内容仍须验证。失败 HTTP 响应、HTML 正文和非法目录都作为失败，不解释为“没有新版”。客户端检查目录时不下载各版完整世界卡。

请求使用 `Accept-Encoding: identity`；当前要求响应不使用 HTTP 内容压缩，或显式返回 `Content-Encoding: identity`。限制针对实际响应字节，不能通过 Content-Length 或分页绕过：

| 项目 | 当前限制 |
| --- | --- |
| 目录正文 | 2 MiB，包含空白与扩展字段 |
| 完整目录记录数 | 1000 |
| 目录请求 | 10 秒 |
| 发行文件下载 | 120 秒，JSON 10 MiB、ZIP 256 MiB |
| 重定向 | 最多 3 次，每次重新校验公开 HTTPS 与 DNS 目标 |
| 启动批次并发 | 3 张卡 |

超时或超限作为失败，不截断、不使用部分目录。ZIP 解压和资源限制继续沿用[世界卡格式](world-card.md#资源和大小限制)。

## 全版本目录

以下为格式示例，域名、哈希和大小不是可供安装的真实发行产物；实际值由发行工具生成。

~~~json
{
  "schema_version": 1,
  "package_id": "8da0e392-2ea6-4ac1-a93a-b94abf6828a1",
  "versions": [
    {
      "version": "1.10.0",
      "title": "港口夜巡",
      "published_at": "2026-11-26T12:00:00+08:00",
      "notes": "新增夜巡开局，修复背包显示。",
      "spec_version": "0.2",
      "artifact": {
        "format": "zip",
        "url": "https://cdn.example.org/worlds/my-world/versions/1.10.0/my-world.zip",
        "sha256": "1111111111111111111111111111111111111111111111111111111111111111",
        "size_bytes": 12582912
      }
    },
    {
      "version": "1.9.0",
      "published_at": "2026-11-01T12:00:00+08:00",
      "notes": "首次开放港口。",
      "spec_version": "0.2",
      "artifact": {
        "format": "zip",
        "url": "https://cdn.example.org/worlds/my-world/versions/1.9.0/my-world.zip",
        "sha256": "2222222222222222222222222222222222222222222222222222222222222222",
        "size_bytes": 10485760
      }
    }
  ]
}
~~~

| 字段 | 约束 |
| --- | --- |
| `schema_version` | 固定整数 1 |
| `package_id` | 规范小写 UUID，必须与已安装作品相同 |
| `versions` | 当前仍公开的全部发行记录；可以为空，不分页、不截断 |
| `version` | 唯一的稳定 `MAJOR.MINOR.PATCH`，每段为非负安全整数，无多余前导零 |
| `title` | 可选版本标题 |
| `published_at` | 带时区的 ISO 8601 发布时间，只展示，不参与版本排序 |
| `notes` | 本版更新说明，允许空字符串 |
| `spec_version` | 发行文件中的世界卡格式版本；下载后与包内核对 |
| `artifact.format` | `zip` 或 `json` |
| `artifact.url` | 直接取得该版本原件的公开 HTTPS 绝对地址 |
| `artifact.sha256` | 最终文件原始字节的 64 位小写十六进制 SHA-256 |
| `artifact.size_bytes` | 最终文件字节数，正安全整数；下载后核对实际大小 |

纯 JSON 文件必须能够独立通过正式导入校验，不能引用未包含的 `sr-asset://` 文件。包含组件文件和媒体的作品推荐 ZIP。当前远端应用支持带正式发行身份的世界卡 0.2；其他 `spec_version` 仍展示在目录中，安装按钮禁用并提示检查 SR 版本。0.1 的普通导入兼容不等于允许无发行身份的卡参与覆盖。

目录允许未知非必需扩展字段；它们不能改变既有字段含义。破坏性协议变更需要新的 `schema_version`。不要把所有 `world.json` 内联进目录。

## 排序与不可变发行

数字三段逐段比较，所以 `1.10.0 > 1.9.0`。不接受 `v1.2.0`、`1.2`、`01.2.0`、自由文本、预发行或构建后缀。版本标题不能替代机器版本。

最新版本是有效目录中的最大版本，与数组位置和发布时间无关。空目录的最新版为 null。不需要另存 `latest` 或 `recommended`，也没有测试版/稳定版通道。目录中包含当前平台尚不能安装的新格式时，仍展示真实最高版本。

同一 `package_id + version` 绑定不可变文件。已有成功目录与新目录中的相同版本若 SHA-256 不同，整份新目录拒绝并保留旧目录。重复版本、错误字段或作品身份不匹配同样整份拒绝。不能从部分合法条目推断“最新”。

允许修改目录的说明文字，或把相同哈希的文件迁到新的公开地址。包内字节发生变化则发布新版本；不能让历史版本链接都指向 `latest.zip`。哈希用于核对文件内容，不提供作者账号认证，也不形成永久全网发行审计。

## 本地保存与检查

`publication_json` 只保存当前安装的正式 `WorldPublication`，旧卡无声明时为 null。成功目录保存到当前数据根下：

~~~text
worlds/<worldId>/
├── source/          当前安装版原始文件
├── package/         当前安装内容、组件与素材
└── releases.json    最近一次成功获取的远端原始 JSON
~~~

该布局跟随 `SERVER_DATA_ROOT`。目录先完整验证，再原子保存收到的 UTF-8 JSON 正文；保留原始排列和允许的扩展字段，不增加本地包装、来源标记、状态 sidecar 或数据库缓存。每次成功整体替换当前目录，已经撤下的发行记录不累计保留。

文件缺失、损坏或作品身份不匹配时按无可用目录处理。失败保留上次成功文件及其 mtime；首次失败不生成伪目录。安装包中的同名文件不能成为本地缓存，导出和资源接口也不包含世界根部的 `releases.json`。

Server 成功监听后自动检查一轮，用户也可在详情明确点击获取/刷新。普通列表、详情和版本 GET 只读本地数据；打开弹窗或导入新卡不会暗中访问作者源。没有周期检查、自动重试、安装队列或自动安装。新导入的卡可以立即手动获取目录，无需重启。

同一应用实例合并同世界、作品身份和来源的进行中检查，直到文件发布结束；任务完成后的下一次手动刷新会重新请求。来源或世界生命周期失效时丢弃晚到结果。删除撤销相关任务；应用任意版本保留既有来源。关闭时取消网络并等待正在提交或补偿的操作收尾。

| 展示字段 | 来源 |
| --- | --- |
| `currentVersion` | 当前 `publication.release.version` |
| `latestVersion` | 当前有效目录中的最大稳定版本 |
| `lastSuccessAt` | 有效目录文件 mtime，Unix 毫秒 |
| `lastAttemptAt/errorCode` | 当前进程最近检查记录 |
| `updateStatus` | `no_source/not_checked/checking/ready/failed` 的内存与文件投影 |

尝试时间、失败和 checking 不持久保存。重启可读旧成功目录及 mtime，但不恢复上次进程的错误。目录刷新不改当前发行版本、作者内容、世界 revision、管理时间或玩家状态。

## 应用指定版本

玩家明确选择并确认后，客户端提交 `version`、目录条目的 `expectedSha256` 和当前世界的 `expectedRevision`。下载地址由 Server 从本地目录取出，不接受临时任意 URL。只下载所选版本的原件，不读取“最新版路径”，也不用本地导出冒充发行原件。

Server 在正式替换前检查：

- 作品 ID、发行版本及卡格式与选中记录一致，文件大小和哈希准确。
- 真实世界卡、资源及组件声明通过导入校验。
- 已有会话的玩家角色仍存在且可扮演。
- 持续保留的 global 根集合和根类型完全一致；已有会话时 session/message 同样要求根集合与类型一致。数字 min/max 只允许放宽，本期不扫描全部历史后再允许收紧。
- 世界 revision 未变化，且没有冲突的叙事、AI 帮答或写入操作。

下载期间可继续游玩；最终覆盖短暂占用该世界，并与叙事/帮答、新会话和状态写入互斥。其他世界不受影响。失败保留或恢复已安装内容，不仅修改版本号。

成功保留 worldId、已有会话/消息和三种 scope 的运行状态，以及本地名称、标签、封面马赛克、默认预设与模型绑定。目标版替换作者内容及 `source/package`；运行状态不重新初始化，也不通过回退回滚历史。当前 `update_url` 与 `releases.json` 原文件/mtime 保留，回退不会切回旧更新源。

应用成功后通过现有会话 SSE 发布 `world.updated`。详情重建发行内容对应的作者预览；已打开会话重取世界内容并按发行版本重建舞台，保留工作区、输入草稿和历史。单纯目录刷新不发布此事件，也不重建预览。

## HTTP 与界面

玩家本地的版本接口、响应形状和错误语义见 [Server HTTP](../runtime/server-http.md#世界版本与覆盖)，会话通知见 [Server 事件](../runtime/server-events.md#世界内容更新)。它们不是作者托管源必须提供的 API。

列表红点仅表示 `latestVersion > currentVersion`。查看更新说明不消除红点，安装最新后消除，回退后重新比较。尚未获取目录不能声称“已是最新版”；检查失败时仍可按旧目录计算，并在详情显示时效与错误。版本弹窗提供获取/刷新、完整版本说明、升级或回退确认，界面行为见 [Web 管理](../runtime/web-management.md#世界发行与版本列表)。
