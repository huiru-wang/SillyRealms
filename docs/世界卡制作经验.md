# 世界卡制作经验

这份笔记保留创作与迁移中反复遇到的判断方法。第一次制作请从[创作者手册](creator/README.md)开始；字段与协议以[格式参考](reference/world-card.md)和当前校验器为准。完整可运行的公共例子是[雾港来信](../examples/worlds/README.md)。

## 先还原行为，再安排字段

迁移旧作品时，先读角色、开局、世界书、变量、正则和脚本。世界书目录只能告诉你有什么资料；按钮和写入逻辑才能说明玩家做了什么、下一轮会发生什么。

为每条内容和每个交互记录来源、触发条件、目标位置与取舍。内容被拆分到角色、状态和开局后，原条目应仍可追踪。不能等价实现的行为明确记录，避免把“可以导入”当成“玩法已还原”。[迁移流程与映射表](creator/from-sillytavern.md)

## 按事实的生命周期组织状态

| 事实 | 通常放在哪里 |
| --- | --- |
| 选中这个身份就成立的身世 | 角色 prompt |
| 本局难度、建角选择 | session |
| 当前金钱、年龄、位置和线索 | message |
| 确实需要所有会话共享的信息 | global |
| 人物生活的共同世界和演绎资料 | 世界书 |

同一事实尽量只保留一个当前值。开局年龄和当前年龄有时值得分开：前者解释身世，后者随剧情增长。界面、人物 prompt 和世界书要读取正确的值，不让一份旧文案长期覆盖新状态。

对象根被开局覆盖时，需要列全希望保留的字段。数组按完整根替换。规则写清变化依据和保留旧值的场景，但不把规则当成程序校验或剧情真实性证明。[状态与规则](creator/state-and-rules.md)

## 分开考虑加载与取值

条目是否加载、正文引用哪个值，是两件事。关键词用来减少无关材料；when 用来筛选当前玩法或阶段；state 字段插值读取当前事实。

“提到了某人”不一定意味着他在场，“加载了真相资料”不意味着玩家已经知道真相。只供组件控制的值可以不进入模型材料，但仍要让实际启用的规则读取正确状态。[世界内容与变量](creator/world-content.md)

## 区分浏览、修改与行动

浏览地图只应改变视图，不应把人物传送到该地点。改一项本局设定，不应重置已经发生的剧情。填入行动建议只是草稿，不能提前执行结果。

建角或设置表单要逐项检查保存结果，不能只改本地 UI 就宣称成功。平台详情预览没有会话身份；会话交互放在 Stage，并使用 SDK。[呈现与交互](creator/presentation.md)

## 验证三个不同对象

制作目录是编辑来源，ZIP 是交付物，导入副本是实际运行内容。三者可能处于不同版本。

先检查源码，再打包，再检查最终 ZIP，最后导入并试玩。至少验证两个开局或互斥选择、一次真实状态变化，以及一次仅浏览的操作。检查新值出现，也检查旧值和未选分支是否仍被常驻资料带进模型。[打包与分享](creator/packaging.md)

如需把这些方法用于自己的作品，可让 Agent 读取 [sr-tavern-migrate](../skills/sr-tavern-migrate/SKILL.md)，按真实原文件建立映射与验收记录。
