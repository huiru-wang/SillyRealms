# 世界卡制作经验

## 先还原原卡的行为

从酒馆 PNG 读取角色定义、开场消息、世界书、初始变量、正则、脚本和外部资源。对照脚本中的按钮与保存逻辑，查清玩家点了什么、实际写到了哪里、下一轮会发生什么。世界书索引可以说明有哪些条目，脚本才说明这些条目怎样参与游玩。

为原条目记录目标位置、触发条件和取舍。黎安原卡有 71 条世界书，制作版保留 65 条，其余 6 条分别落到角色、状态和开局。原手札确实允许编辑全部条目，并直接写回绑定的世界书。本版按当前需求保留玩法选择，正文编辑留给后续的平台编辑器，因此没有为 65 条各建一份会话修订稿或启用开关。[逐条还原映射](../resources/worlds/灭仇家满门之后，我收养了想对我复仇的孤女/验收/还原映射.md)

## 按事实的归属和生命周期分配内容

| 判断依据 | 放在哪里 | 黎安卡举例 |
| --- | --- | --- |
| 每次选择该角色都成立的身份与身世 | 可扮演角色的 `characters[].prompt`，选中后进入 `persona.prompt` | “仇”组织天榜第三，十年前躲在井中逃过灭门 |
| 玩家建角时要回答的问题和全部备选项 | 建角组件；中途允许改选时复用同一份题目与映射 | “这些年”五问中，“钱”对应“你颇有家资” |
| 本局开局背景、已选答案和玩法偏好 | `session`，由玩家在本局设定中调整 | 开局年龄、开局前的经历、实际选择的答案、难度 |
| 可随剧情发展或由玩家更正的当前事实 | `message`，开局组件直接初始化，后续消息继承并按规则更新 | 当前姓名、性别、年龄、营生、技能、修为、地点 |
| 确实需要同一世界的多个会话共享的值 | `global` | 本卡的主角姓名、难度和线路均按局保存，全局域可留空 |
| 人物共同生活的世界及按需取用的演绎素材 | 世界书 | 天榜制度、无锡风貌、黎安的阶段与节日习俗 |

同一事实只保留一个当前值。开局年龄与当前年龄值得分开，前者用于倒推十年前的往事，后者随剧情跨年增长。姓名在本卡只有一个当前值，统一读写 `message.user.姓名`。开局会整项覆盖的消息状态根，要在状态定义和 `openings[].initial_state` 都列全字段，避免开局后子路径消失。

对模型可更新的消息字段，`rules` 写清更新依据和保留旧值的情形。例如，玩家明确更名才改本名，旁人喊绰号仍沿用原值。规则文字供模型判断；程序校验路径和数据结构，不能凭语义规则证明剧情中确实发生了更名。手札与模型应读写同一份当前状态。[上下文素材选择实现](../apps/server/src/usecases/context/stages/materials/index.ts)

## 按原句含义选择变量

先辨认原句是在称呼操作者、指代故事中的主角，还是确实要输出姓名。黎安原世界书使用过 `<user>`；“配合玩家的玩法”直接写“玩家”，“与主角同行”直接写“主角”。人物需要唤名时才代入本名，还要看该人物是否已经得知姓名。

SillyRealms 的 `{{user}}` 展开为所选角色定义的名称，本卡会得到“天榜第三”。本局取名“沈青”后，角色提示词和已激活的世界书正文写 `{{state.message.user.姓名}}` 才会得到“沈青”。姓名留空时，本卡约定叙述称“你”。若别的卡将姓名设计为固定的会话字段，也可按其实际定义引用 `{{state.session.人设.姓名}}`。

按路径引用可读取已加载的 `global`、`session`、`message` 状态根及其对象字段。数字 0 会保留，对象和数组整体输出为 JSON，数组下标不受支持。无法解析的状态路径或未加载的状态根展开为空；未知的自定义占位如 `{{ weather.today }}` 原样保留。插入的状态值不会再次展开。整域变量 `{{state.message}}`、`{{state.session}}`、`{{state.global}}` 用在预设的世界状态节点。[字段读取实现](../apps/server/src/usecases/context/lib/state-variable.ts)

## 分别决定条目何时加载、正文需要哪些值

- **常识和地理**可按常驻或关键词加载。《修炼体系》被“修为”等词触发后，正文读取双方当前修为与武学。如此即使人物已经突破，也不会反复向模型声明开局境界。
- **互斥玩法**在开局选择一次。之后每轮组装上下文时，只加载符合当前选择的规则。选「简单」就只取简单难度正文。加载模式为 `always` 的条目仍须满足自己的 `when` 条件。
- **节日和剧情示范**要区分触发、已发生和角色知情。自动节日核对当前剧情日期；回忆“去年中秋”不会让今天过节。启用真相示范也不会直接更新黎安的「已揭真相」。
- **控制值和叙事正文**分别考虑可见性。手动节日开关、未选线路目录等可以设为 `load.mode: "never"`，供组件和 `when` 的 `getState` 使用。需要模型遵循的当前自订线路，单独按选中条件加载其名称和走向。黎安卡的 65 条中，24 条只需常驻或关键词，另外 41 条有实际玩法条件。

## 区分玩家查看、修改和开始游玩的入口

世界简介面向选卡前的玩家，交代“我扮演谁、眼前发生了什么、可以怎样玩”，避免剧透后续真相。建角组件负责收集资料并核对写入结果，全部保存成功后再标记建角完成。若会话创建时已有开场消息，完成建角后展示该消息，接着玩家行动继续。

游玩中，江湖手札展示剧情人物、时间、事件和地图；本局设定负责改名、改选五问和调整玩法。浏览地图只改变界面选中项。修改五问时，答案和对应关键词一起保存，避免选项变了、旧关键词仍进入模型。修改开局背景也不应把当下的年龄、修为或地点重置。[本卡验收记录](../resources/worlds/灭仇家满门之后，我收养了想对我复仇的孤女/验收/验收记录.md)

## 用下一轮模型输入和最终 ZIP 验收

1. **建两个独立会话。** 分别取名和留空，五问分别选“钱”和“并没有攒下什么”。检查前者带入“你颇有家资”，后者没有该关键词。选择“钱”不会直接给物品栏加银两，未选选项也不应进入日常请求。[原卡五问与答案映射](../resources/silly-tavern/灭仇家满门之后，我收养了想对我复仇的孤女/开局状态与地图速查.md)
2. **检查一次变化前后。** 改名、突破修为或切换难度，核对手札显示和下一轮模型材料。既查新值是否出现，也查旧名、旧境界或未选难度是否仍被其他常驻条目写死。
3. **分别验证制作目录、ZIP 和已导入副本。** 制作目录是编辑来源；改了源文件，旧 ZIP 和已导入的卡仍可能是旧内容。打包后使用实际导入器读取 ZIP，核对根目录的 `world.json`、声明的组件及素材，并在桌面和窄屏实际操作建角与状态栏。[世界卡组件契约](design/world-components.md)
