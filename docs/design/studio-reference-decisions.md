## 第二轮交互规范验证（2026-11-10）

本轮解决：侧栏展开/收起风格不一致、过渡中断、Selected 项重复 Hover 变色。

1. **稳定形态**：展开/收起为同一个侧栏 DOM 容器，不再切换背景、圆角、边框或浮动/贴边定位；视口边距与图标基准位置保持不变。
2. **连续布局**：Sidebar 轨道通过 `grid-template-columns` 在 270ms 内插值，世界卡页 padding 和分类 gap 使用相同缓动。缓动为 `cubic-bezier(.4,0,.2,1)`，不添加弹跳。
3. **内容过渡**：Logo、导航和底部标签、会话/预设列表在收起时先淡出，展开时延迟淡入；这些元素不因侧栏切换被 React 卸载。收起时隐藏列表使用 `inert` 和 `aria-hidden`。
4. **状态优先级**：Selected + Hover 与 Selected 保持相同背景。Hover 仅适用于未选中项；键盘焦点保留独立轮廓，触摸设备不遗留粘滞 Hover。
5. **弹层动画**：Dialog 使用 200ms 透明度和微小垂直位移进出；支持 Escape、点击遮罩退出与 reduced-motion。
6. **移动端边界**：桌面保存的 collapsed 偏好不应隐藏手机 Drawer 中的文字/列表；手机仍展示完整导航内容。
7. **回归证据**：Studio 类型检查、生产构建、旧 Web 类型检查和 Chrome CDP 测试；CSS grid 过渡在固定时间的中间帧断言宽度单调变化、容器材质不变；检查选中状态、主题、分类、弹窗与移动端。

这是已实现的**交互约束**，不代表整体首页视觉基调已经最终获批。

- 保留 Studio AppShell 和语义 tokens，世界概览展示封面、名称、简介、标签及所有角色；下方为介绍、世界书、世界状态、开局、运行配置五个章节。

- 两组列表共享选择状态并双向同步横向滚动位置；未显示的紧凑列表为 inert，不截获纵向滚轮。

## 世界卡详情页 A/B 分区滚动修复（2026-11-11）

状态：A/B 分区版本已获得用户认可，作为本次详情细节调整的基准；类型检查、生产构建与 Chrome CDP 回归已完成。后续修改继续沿用这套布局与滚动规则。

### 页面与滚动职责

- 页面主工作区由 A（封面、名称、简介、标签、完整角色列表）和 B（章节导航与详情）组成；沿用已有 AppShell、Sidebar 与语义 tokens。
- 首次进入时 A 展开，桌面约占可用视口的 1/3；B 的章节导航和正文同时进入首屏。手机允许为可读性保留必要的头部高度。
- 外层原生滚动仅控制 A 的真实布局高度。A 连续缩小、封面与名称收敛、简介淡出；B 随 A 缩高同步上移并扩大。A 到达最小高度后，A、B 的布局位置固定。
- B 左侧始终保留「介绍、世界书、世界状态、开局、运行配置」。点击任意章节（包括当前章节）都会切换到指定内容、将详情滚动到起点，并自动将 A 收起。
- B 右侧详情从展开态开始就是独立滚动容器；其滚轮、触摸及键盘滚动不得驱动 A。详情在顶部、底部以及内容不足一屏时，继续滚动均不得传递给外层。
- 在 A 区域反向滚动可逐步展开概览；显式展开/收起入口同时支持键盘和触摸。不得将 A 或左侧导航的滚轮额外转发到正文。
- 手机及 980px 以下的平板宽度，紧凑头部使用世界身份与角色两行，章节转为横向导航；即使桌面侧栏仍展开，也要保留完整正文宽度。详情仍独立滚动，不能恢复为整个页面的长文滚动。

### 角色交接与连续性

- 展开角色列表先淡出，紧凑头部的完整角色列表随后淡入；展开态不预先显示右上角色列表，也不改为仅展示当前角色。
- 两组角色列表共享选中状态。横向浏览位置按可见角色及项内偏移同步，不直接复制不同密度列表的像素 `scrollLeft`。
- 所有角色单行排列，溢出后可横向浏览；原生纵向滚轮不强制转换为横向输入。
- 隐藏列表同时使用 `inert`、`aria-hidden` 和指针禁用。隐藏时不得保留不可见焦点；交接后同一角色可以继续通过键盘操作。
- A 收缩不卸载 B，不因布局进度重置章节、选择状态或正文的当前位置。只有主动切换章节或进入另一世界才按约定复位详情。

### 实现边界

- 使用固定长度的外层滚动轨道和 Sticky 视口工作台。轨道长度只由展开/收起高度差决定，不随 A 当前高度或详情内容长度变化。
- 工作台内 A 实际缩高，B 以剩余空间布局；详情使用 `overflow-y: auto`、`min-height: 0` 与 `overscroll-behavior-y: contain`，禁止以事件冒泡拦截替代原生滚动隔离。
- 尺寸变化观察固定视口，避免观察 A 的逐帧高度造成反馈。程序化收起只操作外层容器，详情复位只操作详情容器。
- 尊重 `prefers-reduced-motion`：程序化收起立即完成，角色呈现直接切换，避免连续缩放和渐隐动画；内容与所有操作仍保持可用。
- 继续限定于 `apps/studio` 的本地 fixture 原型；不接入 Server、SDK 或真实数据，不改旧 Web 业务页面。

### 验证要求

1. 桌面展开首屏同时可见 A、全部章节入口与正文；检查 25%、50%、100% 收缩进度下 A 高度单调减少，B 等量上移。
2. 在外层处于中间进度时，对详情顶部、底部和短章节发送真实滚轮输入，确认外层位置不变；不能只在外层端点测试，以免掩盖滚动串联。
3. 验证点击各章节自动收敛、详情回到起点；正文聚焦后的 PageUp、PageDown、Home、End 等按键只改变详情位置。
4. 验证角色选择、横向可见角色锚点、隐藏列表不可聚焦以及反向展开。
5. 执行 Studio typecheck、build 与现有 CDP visual 测试，覆盖桌面、手机、尺寸变化和 reduced motion。人工查看实际截图，不能仅凭构建成功判定交互符合需求。

## 世界概览终态切换（2026-11-12）

- 概览只停留在展开和收敛两种状态。概览或章节导航区域的纵向滚轮按方向启动完整动画，动画及同一滚动手势内的后续滚轮输入不反向打断；水平角色浏览保持原有行为。
- 点击章节仍切换内容、将正文回到顶部并自动收敛；展开/收敛按钮继续可用。正文区域的滚动与键盘操作保持独立。
- 原生触摸或其他外层滚动结束后，若停在两端之间则吸附到最近终态；减少动态效果时立即切换。前文关于可停留在连续中间状态的描述仅为历史记录。

### 正文滚动到底部时收敛

- 用户在章节正文中向下滚动到末尾时，顶部概览执行完整的收敛动画；正文在到达末尾之前继续独立滚动，向上滚动不会触发收敛或展开。
- 短章节首次进入不会自行收敛；用户在正文区域明确向下滚动时才触发。键盘向下阅读到末尾同样适用，点击章节自动收敛保持不变。
- 此规则替代上文“正文到底部继续滚动也不改变 A”的历史描述；不改变角色选择、章节或阅读内容。

### 移动端展开态间距

- 移动端世界概览展开时，封面底边与标签底边对齐，角色列表向上靠近封面；收敛态布局与交互不变。减少动态效果时同样保留展开态的排布。

### 世界详情中的会话

- 世界详情增加“会话”章节，展示属于当前世界的静态会话样板，并可进入对应详情；没有样板时展示空状态。点击章节沿用其他章节的收敛和正文复位行为。
- 世界卡和世界概览的会话数量统一由同一份样板数据计算。当前为 Studio 静态探索，不表示已连接真实会话数据。
