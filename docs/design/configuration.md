# 配置：预设、Prompt 节点和模型连接

> 状态：产品领域设计，2026-11-01；SillyRealms 自有默认配置，不宣称与 SillyTavern 默认顺序完全一致。返回[文档索引](../README.md)，构建流程见[Context](context.md)，存储见[存储](../technical/storage.md)。

## 所有权边界

**预设（Preset）是 Prompt 编排的唯一控制者**：定义节点及其顺序、启用状态、消息角色和文本内容，并管理模型连接引用、生成参数。世界卡只定义世界内容、角色/场景/世界书的**加载条件**、Opening、状态字段；**不得**决定 Prompt 的角色、位置、深度、节点顺序，也不能向所选预设隐式插入系统指令。

| 对象 | 职责 | 禁止事项 |
| --- | --- | --- |
| 世界卡 | 提供 `description`、`characters[]`、`scenes[]`、`lorebooks[]`、`examples`、Opening 与可选状态定义 | 修改预设、设置节点角色/顺序/插入位置 |
| 预设 | 提供不可删除的基础节点、排列/开关、自定义文本节点、生成参数与 API 连接引用 | 改写世界卡原始内容或真实 Entry 历史 |
| Context Builder | 先根据世界卡触发规则筛选内容，再按预设节点数组填充、展开并组装最终请求 | 另行按世界卡的注入顺序重排或重复插入内容 |
| Provider | 使用预设绑定的连接发起请求；完成必要的模型格式适配 | 未告知用户就修改 Prompt 语义或替换模型 |

## 不可删除的「基础默认」预设

- 系统内置一套只读预设 `builtin/default`，**不可删除、不可编辑、不可覆盖**，也不能被导入内容覆盖。它是预设模板，不依赖世界卡。见可供实现使用的完整示例 [default-preset.json](../examples/default-preset.json)。
- 新建自定义预设时**复制基础默认的全部系统节点及其稳定 ID**，然后允许调整顺序、启停可选节点、修改可编辑文本节点，并在任意位置增加自定义文本节点；自定义节点可编辑或删除。
- 任何自定义预设仍必须含每个基础节点 **恰好一次**；基础节点不允许删除、改 ID、改 `type`、改 `source`，以防复制造成 Context 丢失或重复。导入预设也必须验证相同约束。默认预设自身不受用户编辑影响。
- `chatHistory` 是**必需**节点，不能禁用；其他基础节点可关闭，不存在内容时自然输出为空（例如未启用状态插件时的 `worldState`）。关闭 `main` 等节点会影响叙事质量，但属于用户在自定义预设中的显式选择。
- 内置默认模板不绑定私人 API 连接，也不保有密钥；用户实际调用模型时需选择/新建一个**自定义预设副本**并绑定连接。首次使用可引导一键创建副本，不通过修改只读模板偷偷保存连接。
- 自定义预设持久化**完整的、排好序的节点数组**，在 `config_json` 中用 `base_preset_id: "builtin/default"` 标识来源，而不是运行时把差异列表与可能升级的模板做隐式深度合并。每份预设只有当前版本；系统默认模板升级不能无声重写用户预设，需要校验/显式迁移新内置节点。

## 十个基础 Prompt 节点

以下是 **SillyRealms 的基础默认顺序**，借鉴 SillyTavern Prompt Manager 的 Main Prompt、World Info、Character/Persona、Examples、History 与后置文本标记，但适配多角色世界卡；**不是照搬酒馆某个版本的预设**。

| 顺序 | ID | 类型 | 内容来源 | 默认启用 |
| --- | --- | --- | --- | --- |
| 1 | `main` | `text` | 预设提供的基础叙事指令 | 是 |
| 2 | `worldDescription` | `slot` | `world.description` | 是 |
| 3 | `worldInfo` | `slot` | 筛选后的 `world.lorebooks` 条目 | 是 |
| 4 | `personaInfo` | `slot` | 当前 Session 选择的身份及参与方式 | 是 |
| 5 | `characterInfo` | `slot` | 当前生效的 `world.characters` 资料 | 是 |
| 6 | `sceneInfo` | `slot` | 当前生效的 `world.scenes` 资料 | 是 |
| 7 | `worldState` | `slot` | 当前世界线的有效完整状态及字段规则 | 是 |
| 8 | `dialogueExamples` | `slot` | `world.examples` | 是 |
| 9 | `chatHistory` | `slot` | 当前世界线的真实历史 + 本次输入（恰好一次） | **强制启用** |
| 10 | `postHistory` | `text` | 预设自定义的历史后置指令 | 否 |

节点属性约定：`id` 为稳定标识；`type` 为 `slot` / `text`；`role` 为 `system` / `user` / `assistant`（`dialogueExamples`、`chatHistory` 用 `auto` 继承原有消息角色）；`enabled` 为布尔值。`slot.source` 是引擎内置来源，用户不可修改；`text.content` 可在自定义预设中编辑。自定义文本节点额外提供 `name`，拥有独立 ID，允许增删、启停、重排及修改 `role`/`content`；第一版不提供自定义 `slot` 或执行代码。

**数组顺序就是 Prompt 节点顺序**，无需 `injection_order` 或对世界卡复用另一套排序规则。`dialogueExamples` 与 `chatHistory` 按对话角色展开为多条消息，不能强制套用单一的 system 角色；缺少可解析示例时不伪造消息，检查界面说明跳过。`worldInfo` 首期只有一个插槽；不再由世界卡选 Before/After。以后若增加多 World Info 插槽，必须由预设节点定义其独立 ID 和具体来源规则。

### 自定义预设与 UI

- 列表中始终有带「系统内置」标识的 `builtin/default`，仅支持查看/复制，不支持删除/覆盖。点击「基于默认新建」创建可编辑副本。
- 节点编辑器支持拖动顺序、开关、编辑 `main/postHistory`、新增和删除**自定义**文本节点；系统节点显示锁定标识，不提供删除。`chatHistory` 开关锁定为开启。
- 预设保存前验证基础节点集合完整、无重复 ID、合法消息角色、每个 `slot.source` 与系统定义一致、必需节点启用；不合规则拒绝，不悄悄自动修复顺序。
- 实例引用**一个**预设，生成时读取当前配置；暂不提供实例级逐参数覆盖，也不允许世界卡对预设做覆盖。预设变更仅影响下一次生成，不追溯修改历史。

## 组装和模型适配边界

1. 读取选中预设，确认全部节点有效。按世界卡的加载条件命中角色、场景、世界书，按当前 Session 取身份、有效状态及目标 Entry 祖先链；内容加载和排序是两个独立步骤。
2. 顺序遍历预设 `nodes[]`，按 `slot.source` 填充命中内容或渲染 `text.content`；跳过禁用节点或空内容。World Info 同一节点内部顺序使用**世界卡源列表顺序**，并按稳定条目 ID 去重；它不提供跨节点的注入排序权限。
3. `chatHistory` 只存在一次，用户本次输入也只能出现一次；在它之后的启用文本节点可以位于用户输入之后，不能冒充用户原始输入。首次不提供历史内深度插入，后续如设计深度规则，仍只能属于预设。
4. 之后统一进行宏替换、Token 预算与 Provider 消息角色适配。需要保留最终请求的顺序和每段来源供预览；若 Provider 无法表达指定顺序/角色，应显式报错或告知有损转换，不能悄悄重排。
5. 世界卡中的 `prompts`、旧版角色卡的 Prompt/注入元数据属于**导入兼容原始资料**，不自动参与生效配置，也不能覆盖节点。仅用户明确选择「导入为自定义预设文本节点」时，才由 UI 转成可编辑的 `text` 节点；原始导入资料可放扩展/来源档案。

## 模型连接与安全

- 一个自定义预设引用一个 `api_connection_id` 和本次生成参数（如温度、Top P、上下文长度等）；Provider/API 连接定义平台、地址、模型 ID 和凭据引用。默认模板不保存私人连接配置。
- 模型 ID 暂不可用时可以保存供修改，但调用失败必须明确提示，不自动替换模型；删除被引用的连接时需要提示重新选择。
- API Key 由本地服务安全保存，不进入普通预设/世界卡 JSON、消息、导出或 Prompt 预览。密钥具体存储与局域网认证要在实现前验证。

## 最小验收场景

- 应用启动始终能读取 `builtin/default`；用户不能删除、改写或以同 ID 导入覆盖。无连接时引导从它创建自定义副本。
- 新副本拥有全部 10 个基础节点；拖动 `worldInfo` 或在 `chatHistory` 后新增自定义文本节点，最终 Context 顺序与预览一致；基础节点删除/重名/重复或关闭 `chatHistory` 必须拒绝保存。
- 世界卡含常驻世界书条目但预设关闭 `worldInfo` 时不注入；世界卡即便有旧 `injection_*` 或来源 Prompt，也不能改变节点角色与顺序。
- 一个正常发送的 User 消息在模型最终 `chatHistory` 中出现**恰好一次**；用户自定义节点的文字独立标明来源，不能冒充真实聊天输入。

## 延后范围

本轮只设计**基础节点、节点编排、预设和世界卡的权限边界**。不设计 AI 帮答、AI 续写的提示词功能，也不展开自定义工具调用、内嵌历史深度、完整 SillyTavern 宏/预设导入兼容、实例覆盖或多预设合并。不同 Provider 的参数映射、流式和取消属于[运行架构](../technical/architecture.md)技术验证。
