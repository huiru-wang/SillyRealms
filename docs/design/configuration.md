# 配置：预设、Prompt 节点和模型连接

> 状态：产品领域设计，2026-11-02；设计不表示功能已经实现。返回[文档索引](../README.md)，Context 与存储的关联规则仍需按本设计同步。

## 职责边界

- **世界卡**提供供玩家查看的 `description`、角色、开局、世界书条目和可选状态定义。`description` 可以是概括或 HTML 展示内容，**不作为 Prompt 输入**。故事前提、场景和人物关系等需要发送给模型的内容，由世界书条目或角色资料表达；不单设 Scenario 字段或节点。
- **预设**定义 Prompt 节点的顺序、开关、消息角色和文本，并选择已配置的模型连接，管理生成参数与 Token 预算。世界卡不能隐式修改预设或移动预设节点；世界书条目可以选择系统定义的相对插入位置、消息角色和同位置顺序。
- **模型连接**独立配置和管理服务地址、模型及凭据引用。预设选择已有连接，不复制连接本身；多个预设可以引用同一连接。
- **Context Builder**根据世界卡的加载条件筛选内容，再按本次生成所用预设组装 Prompt。实际 Provider 对顺序和角色的适配暂不在本轮设计。

## 默认预设与自定义预设

- 系统提供一个**不可删除但可编辑**的默认预设。用户可以直接调整其节点顺序、文本、开关、生成参数、预算和所选模型连接，无需复制后使用。
- 用户可以新建或复制其他预设，并从已有模型连接中选择。修改共享的连接配置会影响引用它的预设之后的调用；不能因此改写历史消息。
- 可以保留出厂配置供用户主动恢复。恢复会覆盖当前预设中的修改，应在操作前说明影响；不应无声恢复。
- 每份预设保存完整、排好序的节点数组。运行时不应将用户配置与变化中的默认模板静默合并；未来系统新增基础节点时需要明确版本兼容及迁移规则。
- 每次生成开始时固定所用的预设和连接配置；运行中编辑只影响后续生成。凭据不得进入预设导出、世界卡或 Prompt 预览。

## 预设节点

预设编辑器显示下列基础节点；用户可以增加、删除、启停和移动自定义文本节点。下图中的自定义节点只是可插入位置的示意，不是必填节点：

```text
Main Prompt
玩家身份
角色资料
[自定义节点]
世界状态
聊天历史
[自定义节点]
用户输入
[自定义节点]
Post-History Instructions
```

| 节点 ID | 类型 | 来源与用途 |
| --- | --- | --- |
| `main` | `text` | 预设中的基础叙事指令 |
| `personaInfo` | `slot` | Session 绑定的个人身份或世界卡角色快照 |
| `characterInfo` | `slot` | 当前命中的其他世界卡角色资料，不重复加载玩家选中的角色 |
| `worldState` | `slot` | 当前世界线的有效状态、字段规则及状态更新格式 |
| `chatHistory` | `slot` | 本次输入之前，目标世界线的真实历史 |
| `userInput` | `slot` | 本次生成绑定的用户输入 |
| `postHistory` | `text` | 预设中的历史后置指令，可为空或关闭 |

七个基础节点在每个预设中**各恰好出现一次**；不可删除，也不能修改稳定 ID、类型或系统来源。节点可调整顺序，但 `chatHistory` 必须位于 `userInput` 之前；用户输入的前后关系不能因拖动节点而颠倒。自定义文本节点可设名称、内容、消息角色和开关。基础文本节点也可编辑；系统资料节点可配置消息角色。具体 Provider 对消息角色与顺序的适配另行设计。

基础节点存在不等于内容非空：没有内容时该节点不产生消息。`chatHistory` 和 `userInput` 必须启用，本次用户输入恰好出现一次；当世界或所选身份定义了状态字段时，`worldState` 必须启用并提供当前分支的有效状态，否则阻止生成并提示。其他基础节点可关闭。真实聊天历史及用户输入保留各自原有的消息角色，不能将整个历史统一改为一种角色。个人身份状态的定义及接入仍需在状态领域明确。

世界卡 `description` 不进入 Prompt；不设置 `worldDescription`、`sceneInfo`、`dialogueExamples` 或 `scenario` 节点。场景、示例和故事前提可以作为世界书条目，在命中后通过下述插入位置加载；不存在承载全部世界书内容的单个 `worldInfo` 节点。

## 世界书的相对插入位置

一张世界卡包含一个 `lorebook`。每条世界书条目先按 `load` 条件判断是否命中；命中后选择以下系统预定义位置之一，预设不需要认识具体世界卡或条目 ID：

| 目标基础节点 | 条目可选插入位置 |
| --- | --- |
| 玩家身份 `personaInfo` | 前、后 |
| 角色资料 `characterInfo` | 前、后 |
| 世界状态 `worldState` | 前、后 |
| 用户输入 `userInput` | 前、后 |

这些位置是系统提供的隐式锚点，不作为额外节点要求用户逐个添加；构建预览必须展开显示它们。锚点随所属节点移动：节点前的条目在节点之前，节点后的条目在节点之后。节点无内容或由用户关闭时，其前后锚点仍存在并照常加载命中的条目；关闭基础节点本身不会关闭附近世界书条目。

例如预设排列为“玩家身份 → 自定义文风 → 角色资料”，展开为：

```text
玩家身份前的条目
玩家身份
玩家身份后的条目
自定义文风
角色资料前的条目
角色资料
角色资料后的条目
```

只有玩家身份节点排在角色资料之前时，“玩家身份后”才一定排在“角色资料前”之前；交换基础节点后，相对位置随节点一起变化。`order` 不跨越不同锚点或自定义节点改变上述顺序。

同一锚点中的条目按 `load.order` 从小到大排列；相同值保留世界书列表顺序，缺省值为 `0`。`order` 表示同位置内的顺序，不是重要程度或预算优先级。每条世界书条目自行指定消息角色 `system`、`user` 或 `assistant`，缺省为 `system`；编辑器可将其作为高级设置。不同角色的条目仍严格按 `order` 输出，不能按角色重新分组而改变顺序。世界卡不修改预设节点角色，预设也不默认覆盖条目角色。

示意字段如下，位置使用目标节点 ID 与 `before` / `after` 分别表达，均为系统内置标识：

```json
{
  "id": "story-rules",
  "title": "剧情规则",
  "content": "保持角色性格一致。",
  "load": {
    "mode": "always",
    "anchor": "userInput",
    "position": "after",
    "role": "system",
    "order": 10
  }
}
```

`on_mention` 使用一组 `keywords` 和 `keyword_logic`，不支持次要关键词或递归加载。关键词扫描范围、匹配细则及预算不足时的裁剪方式仍待确定。没有命中或内容为空的条目不输出。初版不支持任意聊天历史深度或锚定用户自定义节点。

`personaInfo` 从 Session 读取已绑定的身份快照，`{{user}}` 对应该身份名称。用户身份可以是个人身份或世界卡中可扮演的角色；世界卡通过 `allow_user_persona` 和角色的 `player_selectable` 控制候选。

## 构建和验证

1. 固定本次生成使用的预设、模型连接、Session 身份、目标世界线、有效状态及本次用户输入。普通发送、失败重试及历史分叉都以本次操作绑定的用户消息为准。
2. 校验预设结构：七个基础节点各出现一次、ID 不重复、类型与来源有效、必需节点启用，且历史位于本次输入之前。合法节点没有数据时跳过节点自身，不丢弃其锚点内容。
3. 根据世界卡加载条件筛选角色与世界书条目；条目按目标基础节点和前后位置分配，分别按 `order` 排序。顺序遍历预设，将每个节点的前置条目、节点内容和后置条目依次展开；条目保持自身角色及顺序。
4. 历史只使用目标世界线的祖先路径；本次用户输入不与历史重复，恰好输出一次。处理支持的宏并计算预算。预览显示节点、条目、角色、命中原因、相对位置、顺序及裁剪结果，不显示凭据。
5. 状态存在时，`worldState` 使用本次生成父 Entry 的有效状态；失败或失效的状态不能当作有效状态注入。状态结算和恢复规则以[状态设计](state.md)为准。

世界卡中的来源 Prompt 或旧注入元数据不能自动修改预设；如将来支持导入为预设文本，应由用户明确选择。世界卡的正则脚本执行规则另行设计，本轮不规定其行为。

## Token 预算与模型连接

预设保存预算和生成参数，并引用独立模型连接。预算可包括上下文窗口、最大输出、安全余量和世界书上限；可用输入空间必须为输出及必要余量预留空间。本次用户输入和必要固定内容无法放入时应提示，而不是静默截断。

世界书条目在各自插入位置内按 `order` 排列，但预算不足时各类内容的取舍顺序、整条或部分裁剪、模型能力上限如何取得等细节尚未确定。旧设计中的 `priority` 裁剪规则不再适用，待预算设计明确后再冻结。

模型连接不可用时应提示用户检查或重新选择，不自动替换模型。API Key 由本地服务安全保存，不进入普通预设或世界卡导出；具体凭据存储方案有待实现验证。

## 验收关注点

- 默认预设不能删除，但可直接编辑并绑定已有模型连接；其他预设也可引用同一连接。
- 任一预设都包含七个不重复的基础节点；缺少节点、修改内置来源或将历史置于本次输入之后时拒绝保存；关闭必需节点时阻止相关生成。
- 世界卡 `description` 不进入 Prompt；命中的世界书条目可插入四个指定节点的前或后，同位置遵循 `load.order` 与条目自身角色。基础节点为空或关闭时，其前后条目仍正常加载。
- 玩家身份、角色资料之间有自定义节点时，相对锚点分别贴合对应基础节点；移动基础节点后锚点随之移动。混合消息角色的条目不能因合并而改变顺序。
- 个人身份和世界卡角色都能作为 Session 身份；`personaInfo`、`{{user}}` 与选中身份一致，玩家角色不重复进入 `characterInfo`。
- 本次用户输入仅出现一次；有状态时只读取目标分支的有效状态。空内容节点可跳过。
