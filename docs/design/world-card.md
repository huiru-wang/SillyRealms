# 世界卡：内容定义、发布与实例同步

> 状态：领域设计，2026-11-01；规范部分仍为草案。返回[文档索引](../README.md)，相关领域见[Context](context.md)、[会话](session.md)。

## 定位和内容归属

世界卡定义可重用的世界背景、独立角色、场景、开局、世界书及可选的提示词/规则/资源。人物设定存在角色本身，地点/组织/物品等独立资料放在世界书；世界卡不保留玩家当前游玩状态。世界实例是一次独立故事，创建时复制发布的世界定义；所选开局、当前身份/场景、控制权、实际消息和分叉属于该实例。角色可否由玩家选择属于卡片定义，实际选择属于实例。

## 发布版本与同步

- 内容发布版本使用 `data.version = "X.Y"`（两段非负整数）。首次发布 `0.1`，例如 `0.1 → 0.2 → 1.0 → 1.1`；新版本按数值元组比较，必须严格递增，不以字符串排序。草稿可未发布，编辑草稿不会提升已发布版本。
- 格式版本 `spec_version` 与内容版本相互独立。仅保留世界卡的**当前草稿**和**最新发布内容**，不维护可浏览的每次历史发布副本。
- 创建世界实例时复制完整已发布 JSON 及其来源版本；新版本发布不会自动改动已有实例。用户查看可更新提示后可以手动同步。
- **手动同步只覆盖实例中的完整世界 JSON 快照与来源版本**，不做逐字段合并，也不触碰消息、分叉、记忆和状态。该实例所有分支下一次生成使用更新后的世界定义；需要根据依赖关系检查旧设定生成的派生缓存/摘要。
- 实例如果未来需要临时修改世界设定，应以独立的本局覆盖配置表达，不回写到原世界快照内。存储字段见[存储设计](../technical/storage.md)。

## 内容结构与导入边界

### 整体结构

```text
WorldCard
├─ spec / spec_version
└─ data
   ├─ name / summary / description
   ├─ creator / creator_notes / version / tags / cover
   ├─ scenes[]                 场景及其注入配置
   ├─ characters[]             独立角色及其人物设定
   ├─ openings[]               可选开局
   ├─ lorebooks[]              世界资料
   ├─ examples / prompts      可选示例和提示词
   ├─ regex_scripts[]          可选文本规则
   ├─ assets[]                 可选资源清单
   └─ extensions              可选扩展数据
```

结构外壳暂用 `spec: "world_card"`、`spec_version: "0.1"`。`spec_version` 是**卡片格式**版本；`data.version` 是作者发布的**内容**版本。卡片跨版本身份及导入兼容协议仍待确认。具体内容发布与实例同步规则见上文。

有效卡至少具有非空名称和一个有效开局；缺少内容仍可保存为草稿。字段缺失时可选文本按空文本处理，可选列表按空列表处理。未知来源内容不能因不被理解而静默丢失。

## 基础字段

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `name` | string，必填 | 世界卡名称 |
| `summary` | string | 给用户看的简介，不默认发送模型 |
| `description` | string | 世界基础设定、环境与通用规则 |
| `creator` / `creator_notes` | string | 作者和使用说明，不默认发送模型 |
| `version` / `tags` | string / string[] | `version` 为 `X.Y` 两段内容发布版本，严格递增；`tags` 用于分类 |
| `cover` | string | 可选封面引用，暂用 `asset:<资源ID>` |
| `examples` | string | 可选表达或对话示例，不作为实际故事历史 |
| `prompts` | object | 可选系统提示词和历史后置指令；使用前需用户接受 |
| `extensions` | object | 可选扩展，不自动解释或执行 |

## 独立角色

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | string，必填 | 卡内稳定标识 |
| `name` | string，必填 | 角色名称 |
| `description` | string | 完整人物设定，包括需要时的性格、经历、外貌和关系 |
| `avatar` | string | 可选头像资源引用 |
| `tags` | string[] | 可选标签，用于展示、筛选和整理；缺省为空列表 |
| 共同注入字段 | 见下文「场景、世界书与共同注入配置」 | 角色资料何时、以什么方式进入 Prompt |
| `player_selectable` | boolean | 角色是否允许作为玩家身份选择 |

角色和场景、世界书条目使用相同的注入字段，见下文「场景、世界书与共同注入配置」。玩家在本局选中角色时，默认提供该角色资料；其他角色按其加载配置处理。

角色设定直接放在 `description`，不要求通过世界书关联。角色的实际控制者、是否登场、当前状态不写入卡片。角色可以被玩家选择不代表必须由玩家控制，也不决定玩家是否能够读取其他人物的秘密。

## 开局

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | string，必填 | 卡内稳定标识 |
| `name` | string，必填 | 选择开局时显示的名称 |
| `content` | string，必填 | 初始故事内容或特殊入口标记 |
| `player_characters` | string[]，可选 | 该开局允许选择的角色 ID；`custom` 表示允许自定义身份 |

开局未设置 `player_characters` 时是否继承卡片全部可选角色，以及观察者身份的表达方式，待开局设计确认。设置后，实际可选角色还须满足各角色的 `player_selectable`。

默认建议选择第一项；所选开局写入会话初始历史，后续生成不重复注入。开局内容不是当前会话状态，不能因为用户游玩而改变原卡。

## 场景、世界书与共同注入配置

### 场景列表 `scenes[]`

场景定义可进入或切换的叙事环境，`id`、`name`、`description` 分别表示卡内标识、名称和场景设定；可选的 `tags` 是用于展示、筛选和整理的字符串列表，缺省为空列表。场景还可使用下表的共同注入字段。场景可以为空；当前场景是会话状态。关键词触发场景资料加载，不自动切换当前场景。

角色和场景的 `tags` 默认不进入 Prompt，也不自动作为触发关键词；需要按特定词语触发时，应在注入配置的 `keywords` 中明确填写。

### 世界书 `lorebooks[]`

世界书是独立世界资料集合；条目使用 `id`、`name`、`content` 表达资料，并使用共同注入字段定义加载方式。人物设定放在角色自身，不通过关联世界书取得。资料是否在本局关闭属于实例或会话状态，卡片不包含 `enabled` 当前状态。

### 三类内容共用的平铺字段

以下字段直接位于场景、角色或世界书条目对象下，不引入额外嵌套。所有内容都可省略可选字段；下列默认值为本轮产品草案。

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `load_mode` | string | `manual` | `always` 常驻；`on_mention` 关键词命中；`manual` 本局选择 |
| `keywords` | string[] | `[]` | `on_mention` 的匹配词；空列表不触发，并显示配置提示 |
| `injection_position` | string | `content` | `content` 基础内容区；`before_history` 历史前；`in_history` 指定历史深度；`after_history` 历史后，可位于当前输入之后 |
| `injection_depth` | integer | `0` | 仅 `in_history` 使用，非负；0 指本次有效消息序列末尾 |
| `injection_role` | string | `system` | 内容角色：`system`、`user`、`assistant`；最终取决于模型支持 |
| `injection_order` | integer | `100` | 同位置数值较小的内容排在前面 |
| `priority` | integer | `0` | 预算不足时数值较高者优先保留；与排列顺序独立 |
| `recursive_trigger` | boolean | `false` | 是否允许该内容被已命中内容触发 |
| `recursive_source` | boolean | `false` | 该内容命中后是否可继续触发其他内容 |

具体关键词组合、扫描范围、递归开关与预算策略另行设计。现有角色与世界资料采用相同规则，不意味着它们必须同时开启递归。无效配置应提示，不自动按常驻处理；上述默认不代表酒馆兼容语义。

```json
{
  "scenes": [
    {"id": "study", "name": "书房", "description": "一间安静的书房。", "tags": ["室内", "地点"], "load_mode": "on_mention", "keywords": ["书房"], "injection_position": "content"}
  ],
  "characters": [
    {"id": "keeper", "name": "守书人", "description": "谨慎而耐心。", "tags": ["主要角色"], "player_selectable": true, "load_mode": "always", "injection_position": "content"}
  ],
  "lorebooks": [
    {"id": "places", "name": "地点", "entries": [
      {"id": "valley", "name": "山谷", "content": "山谷常年有雾。", "load_mode": "on_mention", "keywords": ["山谷"], "injection_position": "content"}
    ]}
  ]
}
```

场景、角色与世界资料各自保留独立 ID；各集合内 ID 唯一，世界书条目在所属世界书内唯一。用户开关属于实例/会话，不写入 `enabled`。

## 文本规则与资源

文本规则可以定义输出转换和界面呈现需要的内容；规则是否在本局启用由实例或会话配置。导入内容中出现的 HTML、脚本和外部链接应保留，但导入成功不表示客户端支持其运行。

`assets[]` 是可选资源清单；可使用资源 ID 引用封面和角色头像。资源清单、资源路径和实际文件应区分：外链不等于已打包。PNG 角色卡可能以图片本身作为卡面；仅有 JSON 时不能恢复未提供的 PNG 头像。

## 来源迁移与保留

角色卡 V2/V3 仅作为内容来源，不要求世界卡继承其字段或结构。整理时：

- 将确定的人物设定整理到对应角色下；将独立世界资料整理到世界书。
- 原卡的开场白保留为开局；来源中的特殊入口应保留其内容。
- 原来的关闭条目、旧版设定和不支持的扩展保留在原始来源归档；不要未经选择就把相互冲突的版本一起作为活跃世界设定。
- 原始数据与新卡分开保存。原始数据保留不代表所有旧字段或功能已转换完成。
- 关键词、插入深度、正则和资源的原有行为需要逐项分析；不能因保存了正文就宣称运行效果相同。

## 示例与待讨论事项

世界卡整理示例见 [world-card.json](../examples/world-card.json)。原卡素材不随文档库分发。示例中的角色可选资格和加载方式属于人工设计，不是原卡已有权限。

继续设计时需要明确角色加载与玩家身份的关系、开局角色限制的继承、世界书完整触发机制、共同注入规则的默认值、原卡正则和扩展的兼容方式。Prompt 构建的产品逻辑见 [Context](context.md)。
