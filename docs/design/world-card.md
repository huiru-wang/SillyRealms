# 世界卡：内容定义、发布与实例同步

> 状态：领域设计，2026-11-01；规范部分仍为草案。返回[文档索引](../README.md)，相关领域见[Context](context.md)、[会话](session.md)。

## 定位和内容归属

世界卡定义可重用的世界背景、独立角色、场景、开局、世界书、**可选的状态字段定义**及资源/文本规则。**世界卡只提供内容与触发条件，Prompt 节点顺序、插入位置和消息角色由预设唯一控制**；不得通过卡片自动修改预设。人物设定存在角色本身，地点/组织/物品等独立资料放在世界书；世界卡不保留玩家当前游玩状态。世界实例是一次独立故事，创建时复制发布的世界定义；所选开局、当前身份/场景、控制权、实际消息和分叉属于该实例。角色可否由玩家选择属于卡片定义，实际选择属于实例。

## 发布版本与同步

- 内容发布版本使用 `data.version = "X.Y"`（两段非负整数）。首次发布 `0.1`，例如 `0.1 → 0.2 → 1.0 → 1.1`；新版本按数值元组比较，必须严格递增，不以字符串排序。草稿可未发布，编辑草稿不会提升已发布版本。
- 格式版本 `spec_version` 与内容版本相互独立。仅保留世界卡的**当前草稿**和**最新发布内容**，不维护可浏览的每次历史发布副本。
- 创建世界实例时复制完整已发布 JSON 及其来源版本；新版本发布不会自动改动已有实例。用户查看可更新提示后可以手动同步。
- **手动同步只覆盖实例中的完整世界 JSON 快照与来源版本**，不做逐字段合并，也不触碰消息、分叉、记忆和已有 Entry 状态快照。该实例所有分支下一次生成使用更新后的世界定义；需检查旧设定的派生缓存/摘要及 `data.state` 定义兼容性。**不会重新执行 Opening 初始化或重置已有世界线状态**；状态字段删除、改名、类型变化等不兼容更新必须明确处理迁移，不能隐式套用新规则。
- 实例如果未来需要临时修改世界设定，应以独立的本局覆盖配置表达，不回写到原世界快照内。存储字段见[存储设计](../technical/storage.md)。

## 内容结构与导入边界

### 整体结构

```text
WorldCard
├─ spec / spec_version
└─ data
   ├─ name / summary / description
   ├─ creator / creator_notes / version / tags / cover
   ├─ scenes[]                 场景内容与加载触发条件
   ├─ characters[]             独立角色及其人物设定
   ├─ openings[]               可选开局，每项可有 initial_state
   ├─ state                    可选的状态字段定义
   ├─ lorebooks[]              世界资料及加载触发条件
   ├─ examples                 可选的对话示例
   ├─ regex_scripts[]          可选文本规则
   ├─ assets[]                 可选资源清单
   └─ extensions              可选扩展数据
```

结构外壳暂用 `spec: "world_card"`、`spec_version: "0.1"`。`spec_version` 是**卡片格式**版本；`data.version` 是作者发布的**内容**版本。卡片跨版本身份及导入兼容协议仍待确认。具体内容发布与实例同步规则见上文。

有效卡至少具有非空名称和一个有效开局；缺少内容仍可保存为草稿。字段缺失时可选文本按空文本处理，可选列表按空列表处理。未知来源内容不能因不被理解而静默丢失。

## 基础字段

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `name` | string，必填 | 世界卡名称 |
| `summary` | string | 给用户看的简介，不默认发送模型 |
| `description` | string | 世界基础设定、环境与通用规则 |
| `creator` / `creator_notes` | string | 作者和使用说明，不默认发送模型 |
| `version` / `tags` | string / string[] | `version` 为 `X.Y` 两段内容发布版本，严格递增；`tags` 用于分类 |
| `cover` | string | 可选封面引用，暂用 `asset:<资源ID>` |
| `examples` | string | 可选表达或对话示例，不作为实际故事历史 |

| `state` | object | 可选状态定义：每个字段包含 `initial`、`description`、`rule`；实例运行状态不写回世界卡 |
| `extensions` | object | 可选扩展，不自动解释或执行 |

## 独立角色

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | string，必填 | 卡内稳定标识 |
| `name` | string，必填 | 角色名称 |
| `description` | string | 完整人物设定，包括需要时的性格、经历、外貌和关系 |
| `avatar` | string | 可选头像资源引用 |
| `tags` | string[] | 可选标签，用于展示、筛选和整理；缺省为空列表 |
| 共同加载字段 | 见下文「场景、世界书与共同加载条件」 | 角色资料何时可以被选中进入其预设插槽 |
| `player_selectable` | boolean | 角色是否允许作为玩家身份选择 |

角色、场景与世界书条目使用相同的加载条件，见下文「场景、世界书与共同加载条件」。玩家在本局选中角色时，默认提供该角色资料；其他角色按其加载配置筛选，并最终填入预设的 `characterInfo` 插槽。

角色设定直接放在 `description`，不要求通过世界书关联。角色的实际控制者、是否登场、当前状态不写入卡片。角色可以被玩家选择不代表必须由玩家控制，也不决定玩家是否能够读取其他人物的秘密。

## 开局

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | string，必填 | 卡内稳定标识 |
| `name` | string，必填 | 选择开局时显示的名称 |
| `content` | string，必填 | 初始故事内容或特殊入口标记 |
| `player_characters` | string[]，可选 | 该开局允许选择的角色 ID；`custom` 表示允许自定义身份 |
| `initial_state` | object，可选 | 只写**与 `data.state` 默认初始值不同**的字段初始值，字段值必须匹配定义类型 |

开局未设置 `player_characters` 时是否继承卡片全部可选角色，以及观察者身份的表达方式，待开局设计确认。设置后，实际可选角色还须满足各角色的 `player_selectable`。

默认建议选择第一项；所选开局写入会话初始历史，后续生成不重复注入。创建实例时将每个 `data.state.<字段>.initial` 与当前 `opening.initial_state` 合并成**完整初始状态**并保存至开局 Entry；未覆盖的字段使用世界卡默认值，已覆盖字段**整个值替换**，对象、数组不做深层合并。开局覆盖不能新增未定义字段、修改字段类型/描述/规则；不存在的字段、错误类型应阻止发布或实例初始化并提示作者。缺少 `state` 时允许不提供 `initial_state`；开局文本不触发第二次状态结算。此过程仅在创建世界实例时执行，不会因切换世界线、编辑历史或世界卡手动同步而重新执行。

## 世界状态字段 `data.state`

这是**可选**的结构化状态插件，不替代叙事文本或世界书。世界卡只定义字段、默认初值和变化原则；真正的运行值属于 Session 的每个消息 Entry，按世界线继承。没有 `data.state` 的世界卡仍正常聊天。

**最小字段定义只有三个属性**；仅 `initial: null` 时额外要求 `type`：

| 属性 | 含义 |
| --- | --- |
| `initial` | 默认初始值；通常通过 JSON 类型推断状态字段类型 |
| `description` | 字段表示什么，供作者、UI 和 Agent 理解 |
| `rule` | 自然语言更新原则：什么时候应该改变；它是 Agent 指引，不是程序可执行约束 |

字段 ID 是 `data.state` 的顶层键，可以使用有意义的中文或 `guard.attitude` 这类标识符；**整个键是一个字段 ID**，`.` 不表示必须存在嵌套对象。默认支持 JSON 的 `string`、`number`、`boolean`、`array`、`object` 五类初始值，类型来自 `initial`；为了避免复杂的类型系统，首期不区分 `integer/number`、`map/object`。初值为 `null` 无法推断类型时，**例外允许**在该字段额外填写 `type`（`string`/`number`/`boolean`/`array`/`object`），并允许它继续为 `null`；非 `null` 值须匹配该类型。其他字段不必填写 `type`。

```json
{
  "state": {
    "当前时段": {
      "initial": "白天",
      "description": "故事当前的昼夜时段",
      "rule": "只有剧情明确推进时间时才改变"
    },
    "守卫态度": {
      "initial": 30,
      "description": "守卫对玩家的态度",
      "rule": "根据实际完成的互动调整，建议维持在 0~100"
    },
    "背包": {
      "initial": [],
      "description": "玩家实际持有的物品",
      "rule": "获得物品后加入，丢弃或消耗后移除"
    },
    "已发现线索": {
      "initial": {},
      "description": "已发现线索，以线索 ID 为键",
      "rule": "只有剧情实际发现线索时增加；线索失效时可移除"
    }
  },
  "openings": [
    {"id": "day", "name": "白日", "content": "天色已亮。"},
    {"id": "night", "name": "夜行", "content": "夜幕降临。", "initial_state": {"当前时段": "夜晚"}}
  ]
}
```

`openings[].initial_state` **仅保存不同开局的差异值**；不复制 `description`、`rule`，也不允许开局改变状态结构。覆盖以字段 ID 为单位：例如对象字段若被 Opening 覆盖，必须给出完整新对象，不与默认对象递归合并。新建实例时按 `state` 默认值 → Opening 覆盖值构建完整快照；详见[会话](session.md)及[存储](../technical/storage.md)。

### Agent 更新操作与删除边界

借鉴 MVU 的最小操作集合，**由状态引擎统一提供操作，不要求作者逐字段配置 `operations`/`min`/`max` 等参数**：

| 操作 | 允许目标 | 效果 |
| --- | --- | --- |
| `set` | 已声明的任意字段 | 以同类型新值完整替换字段值 |
| `add` | `number` 字段 | 将数字增量加到原值上，负数表示减小 |
| `insert` | `array`、`object` 字段 | 在数组中插入元素，或在对象中新增成员 |
| `delete` | `array`、`object` 的**成员** | 删除明确指定的数组元素或对象键 |
| `move` | `array`、`object` 的**成员** | 在同一集合内调整数组元素位置或将对象成员从一个键迁至另一个键 |

- **Agent 不得新增或删除世界卡顶层状态字段**，也不能改变其类型或定义；`delete` 只删除集合内部成员。要清空集合，用 `set` 将它设置为 `[]` 或 `{}`。消息删除是另一项功能，当前会话产品仍不支持。
- Agent 提交结构化操作，由程序检查目标字段是否存在、操作是否匹配类型、目标元素/键是否存在、值是否符合字段类型；修改对象成员不能越过顶层 Schema 的边界。数组定位必须明确，不按模糊文本猜测删除目标。非法操作拒绝，不执行世界卡提供的任意脚本。
- `rule` 及 `description` 用于指导 Agent 的语义判断，不应谎称自然语言可作为硬约束；例如“建议保持 0~100”需模型遵守，程序不能据此自动推断数值界限。
- Agent 的更新请求只描述**变化**，例如 `{"updates":[{"field":"守卫态度","op":"add","value":5}]}`；结构化协议具体参数按目标集合类型确定，不必暴露给世界卡作者。没有状态变化时返回空操作列表。

### 运行和世界线边界

- 默认 **User Entry 继承父消息完整状态；AI Entry 在叙事完成后分析并结算变化**。用户说“我打开城门”不等于剧情已经成功打开；以 AI 已发生的叙事作为结算依据。Opening 初始 Entry 直接写入已合并的初始快照，不重复解析开局。
- 每条已处理 Entry **即使没有变化，也保存一份完整的状态快照**。Agent 提交增量操作，状态引擎以父 Entry 快照为基准校验、原子应用并保存，不让 Agent 直接覆盖整份运行状态。状态结算失败与“没有变化”必须区分，失败不能伪装成结算成功。
- 新分支从分叉父 AI Entry 继承状态，不能读取其他兄弟世界线的快照；重生成/续写末尾 AI 时以正确父版本重新结算，防止重复 `add/insert`。
- 用户主动编辑历史消息时，保留所有后代正文和树关系，不自动重生成；受影响的后代状态结算应标记失效/待处理，不能默默把旧结果当新事实。世界卡同步不清空或重初始化旧消息快照，状态定义发生不兼容变化时先提示显式迁移。
- 作者编辑体验可只展示“字段名 / 初始值 / 描述 / 规则”；Opening 中列出字段默认值，并允许“覆盖初始值 / 恢复默认”。模型可见状态及结算的 Context 规则见 [Context](context.md)。

## 场景、世界书与共同加载条件

### 场景列表 `scenes[]`

场景定义可进入或切换的叙事环境，`id`、`name`、`description` 分别表示卡内标识、名称和场景设定；可选的 `tags` 是用于展示、筛选和整理的字符串列表，缺省为空列表。场景还可使用下表的共同加载字段。场景可以为空；当前场景是会话状态。关键词触发场景资料加载，不自动切换当前场景。

角色和场景的 `tags` 默认不进入 Prompt，也不自动作为触发关键词；需要按特定词语触发时，应在加载条件 `keywords` 中明确填写。

### 世界书 `lorebooks[]`

世界书是独立世界资料集合；条目使用 `id`、`name`、`content` 表达资料，并使用共同加载字段定义加载方式。人物设定放在角色自身，不通过关联世界书取得。资料是否在本局关闭属于实例或会话状态，卡片不包含 `enabled` 当前状态。

### 三类内容共用的平铺加载字段

角色、场景及世界书条目只声明**内容触发和候选筛选**条件，字段直接位于各内容对象上，不允许声明 Prompt 节点位置、深度、消息角色或跨节点排序。

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `load_mode` | string | `manual` | `always` 常驻候选；`on_mention` 匹配关键词时加载；`manual` 由本局明确选择 |
| `keywords` | string[] | `[]` | `on_mention` 触发词；空列表不命中并提示配置不足 |
| `priority` | integer | `0` | 在**当前插槽内部**预算裁剪时排序优先级；不影响插槽本身的位置或角色 |
| `recursive_trigger` | boolean | `false` | 是否可被其他已加载资料内容触发 |
| `recursive_source` | boolean | `false` | 命中后是否参与触发其他资料 |

已选择的玩家角色可作为加载规则之外的必要候选。具体关键词组合、扫描范围、递归和预算策略见 [Context](context.md)；优先级只决定当前插槽内哪些候选被保留，不允许移动预设节点。相同优先级下的条目按世界卡原始顺序稳定排列，重复条目根据稳定 ID 去重。不能因为 `load_mode` 是 `always` 就在预设相关插槽被禁用时仍强制注入。

```json
{
  "scenes": [
    {"id": "study", "name": "书房", "description": "一间安静的书房。", "tags": ["室内", "地点"], "load_mode": "on_mention", "keywords": ["书房"]}
  ],
  "characters": [
    {"id": "keeper", "name": "守书人", "description": "谨慎而耐心。", "tags": ["主要角色"], "player_selectable": true, "load_mode": "always"}
  ],
  "lorebooks": [
    {"id": "places", "name": "地点", "entries": [
      {"id": "valley", "name": "山谷", "content": "山谷常年有雾。", "load_mode": "on_mention", "keywords": ["山谷"]}
    ]}
  ]
}
```

角色/场景/世界资料各自拥有独立的卡内 ID，世界书条目在所属世界书内唯一。`enabled` 等用户临时开关属于实例/会话，不写回世界卡。

### 世界卡不得控制 Prompt 编排

- 原世界卡字段 `injection_position`、`injection_depth`、`injection_role`、`injection_order` **退出 SillyRealms 原生格式**；即使来自旧卡，也不可作为生效规则。消息排列和角色统一由[预设的节点](configuration.md)提供。
- 原生世界卡**不声明 `data.prompts`**，更不能直接覆盖 `main/postHistory` 等预设节点。来自酒馆的角色卡若包含 prompt、角色卡作者指令、注入控制等内容，可保留在来源档案或 `extensions` 的不执行兼容数据中；用户明确选择导入为**自定义预设文本节点**后才进入 Prompt。
- 内容条件、角色信息、世界书被解析进哪个固定插槽，由引擎的 `slot.source` 映射决定；世界卡不允许创建或覆盖基础 `slot`。未知字段可原样保留用于导入往返，但不应因未知数据存在就自动执行。

## 文本规则与资源

文本规则可以定义输出转换和界面呈现需要的内容；规则是否在本局启用由实例或会话配置。导入内容中出现的 HTML、脚本和外部链接应保留，但导入成功不表示客户端支持其运行。

`assets[]` 是可选资源清单；可使用资源 ID 引用封面和角色头像。资源清单、资源路径和实际文件应区分：外链不等于已打包。PNG 角色卡可能以图片本身作为卡面；仅有 JSON 时不能恢复未提供的 PNG 头像。

## 来源迁移与保留

角色卡 V2/V3 仅作为内容来源，不要求世界卡继承其字段或结构。整理时：

- 将确定的人物设定整理到对应角色下；将独立世界资料整理到世界书。
- 原卡的开场白保留为开局；来源中的特殊入口应保留其内容。原来源中的 Prompt/注入字段不得自动转成生效配置；必要时存入不执行的扩展归档，供用户明确导入为自定义预设节点。
- 原来的关闭条目、旧版设定和不支持的扩展保留在原始来源归档；不要未经选择就把相互冲突的版本一起作为活跃世界设定。
- 原始数据与新卡分开保存。原始数据保留不代表所有旧字段或功能已转换完成。
- 关键词、旧版插入深度、正则和资源的原有行为需要逐项分析；旧版注入深度不属于世界卡生效规则，不能因保留了来源信息就宣称兼容运行效果。

## 示例与待讨论事项

世界卡整理示例见 [world-card.json](../examples/world-card.json)。原卡素材不随文档库分发。示例中的角色可选资格和加载方式属于人工设计，不是原卡已有权限。

继续设计时需要明确角色加载与玩家身份的关系、开局角色限制的继承、世界书完整触发机制、共同加载字段的默认值、原卡正则和扩展的兼容方式。Prompt 构建的产品逻辑见 [Context](context.md)。
