# 作者发行与在线更新

世界卡可以携带作品身份、作者署名、说明和固定更新入口。玩家先导入你分享的 ZIP，再由自己的 SR 获取公开版本目录，选择升级或回退。你只需要公开托管 JSON 与 ZIP；不需要搭建额外的账号、Hub 或安装服务。

世界卡的完整字段见[格式参考](../reference/world-card.md#作品发行信息)，公开目录的精确契约见[开放 OTA 协议](../reference/world-updates.md)。

## 首次准备

保持既有源码布局：根 `world.json`、`components/` 和 `assets/`。卡格式固定为 `0.2`；先在 `data.publication` 填写下面的信息，再按[打包与分享](packaging.md)检查资源：

~~~json
{
  "package_id": "8da0e392-2ea6-4ac1-a93a-b94abf6828a1",
  "authors": [
    { "name": "世界作者", "url": "https://creator.example.org/" }
  ],
  "creator_notes": "建议从港口抵达开局开始。素材来源与使用说明见作品主页。",
  "release": {
    "version": "1.0.0",
    "published_at": "2026-11-26T12:00:00+08:00",
    "notes": "首次公开发行。"
  },
  "homepage": "https://creator.example.org/my-world/",
  "update_url": "https://cdn.example.org/worlds/my-world/releases.json"
}
~~~

示例 UUID 只用于展示。首次创建自己的作品时生成一次小写 UUID 并保存到源码，之后发版、改名和回退保持同一个值：

~~~sh
node -e "console.log(require('node:crypto').randomUUID())"
~~~

`package_id` 标识作品，不是玩家本机的 worldId；同作品可以独立导入多份。独立二次创作使用新 ID，在说明中保留原作出处。作者名字与链接用于署名，不代表平台账号认证。

`creator_notes` 写整个作品的玩法建议、限制与致谢，`release.notes` 写本次版本变化。两者分别展示，不进入叙事提示词。`homepage` 给人阅读，`update_url` 给程序读取。没有更新源的卡仍可普通分发，但玩家无法由卡内地址发现新版。

`publication` 是固定 schema，不能塞入检查状态、自定义属性或完整发行目录；自定义作者扩展继续放在 `data.extensions`。所有世界卡均使用 0.2 并声明完整 publication；离线作品可以省略 update_url。旧格式或缺少 publication 在世界卡校验阶段返回 INVALID_WORLD_CARD，不从昵称、卡名或扩展版本自动推断身份。

## 发版命令

在仓库根运行。先将本版更新说明保存为真实 UTF-8 文本文件，例如 `release-notes.md`，可以包含多行中文和 Markdown。不要把整个文件内容写成含字面 `\n` 的单行字符串。

~~~sh
pnpm world:release \
  --dir ./my-world \
  --version 1.1.0 \
  --notes ./release-notes.md \
  --artifact-url https://cdn.example.org/worlds/my-world/versions/1.1.0/my-world.zip \
  --index ./dist-world/releases.json \
  --out ./dist-world \
  --title "港口夜巡"
~~~

可额外传 `--published-at 2026-11-26T12:00:00+08:00` 固定发行时间。缺省使用本次命令的实际时间。固定时间不承诺每次重打包得到相同 ZIP 字节；发布时保留并上传同一次生成的文件。

| 参数 | 含义 |
| --- | --- |
| `--dir` | 已有且有效的 0.2 世界源码目录，必须声明固定作品身份和作者 |
| `--version` | 本次稳定发行版本，如 1.1.0、1.10.0；不能带 v、前导零或预发行后缀 |
| `--notes` | 本版更新说明的 UTF-8 文件，可为空文件 |
| `--artifact-url` | 上传后能直接下载这次 ZIP 的公开 HTTPS 地址 |
| `--index` | 本地完整版本目录；不存在时创建，存在时校验并追加，原子替换 |
| `--out` | 发行输出根目录 |
| `--published-at` | 可选，带时区的 ISO 8601 发布时间 |
| `--title` | 可选，人类可读版本标题 |

相对路径一律按仓库根解释，和调用者的工作目录无关。运行 `pnpm world:release --help` 可查看帮助。命令只生成本地文件，不访问远程链接、不上传文件、不读取玩家运行数据。

本次示例得到：

~~~text
dist-world/
├── releases.json
└── versions/
    └── 1.1.0/
        └── my-world.zip
~~~

标准输出为 JSON 报告，包含作品 ID、版本、ZIP 与目录路径、真实 SHA-256 和字节数。退出码 0 表示成功，非 0 表示失败。

工具从源码读取固定的 `package_id/authors/creator_notes/homepage/update_url`，用同一份发行数据生成包内 `publication.release` 和目录条目。作者源码保持原状，`--version` 和 `--notes` 只进入本次发行产物。包内仍只包含正式 world.json、components 和 assets，目录文件留在包外。

检查复用 `world:check/world:pack` 的正式卡片、状态/引用、资源、组件语法与模块依赖图校验，并重新验证最终 ZIP。目录校验和客户端使用同一份纯协议函数。工具不会执行作者代码、调用模型或代替实际导入试玩；发布前仍按[试玩步骤](packaging.md#发布前实际导入一次)检查。

## 发布顺序

1. 修改内容与本版说明，选择尚未发布的版本号。
2. 运行发行命令，检查报告，并用最终 ZIP 实际导入测试。
3. 先将 ZIP 上传到 `artifact.url` 对应的固定版本地址，确认无需登录即可直接下载。
4. 再上传覆盖 `update_url` 对应的 `releases.json`。
5. 首次分享时给玩家当前 ZIP 或其直接下载链接，另附面向人的作品说明。

目录先发布、ZIP 尚未可用会让玩家下载失败。历史版本必须继续指向自己的原始文件，不能把全部历史路径重定向到最新版。目录与 ZIP 可以托管在不同域名，路径也无需遵循示例形状。

`releases.json` 是完整公开目录，旧发行对象应保留。确需撤下某个版本时，从公开目录移除该记录；玩家下次成功检查会整体替换缓存，不继续累计撤下条目。不要为了每次更新手工填写一个冗余 latest 字段。

## 版本不可覆盖

同一个作品 ID 和版本号绑定同一份发行文件。脚本拒绝已存在的版本记录，也拒绝覆盖目标 ZIP；旧目录的错误字段或不同作品 ID 同样会中止。发布后修改包内任何内容，都应使用新版本号重新发行。

SHA-256 和大小根据最终 ZIP 计算，不能先写入卡内再打包，否则会形成“ZIP 包含自身哈希”的循环。它们只在包外的目录记录中保存。

若发布前命令失败，脚本保留旧目录并清理此次未完成的文件；已有发行 ZIP 不会被删除或改写。同一目录的并发发行使用临时锁，遇到 `RELEASE_INDEX_LOCKED` 时先确认是否仍有命令在执行；只有确认进程已结束，才处理残留的 `releases.json.lock`。目录被其他程序修改时中止，避免丢失外部修改。

## 玩家如何取得和应用更新

Server 每次成功启动后检查一轮；玩家也可以在详情主动“获取版本列表”或“刷新版本列表”。打开列表、详情或版本弹窗仅读取本地缓存。新导入的卡不会立即自动联网，但可直接手动获取。

检查只获取目录。玩家选择目标版本并确认后，才下载并覆盖当前安装。列表红点表示公开目录有更高版本，看过更新说明不会消除；安装最新版本后消除，回退后重新比较。

覆盖保留原 worldId、会话消息、运行状态及本地管理配置；作者内容、组件与资源换成目标版。已有会话会使用目标版的人物、世界书和舞台；回退不会回滚玩家剧情进度，也不会更换当前更新源。

需要保持已有玩家角色与状态定义兼容。持续保留的 global 根集合和类型必须一致；已有会话时 session/message 根集合和类型也必须一致，数字范围只允许放宽。无会话时可修改 session/message 定义；rules、load、initial 可以修改，但不会重置已保存运行值。删除已使用的角色、增删需保留的状态根、改变类型或收紧范围会被拒绝。JSON 内部路径及剧情语义不由此静态校验证明；较大玩法变化应明确建议玩家另行导入并新开会话。

## 常见问题

| 现象 | 检查位置 |
| --- | --- |
| 没有版本入口可用，或提示无更新源 | 包内是否有有效 `publication.update_url`；离线卡可添加 update_url 后重新分发 |
| 获取失败但仍显示旧版本 | 旧成功目录被保留；检查远端 HTTP、公开 HTTPS 地址、JSON 结构和作品 ID |
| 点击刷新后没有新版本 | 目录是否已更新；新版本是否为更大的数字三段；不能按发布日期推断 |
| SHA-256/大小不符 | 是否上传了报告中的同一个最终文件；托管地址是否返回 HTML 或另一版本 |
| 同版本冲突 | 是否重打/替换了同版 ZIP；使用新版本发布修改 |
| 覆盖提示忙或 revision 冲突 | 等待叙事/AI 帮答结束，刷新详情后再次选择 |
| 角色/状态不兼容 | 保留原 ID/类型与兼容范围，或告知玩家作为新世界导入 |
| 包资源缺失 | 复用正式打包工具；不要单独分发引用包内资源的 JSON |

完整错误响应及版本 API 见[Server HTTP](../runtime/server-http.md#世界版本与覆盖)。没有集中托管服务时，合规静态 JSON 与 ZIP 仍可完成整个检查和应用流程。
