# 预设与模型

世界卡决定“这个世界有什么”；预设决定“怎样组织材料与叙事”；模型配置决定“请求发给谁”。把它们分清，作品就能在玩家自己的模型配置下运行，而不需要把作者的密钥或本地配置 ID 放进卡包。

## 从标准叙事开始

首次启动会安装「标准叙事」。它是文字世界的起点，包含人物、世界书、历史、状态更新、行动建议与角色立绘所需节点。权威文件是[初始化预设](../../initial-data/presets/标准叙事.json)，不另外维护一份供复制的旧默认 JSON。

先用它验证世界内容。需要改变语气时，再创建自己的预设或调整节点。先备份原预设，方便恢复；恢复某节点默认内容会替换该节点的自定义文字。

| 你想改变什么 | 优先改哪里 |
| --- | --- |
| 林舟的身世、习惯和知情边界 | 世界卡角色 content |
| 灯塔规矩和任务背景 | 世界书 |
| 当前银币和已知线索 | 状态定义及更新规则 |
| 有哪些表情、姿态或服装图片 | 世界卡角色 sprites |
| 哪些人物需要显示、怎样安排相对位置 | 预设 characterSprite 节点 |
| 整体采用简短对白、慢节奏描写 | 预设 main / 自定义风格节点 |
| 服务地址、API Key、可用模型 | 模型配置 |
| 温度、top-p、思考开关等请求偏好 | 预设模型参数；实际支持取决于模型路线 |
| 历史保留与摘要策略 | 预设上下文设置 |

不要用一句“这个模型支持”替代连通性和实际请求验证。配置保存成功也不等于账户额度、模型权限或所有参数都可用。

## 提示词编排

预设是一层节点列表。内置系统节点保持既定相对顺序；自定义文字节点可以插入其间。自定义节点选择明确的消息角色，填写内容并开启。内置节点的类型/角色受平台约束。

主提示词负责叙事要求，例如：

~~~text
用清楚、具体的动作和对白推进场景。尊重玩家对自身角色重要行动和对白的决定权。
人物只依据亲历、被告知或已经确认的事实行动。保留未知信息，避免提前揭露答案。
~~~

这段可以合并到适当节点，不应替换掉用于装入人物、历史、用户输入的必要变量。世界状态（worldState）是历史之前的固定系统节点。状态更新（stateUpdate）、行动建议（actionSuggestions）、角色立绘（characterSprite）按此顺序作为可选能力。

服务端按实际声明并启用的节点构建。节点缺失或 enabled=false 时，不构建它的 prompt，也不在历史消息末尾追加它的数据块。启用后还要满足该节点的数据条件：状态更新的历史旁注需要任一域有适用状态，生成更新指令还需要激活的消息根，characterSprite 需要非空素材目录。已启用节点的 prompt 为空或变量非法会校验失败，不自动补回默认文字。

状态更新开关也控制本轮模型的写权限。关闭后，当前状态仍可阅读；如果模型自行输出状态更新，服务端会解析并记录拒绝结果。

## 可用变量

以下是此版本服务端预设可用的系统变量。世界素材与模型结果均按本轮捕获的数据构建。

| 变量 | 内容 |
| --- | --- |
| `{{user}}` | 选中的玩家身份名称 |
| `{{system.language}}` | 应用选择的回复语言：简体中文 / English / 日本語 |
| `{{persona.content}}` | 玩家角色材料 |
| `{{characters.content}}` | 已激活的其他人物正文拼接结果 |
| `{{world.lore}}` | 已激活的世界书正文 |
| `{{history.summary}}` | 当前使用的摘要 |
| `{{history.messages}}` | 保留历史消息，以原生消息角色加入 |
| `{{input.text}}` | 本轮用户输入 |
| `{{state.global}}` | 已加载的全局状态，只读背景 |
| `{{state.session}}` | 已加载的本局状态，只读背景 |
| `{{state.message}}` | 当前消息状态的值和说明，JSON 根附 type: json |
| `{{state.update.message}}` | 「状态更新」节点专用，列出已激活的消息根和已提供的规则。缺少 rules 的根仍可更新 |
| `{{characterSprite.catalog}}` | 角色 ID/姓名、素材 ID/说明及当前玩家角色 ID；不包含图片地址 |

`characterSprite.catalog` 可在其他节点引用，但只有 characterSprite 节点存在、启用且世界有素材时才有值；否则为空，不能通过自定义节点绕过开关加载目录。

`history.messages` 必须且只能在历史节点出现一次，`input.text` 必须且只能在输入节点出现一次。后处理节点不要重复插入输入、历史或摘要。未知变量、无效角色或内置节点顺序会导致保存校验失败。

角色/世界书里的 `{{state.message.coins}}` 是作者字段变量，不等同于预设整域变量。不要把两套规则互相套用；详见[世界内容变量](world-content.md#变量不要复制酒馆宏后就假定会展开)。

## 状态更新与行动建议

主叙事一次请求可以同时产生正文、状态更新、行动建议和立绘快照，平台把结构块与可见故事分离。状态失败不会自动让有效正文或另一项建议失效；停止或模型中断时，已显示正文可能保留，后处理不因此保证执行。

需要检查模型输出时，当前状态块使用 **JSONL**，每个非空物理行一个完整对象：

~~~text
<state_update>
{"path":"coins","value":10,"reason":"正文确认购买船票花费两枚银币"}
{"path":"clues","value":["信封上的灯塔印记"]}
</state_update>
<action_suggestions>
["向林舟询问信封印记。","沿码头寻找旧航线的线索。"]
</action_suggestions>
~~~

这是协议示意，不是每轮都要复制的固定结果。状态块没有外围数组，一项更新不能跨行；`path` 不含 scope 前缀。数组字段的值仍是完整 JSON 数组。行动建议自身使用字符串数组，点击建议会填入草稿，玩家确认发送后才构成行动。

行动建议来自主叙事。AI 帮答使用单独的预设和模型，生成供玩家编辑的输入草稿。精确处理规则见[叙事协议](../runtime/server-narrative.md#叙事后处理与能力结果)。

## 角色立绘

先在[角色 sprites](../reference/world-card.md#角色立绘)中声明可用素材，再启用预设的 characterSprite 节点。默认节点会装入 `{{characterSprite.catalog}}`，按本轮最终正文选择人物与素材；无素材时不会构建立绘 prompt、输出指引或历史立绘旁注。

创作者可以调整人物优先级、表情选择及相对位置策略。位置表达故事安排，支持 left、center、right、top、topleft、topright、truecenter；前端组件可以按自身布局选择展示其中哪些位置。

模型每轮输出完整的当前快照。以下示例假设三个角色及对应素材均已声明：

~~~text
<character_sprite>
{"position":"left","characterId":"alice","spriteId":"restrained_smile"}
{"position":"center","characterId":"bob","spriteId":"default"}
{"position":"right","characterId":"carol","spriteId":"default"}
</character_sprite>
~~~

每个非空行是一个完整 JSON 对象，只含 position、characterId、spriteId。**同一快照内，一个角色只能出现一次，一个位置只能分配给一个角色。** 可以超过两人；七种位置各自唯一，最多形成七个有效条目。

服务端从上到下逐行校验。JSON、字段、角色/素材引用、位置或唯一性失败时跳过该行，其他行继续。第一条有效行优先；失败行不占位。例如 Bob → left 因 left 已被占用而失败，后续 Bob → center 仍可通过。

| 输出情况 | 保存与通知 |
| --- | --- |
| 全部行通过 | 保存完整快照并发送立绘变化通知 |
| 部分行通过 | 保存通过项与行错误；通过项组成完整新快照并通知 |
| 非空块全部失败 | 保存失败结果，不发送清场通知 |
| 明确空标签 | 保存成功的空数组并通知清场 |
| 完全没有立绘标签 | 不产生本轮立绘结果 |

快照不与上一条消息合并，也不会从历史补回失败行涉及的角色。当前场景不需要任何立绘时输出：

~~~xml
<character_sprite></character_sprite>
~~~

立绘历史旁注采用同样的节点启用条件：从历史选最近两条有可见正文的助手消息，只对最终保留的消息追加其自身有效快照。没有结果、解析失败或数据读取失败时，也追加完整空标签，帮助模型遵守输出格式。历史空标签只存在于模型输入，不改写消息结果或额外通知清场；节点关闭时连空标签也不追加。

世界详情提供角色素材声明，character_sprite.changed 事件的每个条目携带 asset，指定消息查询返回已保存的立绘 ID 与位置，图片仍通过既有资源入口访问。预设启用且世界有素材时，会话输入框上方提供「立绘」开关；该开关只控制宿主展示。精确接口见[Server HTTP](../runtime/server-http.md)。

## 上下文与长篇游玩

滚动摘要将较早历史整理为摘要，滑动窗口裁去超出窗口的旧历史。两者都受模型和预设的上下文预算限制，不能保证无限完整记忆。

创作者可以通过精简常驻材料、按关键词/状态加载资料、把当前事实保存为状态来减少噪声。不要把整部设定集和所有未来情节都常驻。若出现容量错误，查看[排错](troubleshooting.md)，先辨认是固定材料太大还是历史太长。

## 分享预设时

世界 ZIP 不包含模型 Key，也不包含你的会话历史。需要特定叙事风格时，可以另外分享导出的预设 JSON，并说明作品需要开启哪些节点；不要要求接收者使用你环境里的模型或预设 ID。写清推荐的风格、必要协议和已测试配置，比只写“必须某模型”更便于复现。

## 配置 AI 帮答

在预设库选择「AI 帮答预设」，打开「标准帮答」，选择本机模型并保存。在应用设置选中这份帮答预设作为默认值，也可以在创建会话时或在舞台的「会话设置 → AI 帮答预设」为当前会话单独选择。会话设置中的目标可留空，预设节点使用 `{{session.reply.assist.goal}}` 引用当前会话的目标。主提示词始终启用，其余材料节点可关闭。草稿会流式填入玩家输入框，由玩家决定何时发送。
