# 打包与分享

一份可分享的作品需要让接收者取得同样的内容、组件和素材。最小文字世界可以只交付 JSON；包含外置组件或包内资源的作品使用 ZIP。需要正式作者署名、发行版本和在线更新时，按[作者发行指南](world-publishing.md)使用 0.2 publication 与 `pnpm world:release`。

## 包内布局

~~~text
my-world.zip
├── world.json
├── components/
│   ├── Stage.tsx
│   └── panels/
│       └── Status.tsx
└── assets/
    ├── images/
    ├── audio/
    ├── video/
    └── fonts/
~~~

ZIP 根必须直接包含固定名称 `world.json`，不能再包一层同名目录。只有根 world.json、components 和 assets 进入导入包。创作目录中的 README、授权说明和迁移记录可随源码另外分发；需要在包中带素材说明时可放入 assets 下的文本文件。

组件目录可以分层，但组件之间仍按**登记的 ID**导入，不按磁盘文件路径导入。定义示例：

~~~json
{
  "cover": "sr-asset://assets/images/cover.svg",
  "components": [
    {"id": "Status", "path": "sr-asset://components/panels/Status.tsx"}
  ]
}
~~~

这些字段合并到 data。包内 URI 从 assets/components 根开始，使用原始路径，不提前 URL 编码；大小写与文件名保持一致。不要使用本机绝对路径、反斜线、`..`、符号链接或只在某个平台有效的文件名。

## 检查和构建

在仓库根运行：

~~~sh
pnpm world:check examples/worlds/fog-harbor
pnpm world:pack examples/worlds/fog-harbor --out dist/worlds/fog-harbor.zip
pnpm world:check dist/worlds/fog-harbor.zip
~~~

`world:check` 接受创作目录、JSON 或 ZIP。`world:pack` 接受目录，省略 `--out` 时在源码目录同级生成 `<目录名>.zip`。相对路径均以仓库根解析；指定输出可以是相对或绝对路径。不要把输出 ZIP 放进被打包的 components/assets。

成功退出码为 0，失败为非 0；报告为 JSON。打包会先检查源码，再检查生成的最终包。已有输出文件不会被静默覆盖；更新时使用新的输出名，或确认旧文件可重建后自行删除。

## 检查覆盖什么

| 检查 | 能发现什么 | 仍需要你检查什么 |
| --- | --- | --- |
| 世界结构与状态 | 缺字段、错误类型、无可扮演身份、无开局、非法初值 | 人物设定是否连贯、状态含义是否清楚 |
| ID 与引用 | 重复 ID、缺失组件、开局引用未定义状态 | 组件是否出现于期望位置 |
| 包资源 | 包布局、声明资源路径、文件缺失、大小限制 | 动态拼接资源、远程链接与许可 |
| 模块检查 | TSX 语法、支持的导入、依赖图 | React 渲染、点击、媒体、窄屏布局 |
| 最终 ZIP | 发出的包是否能通过真实导入校验链路 | 实际应用导入后的全部页面和模型叙事 |

工具不执行组件、不下载或验证远程 URL、不向模型发请求。组件内部用运行结果拼出的资源地址不一定能被静态分析穷举。即使报告通过，也要实际打开关键页面并检查相应素材。

## JSON 与 ZIP 的区别

单独导入 JSON 时，可以使用内联组件和可访问的外部资源；不能使用依赖包内文件的 components.path 或 `sr-asset://assets/...`。把一个引用本地资源的 world.json 单独发给别人会丢失这些文件。

ZIP 可以带齐素材，减少对图片外链的依赖。它使素材随作品分发，**不代表模型推理能够离线运行**；远程模型仍需要接收者配置连接。引用外部媒体时，是否加载还受网络、源站和隔离策略影响。

## 发布前实际导入一次

1. 用最终 ZIP 导入一个新的测试世界；不要只在旧副本中看效果。
2. 打开介绍和每个开局预览，确认没有缺图或组件错误。
3. 创建会话，检查身份、开场和初始状态。
4. 完成至少一轮行动，检查正文、状态和建议是否符合设计。
5. 在桌面与窄屏查看正文、状态面板、按钮和媒体。

普通导入会创建独立世界，不自动覆盖旧作品或迁移旧会话。源码改变后，旧 ZIP、旧导入世界和旧会话仍可能是旧内容。正式发行卡可由玩家明确选择并确认在线升级或回退，保留原世界与会话；这与普通导入是两个入口。给每个交付版本填写 publication.release.notes，并按[作者发行指南](world-publishing.md)维护不可变文件与完整目录。

## 给玩家的作品说明

随下载说明写清：

- 作品名、作者、版本与适用的 SR 版本/提交。
- 玩家扮演谁、从哪个开局开始、可以做什么。
- 是否需要额外预设或外部资源，已验证过的模型/风格要求。
- 源码、素材的来源与再分发条件；保留原作者署名。
- 已完成的检查、试玩步骤和已知问题。

世界导出包含作者内容和资源，不是聊天备份，也不打包 API Key、模型配置或个人会话数据。分享前检查自己放进 assets 的文件，避免把无关私人材料一起打包。

精确字段与大小限制见[世界卡格式参考](../reference/world-card.md)；错误码和常见现象见[排错](troubleshooting.md)。
