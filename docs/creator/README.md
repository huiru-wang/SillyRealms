# 创作者手册

把一个设定做成能游玩的世界：写人物和开局，决定什么会随剧情改变，再为玩家安排合适的呈现方式。你可以从文字世界开始，也可以用 React 组件制作状态面板、插图和自己的会话舞台。

这套手册用同一个故事「雾港来信」贯穿内容、状态、界面和打包。先做出一张能玩的卡，再按作品需要增加能力。

## 先认识四个对象

**世界卡**保存作者的设计：人物、世界书、开局、状态定义、组件及素材。它是一份 JSON，或包含这些文件的 ZIP。**导入的世界**是 SR 保存的一份独立副本；导入同名卡并不等于更新原世界。**会话**是玩家选择身份与开局后的一次游玩，持有自己的历史和进展。**预设与模型**决定如何组织请求、如何叙事及由哪个模型回答，玩家可在自己的环境中配置。

创作目录、打包文件、导入副本是三个不同对象。修改本地源码后，需要重新打包、导入并新建会话验证；已有副本不会自动同步源码。世界卡也不是会话存档，分享世界卡不会附带你的聊天进度或模型密钥。

## 三条创作原则

1. **同一事实有一个当前值。** 当银币已作为状态保存时，人物提示词不再写死“永远有 12 枚银币”。界面和下一轮叙事都读取这个状态。
2. **先写发生的事，再定义变化。** “询问线索”是尝试，“得到了灯塔印记”才是可以保存的结果。规则给模型提供判断依据，不能替代实际试玩。
3. **从可用的默认界面增补。** 官方舞台组合 `SR.WorldStory` 的正文、历史和状态与独立的 `SR.ActionSuggestions`。自定义舞台可继续复用两者，在 `useSRActionSuggestions()` 的 items 非空时才挂载整个行动区；也可以用同一 Hook 编写自己的视图，见[呈现与交互](presentation.md)。

## 能力边界

世界卡可以声明状态和加载条件；主叙事根据已加载的消息状态生成更新。作者组件可通过 SDK 读取会话数据、提交允许的操作。介绍和开局预览只读世界全局状态，没有会话身份。

酒馆 PNG、插件脚本、宏和正则不会自动成为等价的 SR 作品；迁移需要检查原行为。当前手册讲解已存在的文字叙事、状态和组件能力，不把计划中的记忆模块或视觉小说演出写成现有功能。完整字段见[世界卡格式参考](../reference/world-card.md)，API 细节见[SDK 手册](../sdk/README.md)。
