# 状态与规则

状态保存故事中需要持续使用的事实。比如玩家已经得到哪些线索、还剩多少钱、正在做什么任务。模型以当前值续写，组件也显示同一份值，避免文字和界面各维护一套数据。

本章给最小世界增加「雾港来信」使用的三个 message 状态。完整源码见[示例 world.json](../../examples/worlds/fog-harbor/world.json)。

## 1. 先选对作用域

| 作用域 | 生命周期 | 适合放什么 | 谁会更新 |
| --- | --- | --- | --- |
| `global` | 同一个导入世界的会话共享 | 确实需要跨局共享的世界信息 | 应用/会话舞台通过受限 SDK 写入；主叙事只读 |
| `session` | 单次会话 | 本局难度、玩家建角选择 | 应用/会话舞台写入；主叙事只读 |
| `message` | 随会话消息保存与继承 | 当前银币、任务、线索、人物现状 | 主叙事更新已激活根；舞台也可提交字段写入 |

普通作品的银币和剧情进展通常从 message 开始。把每局的银币放在 global，会让同一世界的其他会话也看到变化。`message` 的历史继承是存储行为，不代表界面已提供任意楼层回退或分支存档。

## 2. 声明初值和含义

将以下对象放入 `data.state`。如果已有状态，合并根字段，不要覆盖原定义。

~~~json
{
  "schema_version": 2,
  "scopes": {
    "message": {
      "coins": {
        "type": "number",
        "initial": 12,
        "min": 0,
        "description": "旅人随身的银币。",
        "rules": {
          "coins": "只在正文确认付款、收入、遗失或得到银币时更新余额。报价、计划购买和行动建议不扣款；没有变化时保留旧值。"
        }
      },
      "clues": {
        "type": "json",
        "initial": [],
        "description": "旅人已经确认的线索列表。",
        "rules": {
          "clues": "只收录正文中已获知的线索，保留已有线索、去除重复；猜测和计划调查的地点不写入。更新时给出完整数组。"
        }
      },
      "quest": {
        "type": "string",
        "initial": "寻找信件的收件人",
        "description": "当前正在推进的任务。",
        "rules": {
          "quest": "目标明确改变或完成后才更新；询问和建议本身不代表任务完成。"
        }
      }
    }
  }
}
~~~

根字段必需 `type`、`initial`、非空 `description`。`type` 可为 `string/number/boolean/json`；对象和数组用 `json`。只有 number 支持 `min/max`。

`rules` 可省略。它是给模型看的更新依据，不是执行代码，也不是“必须覆盖每个字段”的 schema。你可以只写容易误判的字段；程序检查数据、路径、数值边界等结构条件，不能证明某件剧情事实一定发生过。

## 3. 为不同开局设置不同起点

「灯塔下的约定」可以在开局中写：

~~~json
{
  "initial_state": {
    "clues": ["信封上的灯塔印记"],
    "quest": "向林舟核对灯塔印记"
  }
}
~~~

这段只合并到对应的 `openings[]`。银币不在覆盖列表，仍从 12 开始。所有开局覆盖的根必须先在 message 定义中声明。

上面是只覆盖两个根的教学片段。仓库完整版为了让起点一目了然，在两个开局中都显式给出了 coins=12；如果直接修改完整版的 coins.initial，还要同步修改 openings 中的 coins 覆盖值。

**对象整根覆盖：**若有 `hero: {name, age, skills}`，开局中只给 `hero: {name}` 会替换整个 hero 根，其他字段不会自动补齐。以后写入已经消失的 `hero.age` 也不会自动创建它。希望保留的字段应在完整覆盖值里写全。

## 4. 让模型使用状态

使用「标准叙事」预设，并保持世界状态节点启用。平台在每轮开始时读取当前状态，按加载条件选取根，然后给模型提供当前值、含义和已有规则。

模型更新只作用于本轮激活的 message 根及允许的已有路径。global/session 作为只读上下文。状态定义的 `load` 与人物、世界书相同；设为 `never` 或条件不满足的根不会成为本轮模型可更新状态。

正常创作不必在世界书里再写一套输出标签。平台预设负责输出协议；确需排查时，可参考[预设与模型](presets-and-models.md#状态更新与行动建议)。

## 5. 在舞台中显示同一份值

官方正文已经能显示状态。要做自定义面板，在已注册的会话组件中读取它：

~~~tsx
import React from 'react';
import { useSRState } from '@sillyrealms/sdk';

export default function Purse() {
  const [coins] = useSRState<number>('coins', 0);
  return <p>随身银币：{coins}</p>;
}
~~~

`useSRState` 默认 message，参数里的 0 只是界面缺省值，不会创建字段。把它放进舞台组件并登记的步骤见[呈现与交互](presentation.md)。

如果制作玩家可修改的建角表单，使用 `useSRStateAPI` 或 Hook 返回的设置函数，捕获请求失败并逐项检查回执。生成过程中状态可能被锁定；收到成功回执后仍以回读或宿主快照为准。不要只修改 React state 就提示“已保存”。[SDK 写入示例](../sdk/state.md)

## 更新路径与数组

| 需求 | 写法 |
| --- | --- |
| 改银币 | 路径 `coins`，值为新的总余额 |
| 改已有对象中的姓名 | 路径 `hero.name`，值为新姓名 |
| 添加/删除一条线索 | 路径 `clues`，值为修改后的完整数组 |
| 描述每个数组元素的规则 | rules 可使用 `clues[]`；它不是更新路径 |

当前写入按给定路径替换值，不提供 `add/remove/push` 操作协议，也不通过 `clues[0]` 或 `clues.0` 改数组元素。对 json 根整体替换时，保留同一对象中未变化的字段。

SDK 对不存在的路径可能返回成功但忽略修改；模型更新不存在路径会记录无效路径。两种场景都不应用“成功”推断字段一定被创建。需要新的字段时，修改创作源的定义和初值，重新导入测试。

## 验证一次真正的变化

1. 从“渡轮靠岸”创建新会话，核对银币 12、空线索和初始任务。
2. 发送“我只询问船票价格，还没有决定购买”。检查银币保持不变。
3. 在叙事已经明确成交的情况下，检查余额与正文一致；金额以实际回复为准，不能靠预先假定剧情算账。
4. 再问一次已知线索，确认没有重复条目。
5. 从另一个开局新建会话，核对灯塔印记已存在，且没有继承上一局的变化。

检查工具验证结构与初值，不能代替这组剧情验证。状态不变化时按[排错中的状态路径](troubleshooting.md#状态没有按剧情变化)逐层检查。
