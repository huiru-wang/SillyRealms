# 使用 Agent 创作

本仓库提供两份创作 Skill。它们是给能读写仓库文件的 Agent 的工作说明，使用同一套格式参考、SDK 和检查工具。无需把它们安装进个人全局 Skill 目录，也不依赖某个宿主的私有配置。

先让 Agent 访问这份完整仓库和准备使用的源文件。仅复制一个 SKILL.md、不给它所引用的文档和示例，不能获得完整创作环境。不同客户端是否自动发现仓库 skills 由客户端决定；下面的显式文件路径用法可作为入口。

## 从想法开始

把这段请求交给 Agent，并替换方括号里的内容：

~~~text
请先阅读 skills/sr-world-author/SKILL.md，再按当前仓库的世界卡规范创作。

主题：雾港中的送信人。
玩家身份：第一次到港口的旅人。
主要角色：守灯人林舟、渡口信使阿遥。
第一版玩法：找出信件收件人；记录银币、已确认线索和当前任务。
界面：优先复用官方 WorldStory，添加一个移动端可收起的状态面板。
素材：使用可分发的本地资源，缺少素材时明确说明。

在 examples/worlds/my-harbor/ 保存可编辑源文件。
交付 world.json、所需组件与素材、ZIP、实际检查结果和三步试玩说明。
~~~

不需要一开始把每个字段和 API 都描述清楚。给出玩家要做什么、作品气氛、必须保留的设定和想看到的结果，Agent 再把它们转成结构。

**预期流程：**Agent 读取规范与模板，先明确创作范围，再制作内容和最少状态；需要 UI 时按 SDK 编写；执行 world:check、world:pack 和最终 ZIP 检查；最后说明完成情况与试玩要点。

## 修改现有世界

~~~text
请阅读 skills/sr-world-author/SKILL.md。
修改 examples/worlds/my-harbor 中的世界：
加入“向林舟询问信件”的快捷按钮，点击后填入平台草稿，不直接发送。
保留原角色设定、开局、状态字段和素材；检查组件在手机窄屏下的布局。
重新检查并输出一个新的 ZIP 文件名，同时说明本次改动。
~~~

明确源目录，避免 Agent 改到 data 下的已导入副本。若有尚未提交的修改，要求 Agent 阅读现状并保留它们。改动完成后需要重新导入测试；源文件和现有会话不会自动联动。

## 迁移已有作品

~~~text
请先阅读 skills/sr-tavern-migrate/SKILL.md。
源作品位于 [实际路径]，目标目录为 [新目录]。

先盘点角色、世界书、开局、变量、正则、脚本与素材，保留原作品内容。
逐项建立原行为到 SR 的映射；不能等价迁移的部分写明原因和影响。
制作可运行版本，交付源文件、ZIP、映射说明、非等价项及实际检查结果。
~~~

这个流程不会让原酒馆插件在 SR 中自动运行。Agent 必须分析行为，再用世界结构、状态和 SDK 重建。源文件缺失、外链失效或素材不能分发时，应清楚报告，不应编造“已还原”。

## 看 Agent 是否完成了工作

| 交付项 | 你应该看到什么 |
| --- | --- |
| 创作源 | 能继续编辑的 world.json，组件与素材分目录保存 |
| 结构说明 | 玩家身份、开局、核心玩法、状态分别放在哪里 |
| 检查结果 | 实际命令、输入路径、通过或失败；未执行项明确写出 |
| 最终 ZIP | 根目录正确，最终产物本身通过检查 |
| 试玩步骤 | 从哪个开局开始、输入什么、观察什么 |
| 限制 | 尚未运行的浏览器/模型测试、缺失素材、迁移非等价项 |

`world:check` 不会调用模型或执行组件。Agent 没有可用浏览器或模型配置时，仍可以交付通过静态检查的作品，并将互动/叙事验收留作明确待验证项；不能称“已经完整试玩”。

## 两份 Skill 的职责

- [sr-world-author](../../skills/sr-world-author/SKILL.md)：新建、扩展或修复 SR 世界；按内容、状态、呈现、打包的顺序完成。
- [sr-tavern-migrate](../../skills/sr-tavern-migrate/SKILL.md)：读取已有酒馆作品并保留创作意图，记录迁移映射和无法等价的部分，再完成 SR 交付。

两份 Skill 都指向本仓库文档，避免另存一套会过时的字段协议。修改规范时应同步维护示例、检查器和引用它的 Skill。更多使用方式见[仓库 Skills 索引](../../skills/README.md)。
