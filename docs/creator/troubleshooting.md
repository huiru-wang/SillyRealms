# 创作排错

先确定失败发生在源码检查、最终包、导入、组件运行还是模型叙事。每次只改变与现象相关的一项，保留失败命令和字段路径，便于复现。

## 快速定位

| 现象 | 首先做什么 | 下一步 |
| --- | --- | --- |
| 检查或导入提示内容无效 | 对同一文件运行 `pnpm world:check <路径>` | 按报告的字段路径修复，参考[格式](../reference/world-card.md) |
| ZIP 找不到 world.json | 打开压缩包看根目录 | 用 world:pack 构建，去掉多余外层目录 |
| 导入后仍是旧内容 | 核对源目录、ZIP 路径、导入副本和新会话 | 重新构建并导入新的测试副本 |
| 组件未显示 | 核对 components 登记和挂载引用 | 看[组件排错](#组件加载或运行失败) |
| 图像缺失 | 核对文件路径、大小写和资源 Hook | 看[素材排错](#素材没有显示) |
| 正文正常但状态不变 | 核对定义、load、节点和输出处理结果 | 看[状态排错](#状态没有按剧情变化) |
| 人物不出现或旧信息反复出现 | 核对加载条件、摘要/历史及重复事实 | 看[材料排错](#角色与世界书没有按预期加载) |
| 无法续写 | 检查模型连接、当前生成状态和上下文预算 | 看[叙事排错](#模型无法继续叙事) |

## 结构与包导入失败

常见错误及处理：

- `INVALID_WORLD_CARD`：看 `$.data...` 指出的字段。必须有 `spec_version: "0.2"`、完整 publication、非空名称、至少一个可扮演角色和一个有效开局。旧字段不会自动转换。
- 组件找不到：世界/角色/开局 presentation、stage_component 或消息规则引用的 ID 必须存在于 components。路径文件存在不等于组件已登记。
- `initial_state` 无效：只能覆盖已声明的 message 根，值要符合对应定义。不要加 scope 外壳或未声明字段。
- JSON 不能读包内资源：使用 components.path 或 sr-asset 资源后改用 ZIP。
- `INVALID_WORLD_PACKAGE`：检查根布局、重复/大小写冲突路径、符号链接和大小。资源不要包含操作系统额外打包的目录或隐藏文件。

检查目录通过、ZIP 失败时，要检查最终 ZIP 的实际内容。不要把旧压缩包的结果归因于新源码。

## 组件加载或运行失败

按顺序核对：

1. `components[].id` 与使用处一致；组件有默认导出。
2. 指定 path 时文件确实存在。path 优先于 inline component，读取失败不会回退。
3. 内部导入使用 `./组件ID`，每个依赖已登记，不是 `./目录/文件.tsx`。
4. 只使用当前环境提供的 SDK。介绍/开局预览没有 `useSRSession`、会话状态或写入能力。
5. Hook 在组件顶层调用；数据未加载时不会访问空数组的最后一项；异步读取有错误处理。
6. 运行 `pnpm world:check <目录>` 检查语法与依赖，再在实际页面看错误提示。

源码编译通过仍可能运行失败，例如读取不存在的数据或在 render 中触发副作用。打开浏览器开发者工具时，作者界面在独立 Stage 来源的 iframe 中；平台主页面与作者页面应分别查看。调试入口见[本地运行与调试](../runtime/local-development.md)。

切回详情预览不一定重新挂载；旧局部状态可以保留。要验证最新源码，请重新导入，或对已更新的导入内容使用重试/重新进入。源目录变更本身不会推送进已导入世界。

## 素材没有显示

确认 `sr-asset://assets/...` 与 ZIP 内路径逐字对应，包含大小写和中文字符。不要提前 URL 编码，也不要写作者机器上的绝对路径。

在 React 中使用 `useSRAssetUrl`，再把解析结果赋给 src。检查组件动态拼接后的实际路径；静态校验不会穷举所有运行时字符串。外部 URL 另检查是否可匿名访问、是否失效、是否被源站或浏览器策略阻止。

音视频没有自动播放可能是浏览器的用户交互要求。提供清晰的播放按钮，避免将“用户还没点击播放”当作素材不存在。离开或切换页面时确认媒体停止，不能依赖隐藏组件的所有 JavaScript 自动暂停。

## 状态没有按剧情变化

按这条链路定位：

1. **定义存在吗？** 检查 `data.state.schema_version: 2` 和根字段的初值。开局整根覆盖是否漏了对象子字段。
2. **域选对吗？** 主叙事只更新 message，global/session 是只读背景。
3. **本轮加载了吗？** `load.mode: "never"` 或未通过关键词/when 的根不会成为本轮模型更新目标。
4. **预设启用了吗？** 检查预设的「状态更新」开关，以及本轮是否激活了可写的消息根。当前值在「世界状态」节点展示。
5. **剧情真的发生了吗？** 询价、猜测、计划、建议都不等于成交或获得线索。
6. **输出有效吗？** 状态块为 JSONL，每行一个完整对象，无外围数组；path 不含 message 前缀，不使用数组下标。
7. **这一轮正常完成了吗？** 停止、长度中断或模型错误时可能保留正文，但不执行状态后处理。

调试模式的「数据处理结果」及服务端日志可帮助区分无更新、无效标签、无效路径和值校验失败。不要通过把所有状态常驻或把全部规则改成强制更新来掩盖原因。

SDK 写入则要捕获请求拒绝并逐项检查结果。缺失路径可能被忽略；生成期间可能出现 `STATE_WRITE_LOCKED`。同一世界其他会话生成时 global 也可能被锁。以实际回读值判断是否成功，生成结束后由用户重新操作。

## 角色与世界书没有按预期加载

关键词是区分大小写的字面匹配，扫描包含当前准备的摘要、保留历史和本轮输入。它不等于实时“在场名单”。`always` 仍要通过 `when`，世界书 `enabled: false` 会禁用条目。

先用明确的词触发一条简单资料，再检查组合条件。`when` 的状态路径应存在、作用域正确、值的类型一致。不要用字符串 `"12"` 与数值 12 混做相等判断。

如果当前银币更新了，叙事却反复称“只有最初的 12 枚”，搜索角色 content、世界书和开场中是否写死旧值。若玩家姓名没有替换，核对 `{{user}}` 是角色定义名称，动态姓名需要读取实际状态路径。未加载的状态路径展开为空。

## 模型无法继续叙事

先在模型配置中测试连接，再确认当前会话选择了预期模型。保存配置不保证模型权限、账户额度、路由或采样参数可用。调用失败的具体原因以真实错误为准，不把它一概归因于世界卡。

生成中不重复提交；先停止或等待当前执行结束。连接恢复不会自动重新发送你的行动。上下文容量错误时检查常驻角色/世界书/状态材料规模以及预设预算；滚动摘要也受容量限制。主材料本身太大时，仅缩短历史无法解决。

自定义预设导致请求构建失败时，核对内置节点相对顺序及变量归属，必要时在保留备份后恢复相关默认节点。

## 提供可复现的问题

反馈时提供：SR 提交/版本、世界源文件或最小复现包、运行命令、错误路径、所选开局/身份、复现步骤和预期结果。截图尽量同时展示相关状态与问题位置。日志中移除 API Key、凭据和无关私人内容。

请分别说明“检查通过”“应用导入成功”“组件实际打开”“模型完成一轮”四种结果。这样才能定位问题，而不用重做已经通过的步骤。
