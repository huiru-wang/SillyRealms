# 叙事 Prompt 状态变量 V2：实施任务

已实施下列变更。为遵守 Server 禁止跨业务模块导入私有实现的约束，共享语法和路径分段落在 `apps/server/src/lib/`，状态求值保留在 context 内。Web 复用编辑器已有的节点/摘要入口判断。

验证：功能定向测试、Web 测试、typecheck、lint 通过。Server 全套测试中，HTTP 关闭期间的 SSE 访问检查用例期望 503、实际返回 200；此项不属于变量渲染链路。

| # | 任务 | 验收 |
|---|---|---|
| 1 | 先固定世界卡透传边界。在既有导入用例放入合法、未知、非法、未闭合和含空白的占位。 | 导入成功，读回作者字段与源文本相同；原有世界卡结构与状态 schema 校验不放宽。 |
| 2 | 收敛扫描器，提取共用的安全状态路径解析；为作者/预设建立两组表驱动用例。 | 三域、中文键、空段、方括号、超深、危险键可区分；未知占位保留内部空格；坏开符不吞掉后续变量；作者的精确 user、普通反斜杠和预设的既有转义分别回归。 |
| 3 | 将预设 schema 和运行时迁移到同一语法，保留原有固定名及节点约束。 | 合法路径可随预设保存、导入导出；未知/非法路径的严格校验、旧 state.entries 迁移、历史/当轮输入的唯一性和 postprocess 的限制及回退行为不退化。 |
| 4 | 材料阶段先产生三域可见根，再实现基于捕获视图的只读求值。 | 单测覆盖根与子键、false、0、空串、null、对象、整体数组、数组不下钻、无值和不可见根；message 取实际 tip 继承值，读取其他域不增加 message 写权限。 |
| 5 | 在选中的玩家、NPC、世界书原始字段上一次扫描；普通/能力预设节点接入同一状态取值；保留各入口现有编码。 | 三类素材均得到方案示例效果；字段值或玩家名是另一个合法占位时仍按字面插入；通过 persona.prompt 等外层变量注入后不变；用户输入、历史、摘要、状态规则不获新增插值能力；缺值不触发能力回退。 |
| 6 | 验证候选裁剪与计量。 | 同轮两次候选使用相同视图，裁掉触发关键词后引用从有值变空，生成的文字本身不激活新根；新轮重新读取；展开的大对象计入实际预算，素材与能力文本不重复计量。 |
| 7 | 同步作者示例、维护约束、预设编辑器文案；执行验证。 | 作者能区分留空、透传和不递归；摘要编辑器不提示新增插值。运行定向导入/预设/状态/上下文测试，再运行 pnpm test、pnpm typecheck、pnpm lint，不启动服务或新建 mock E2E。 |
