# SR 简化状态提示与双输出插件方案 v6

日期：2026-11-15。状态：设计，未实施。任务见 [实施清单](./sr-output-plugins-prompts-v6-tasks.md)。

本文汇总 v5 之后的用户修订，以本次简化示例为准。业务代码、数据库、正式 docs 和 AGENTS 本轮均不修改。v5 未冲突的预设文案归属、无脚本、权限和无损迁移要求继续适用。

## 1. 最新产品结论

- 按最新修订删除“世界状态”系统节点。保留七个系统节点：main、用户信息、角色信息、世界书、会话历史、用户输入、行动建议。用户只要求删除世界状态，不同时删除行动建议；剩余节点固定存在，内容可查看。
- 预设能力区提供“世界状态”“行动建议”两个开关，分别绑定 `output_plugins.state_update`、`output_plugins.action_suggestions`，默认均为 true。这里“保持开启”按默认状态开启处理，仍允许通过开关关闭；运行时不强行覆盖 false。无正则、可执行脚本或用户可配置 parser/handler。
- 开启“世界状态”，在用户输入后、行动建议前插入完整 `<世界状态>…</世界状态>` system 提示；其来源标记为预设能力，不伪装成系统节点。开启“行动建议”，由保留的行动建议节点输出完整 `<行动建议>…</行动建议>` system 提示。两个能力各注入一次，使用预设中各自的完整模板，不能只注入格式片段或再叠加第二份节点提示。
- 所有 SR 模型提示文字、材料展示模板、例子仍保存于预设。服务端持有固定协议解析、数据序列化和执行校验，不内置自然语言补丁。
- 世界状态分为“当前状态：key → value”和“状态更新规则：同一个 key → description/type/min/max”。仅含本轮激活且获准更新的状态，无 scope/current_state/writable_state/readonly_state 标签。外层 `<世界状态>` 只组织输入提示，不是输出标签。
- global/session 中已加载且需要引用的值变为背景内容，分别放世界书节点的世界背景材料与会话历史节点的会话背景材料；后者为预设说明 system 消息，不冒充历史事件。不对外改变这两种 scope 的 API/SDK 权限。
- 世界状态能力关闭时不注入 `<世界状态>`、可写清单或更新规则。此前约定的 message 材料如需作为叙事参考，只能通过预设显式配置的背景模板放入已有背景区，不再依赖已删除的世界状态节点。能力区仍可查看完整模板和关闭状态。
- 不要求模型输出 `<sr_extensions>`。直接在正文末尾依次输出需要的 `<state_update>`、`<action_suggestions>`。
- 建议固定三条，数组顺序代表缓慢、中速、快速，每条最多 50 个 Unicode 码点（首尾空白去除后计数）；不展示额外速度标签，不再提供 2/4 数量选择。
- 暂不新增嵌套 fields/schema/check。JSON 子字段的业务规则继续写在所属状态项的 description 中。之前的 fields 示例只是可选提案，并未实施，本次不纳入。

这取代 v5 中“固定八节点含世界状态”“用户输入最后”“插件不能关闭”“含 scope 的状态对象”“保留 sr_extensions 外层信封”“建议 2/3/4、120 字符”的决定。根 AGENTS 的旧完整信封要求也因本次明确指令而调整为“完整可信的有序输出块”；修改事实文档要等代码实施后。

## 2. 当前实现差距

| 位置 | 当前情况 | 所需变化 |
| --- | --- | --- |
| context/direct-prompt.ts | 硬编码自然语言；状态项含 scope；封装 sr_extensions | 从预设装配说明/格式；值与规则分离；两个裸输出块 |
| context/prompt-builder.ts | 当前状态在 userInput 之前；世界书/历史有固定布局 | 调整后置顺序，背景材料与可写材料隔离 |
| runtime/config.ts | Direct 强制开启两个能力，存储 false 不生效 | 由冻结的预设开关决定，不再隐式覆盖 |
| extension-stream-splitter.ts | 只识别 sr_extensions 开始标签 | 新协议识别两个保留开始标签，完整支持跨 delta 的半标签 |
| extension-parser.ts | 必须有外层信封；内部严格 JSON 解析 | 独立的顺序块解析，复用 JSON 校验 |
| action-suggestions-handler.ts | 最多四条/120 字符，数量不符只警告 | 新协议恰好三条/50 码点，错误隔离 |
| domain/session/run-result.ts、SDK run-contract.ts | 识别 sr_extensions/v1 | 添加新协议读取/类型，保留旧记录 |

当前状态定义只支持 string/number/boolean/json 和根 number 的 min/max。description 是模型规则，不能据此宣称时间、JSON 内部类型、变化幅度或关联交易已被执行层校验。load.when 控制加载，不验证本轮更新。合法更新逐项应用，跨项业务一致性并非全有或全无。

## 3. 数据与规则的对应关系

值列表、规则列表、允许更新的根集合必须从同一次最终激活结果派生：同样的 key、同样的顺序，不允许规则中有未展示的可写根，也不允许显示值却漏掉其类型规则。

来源分别是当前冻结快照与世界卡定义：不能拿 initial 冒充当前值。description 缺失可省略该行；type 始终展示，min/max 只在 number 定义确实提供时展示。不能在提示层从描述推导并补造硬约束。

示例中的“主角.庄园声望”和独立“声望”需选择一个权威存储位置。本文采用独立 `声望:number`、当前值 50、min=10、max=100；从示例主角对象中移除重复值。这样范围校验实际有效。仅是设计示例，不自动转换用户世界数据。

所有模型输出 path 使用这些真实 key，如 `当前时间.当前时刻`、`主角.着装.衣服`、`声望`。不能把不属于该世界的 `世界.时间`、`金币`、`背包` 当本轮可写示例；独立教学示例如使用这些名称，必须显式声明独立基线。

展示模板保存在预设：标题、项目符号、字段标签、分隔符及节点前后文均可见。Server 只负责固定插槽和安全编码，预设不能 getState、任意遍历状态或执行脚本。字符串/对象/数组的值用 JSON 安全编码，正常字符串显示引号，以区别字符串“100”和数字 100；description 保留全文但作为编码后的资料值，不能闭合提示块。危险键名、尖括号和物理换行须安全编码，变量结果不能二次模板执行。示例、模板和背景说明包装不参加激活扫描。

## 4. 世界状态能力完整展开示例

以下是启用状态插件且有可写根的展开示例；数据来自世界，规则说明与格式来自预设。这里的示例内容不是服务器内置文案。

```text
<世界状态>
当前状态：
- 当前时间：{"当前日期":"新历2088年01月01日","当前时刻":"23:00","当日时段":"夜间"}
- 当前地点："Robin主卧"
- 主角：{"着装":{"衣服":"黑色外套","裤子":"深色长裤","鞋子":"室内拖鞋"}}
- 声望：50

状态更新规则：
- 当前时间：
  - description：根据本轮实际经过的时间更新时间；跨越午夜时同步更新日期；当日时段与日期、时刻保持一致。
  - type：json
- 当前地点：
  - description：仅在主角实际抵达新地点后更新；提议前往、准备出发不算抵达。
  - type：string
- 主角：
  - description：着装.衣服、着装.裤子、着装.鞋子仅在本轮实际更换时更新；替换整个着装或主角对象时保留其他仍有效的内容。
  - type：json
- 声望：
  - description：主角实际获得嘉奖时增加10；同一次嘉奖不重复结算，到达上限后不再增加。
  - type：number
  - min：10
  - max：100

输出要求：
- 先完成叙事正文，再依据正文中实际发生的事件更新状态。
- 遵守对应状态的 description、type，以及存在的 min/max。
- 计划、假设、行动建议和未完成的尝试不算已发生的变化，不重复结算历史事件。
- 只更新上方列出的状态及其合法对象子路径。path 使用真实状态 key，子路径用英文句点连接。
- value 是目标路径的完整新值，不是增减量或对象合并补丁；替换对象或数组时保留仍需存在的内容。
- 数组整体替换，不用下标路径；删除对象属性时替换所属对象，null 不表示删除。
- 输出一个完整的 state_update，内容为合法 JSON 数组；只列变化项，最多100项，没有变化时输出 []。
- 每项包含 path、value，可选简短 reason；不要输出内部判断过程。
- 该块位于正文后、行动建议块前，不输出额外外层标签；格式示意中的省略号不是合法 JSON。

输出格式：
<state_update>[]</state_update>
</世界状态>
```

空数组骨架是合法的无变化输出，正常变更示例统一见第 6 节，避免两个能力各放一段不一致的完整例子。

世界状态能力已开启但无可写根时，能力预览显示“本轮无可更新状态”。仍装配预设的完整无数据分支：当前状态/规则为空，输出要求明确本轮无需 state_update；不把通用示例误当真实可写数据。关闭能力则不注入该能力提示，不把“只读”混进可更新列表。

## 5. 行动建议节点完整 prompt

```text
<行动建议>
行动建议是提供给玩家选择的下一步行动，不代表已经执行。
根据本轮正文结束后的情境，按以下顺序生成三个建议：
1. 缓慢：停留在当前场景，通过观察、交流或细节互动展开故事。
2. 中速：采取具体行动，推进眼前事件或当前目标。
3. 快速：主动推动关键事件，尝试让局面进入新的阶段。

行动建议生成要求：
- 建议具体、简短，符合当前情境，三个方向有明显区别。
- 只描述玩家可以尝试的行动，不预先保证结果，也不提前改变状态。
- 每条不超过50个字符，不需要附加速度标签或解释。

输出格式：
- 在叙事正文之后输出一个完整的 action_suggestions，内容为恰好三个字符串的 JSON 数组。
- 如果本轮还需要 state_update，将 action_suggestions 放在它之后。
- 不输出额外外层标签，最后一个输出块关闭后不再追加正文或解释。
</行动建议>
```

“移动建议生成要求”统一更正为“行动建议生成要求”。预设能力开关是是否注入/解析行动建议的唯一开关；保留的行动建议节点引用该能力的同一份模板，不再有第二个节点启用开关，也不重复保存提示词。能力关闭时该段不进入模型请求，节点仍可在前端查看并说明由能力开关控制。新协议不沿用建议 [] 的宽松例外；生成不到三条时由建议插件报告失败，不由运行时补写建议。

## 6. 整体输出与四种开关组合

公共格式说明与完整示例是预设中可见的尾部模板，在能力详情中展示，附于最后一个生效的能力提示中，不新增系统节点。两个能力都生效时附于行动建议；只有状态更新生效时附于世界状态。具体分支由 Server 按冻结的两个开关和最终可写根集合选择；Server 不生成隐藏自然语言，也不重复注入公共格式。

公共文字：

```text
先输出完整叙事正文，再按顺序输出本轮需要的内容块。
每种块只出现一次；两个都需要时，state_update 在前，action_suggestions 在后。
实际输出不用 Markdown 代码围栏，不输出世界状态、行动建议等输入说明标签，也不增加外层包裹标签。
每个内容块必须完整闭合，最后一个块之后只允许空白。
内容块内使用合法 JSON，禁止注释、尾逗号、重复键、省略号和 NaN/Infinity。
JSON 字符串中的 < 使用 \u003c；正文要展示保留标签的字面文本时使用 HTML 实体。
```

两个插件都启用且存在可写根时的独立示例，基线使用第 4 节的值：

```text
五分钟后，你从主卧来到书房。管家递来嘉奖书，确认你此前完成的任务已获得正式表彰。

<state_update>
[
  {"path":"当前时间.当前时刻","value":"23:05"},
  {"path":"当前地点","value":"书房"},
  {"path":"声望","value":60,"reason":"本轮收到正式嘉奖"}
]
</state_update>
<action_suggestions>
["仔细阅读嘉奖书，向管家询问其中的细节。","与管家商量下一项任务的具体安排。","提出现在就去会见委托人，争取接下新的任务。"]
</action_suggestions>
```

| state_update 开关 | action_suggestions 开关 | 预期输出 |
| --- | --- | --- |
| 开，有可写根 | 开 | 正文＋state_update＋action_suggestions |
| 开，有可写根 | 关 | 正文＋state_update |
| 关，或没有可写根 | 开 | 正文＋action_suggestions |
| 关，或没有可写根 | 关 | 仅正文 |

状态无变化保留 []，与“没有可写根所以不要求状态块”不同。公共模板也按表选择；仅正文时不注入 JSON/输出块指导。教学示例不加入激活扫描，也不授予状态权限。

## 7. 无外层信封的解析与提交

这是协议变更，不是单纯改提示文字。建议新输出协议版本为 `sr-output-blocks/v1`，作为 Server 内部格式标识，而非预设新增自由配置。

### 流式正文切分

识别第一个完整的 `<state_update>` 或 `<action_suggestions>` 后，正文结束，后续只进入有界缓冲区，不显示为故事、不再回到正文模式。维护多标记的前缀保留窗口，覆盖任意 token/delta 边界、UTF-16 代理对与半标签 EOF。继续使用当前 262144 字节的总尾部上限，不逐块无限缓存。

两种保留标签都由结构切分器识别，以免模型误输出已关闭插件时标签泄露为正文；关闭插件不进行业务解码/执行。边界可确定的完整非预期块跳过并报告诊断。共享切分/结构检查不等于启用了对应插件。

正文禁止裸写这两个保留开始标签，即使放进代码块也会被视为输出尾部起点；需要展示时用 HTML 实体。不得新增不明确的正则回溯来猜测正文与协议。

### 顺序块语法

无外层信封后，整个尾部只允许：已知标签组成的顺序块，块间及块后空白。状态在建议前，每种最多一次。不能重排、重复、嵌套、含未知标签或在块后续写正文。

块边界仍用理解 JSON 字符串/转义/括号深度的词法扫描确认，不能通过简单 `split('</state_update>')` 截取。随后对启用的块使用现有 strict JSON 校验，拒绝重复键、不完整值和非有限数值。字符串中形似闭合标签的文字不能结束真正的块。

整体结构完整且模型正常 stop、无 toolCall、流式与最终消息一致后，才处理状态候选。读到 `</state_update>` 时不能立即写库，因为后面可能重复该块、结构损坏、被取消或异常终止。

### 失败语义

| 情况 | 状态/建议结果 |
| --- | --- |
| 必需状态块缺失或其数据非法 | 保留已生成故事，Run 失败，无状态变更，建议阻止发布 |
| 状态数组含部分无效项 | 合法项按序处理，报告 partial；建议阻止发布，保留现有逐项语义 |
| 状态有效；建议块完整可定位，但 JSON/数量/长度不合法或缺失 | 保留合法状态，建议失败，不自动重试或补齐 |
| 标签不闭合、重复/乱序/未知块、尾部夹杂正文，或 JSON 词法破坏导致边界不可确定 | 整体协议失败，不提交候选状态或建议；故事保留 |
| Provider length/error/断流、最终文本不一致，或提交前 stop | 不提交候选；按现有 Run 生命周期结算 |
| 关闭的插件输出了完整、边界可信的块 | 不执行该插件，记录意外输出诊断；不从其内容推导权限 |

因此“建议单独失败不丢有效状态”仅适用于边界可信的局部数据失败；建议半标签破坏整体结构时，依旧不能提交。以新的完整块序列替代外层信封的 framing 作用，不削弱正常终止和提交边界。

状态插件保持现有 path/value/reason、100 项、根授权、点路径、整值替换和逐项错误语义。建议插件新规则为恰好 3 条、每条 trim 后 1–50 个 Unicode 码点、三条非重复；不自动截断、补齐或改写模型文本。三种推进策略是模型语义要求，Server 不能仅凭字符串证明其推进速度。

## 8. 预设归属、兼容与 UI

- main 仅保留基础叙事/输入理解等规则，不保留冲突的旧外层信封要求。所有状态/建议/公共输出格式和示例在预设可见字段中管理。
- 预设 schema 与默认模板不再要求 worldState 系统节点。旧节点及其内容先按原生效语义迁入世界状态能力模板，原配置备份到 compatibility；已经失效的旧内容不得突然生效，不能直接删除用户文字。旧格式转换与新格式校验明确分开。
- Studio 系统节点列表只展示七节点；能力区默认勾选“世界状态”和“行动建议”，点击可查看完整模板与展开结果。请求预览中世界状态显示为“能力提示”，行动建议节点引用同一份能力内容；显示顺序与实际 Provider 消息一致。
- 候选预算预览、最终请求与前端查看使用同一装配逻辑。没有会话上下文时显示模板/来源说明，不伪造真实材料。
- 冻结发生在第一次 await 前；最终激活只根据最终摘要、保留历史、当前输入。值列表与规则列表一起计入完整请求预算。
- 两个布尔开关是新预设可编辑的输出插件设置。旧 count/preferences 等保留为兼容数据，新格式不再读取旧 count 覆盖固定三条；默认不开更多参数。
- 默认预设数据、旧预设物化、旧协议提示升级分开进行。保留用户原文/版本，禁止直接批量删除用户文本中的标签或把同名文字当协议清理；转换须有可审阅差异和备份。
