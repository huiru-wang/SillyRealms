# SR 主叙事立绘与官方舞台组件方案

日期：2026-11-24（Asia/Shanghai）
状态：方案，尚未实施。
代码基线：`main @ e4f238e`；当前目录是 `apps/server`、`apps/web`、`packages/sr-sdk`。
目标文件：`plan/主叙事立绘与官方舞台组件方案.md`。

## 1. 目标与确定范围

在普通主叙事中增加一种标准立绘能力：世界卡提供角色立绘目录，预设提供选择策略，模型在正文结束后输出左右槽完整快照，服务端校验后随助手消息持久化并通过现有会话 SSE 通知；舞台通过标准 SDK 显示。

本期分成两个可独立验收的交付：

| 交付 | 内容 | 完成标准 |
| --- | --- | --- |
| A：Server 标准立绘能力 | 世界卡字段、预设节点与变量、输出协议、独立后处理、消息存储、当前快照读取、SSE | 不依赖官方 UI，也能通过标准消息/HTTP/SSE 得到正确立绘结果 |
| B：Stage SDK 与官方组件 | Host 立绘展示投影、SDK Hook 与组件、默认舞台组合、左右胶囊、响应式与资源处理 | 官方舞台开箱可用，创作者自定义舞台也能通过公开 SDK 使用 |

主要决定：

1. 复用角色下的 `sprites[{id, asset, description}]`，默认素材 ID 为 `default`。
2. 新能力统一命名为 `portraitDisplay`，模型标签为 `<portrait_display>`，事件为 `portrait_display.changed`。
3. 每条正常完成的助手回复产出一份 `{left, right}` 完整画面；每侧最多一人，同一角色不同时占两侧。
4. 模型决定人物、表情/姿态和语义左右位置；组件决定实际坐标、尺寸、留白和窄屏呈现。
5. 有合法立绘素材时默认自动启用。胶囊控制本地显示，预设节点的开关控制是否生成立绘指令，两者分开。
6. 结果保存在现有助手 `extData.output.portraitDisplay`，不增加数据库表、列或通用世界状态字段。
7. 当前画面由服务端基于实际消息历史投影，不能依赖前端已加载的最近五轮。
8. 官方默认舞台新增 `SR.WorldStage` 组合 `SR.Portrait`、`SR.WorldStory` 和两个胶囊；自定义舞台自行选择组件。

### 1.1 与视觉小说计划的关系

沿用 [视觉小说与场景演出方案](./视觉小说与场景演出方案.md) 中已确定的素材格式。该计划仍是独立的后续范围：

- 本期保持普通叙事正文，立绘表示“本轮正文结束后的画面”。
- 本期没有逐句换表情、说话者逐段高亮、背景、音乐、音效、场景探索或 XML 演出正文。
- 旧计划已选定的 XML 演出正文不被这次尾块方案替代。未来视觉小说共享素材和底层图片组件，其逐段播放器负责画面；同一舞台不同时让 XML 播放器与普通尾块控制画面。
- [主动状态更新与 AI 帮答方案](./主动状态更新与AI帮答方案.md) 尚属规划。本功能按现有单叙事预设落地，不把“三场景预设改造”作为前置条件；未来迁移时立绘规则属于 narrative 场景。

## 3. 世界卡素材与开局契约

### 3.1 角色立绘目录

以下为世界卡局部示例，不是可以独立导入的完整世界卡：

~~~json
{
  "data": {
    "characters": [
      {
        "id": "alice",
        "name": "爱丽丝",
        "sprites": [
          {
            "id": "default",
            "asset": "sr-asset://assets/characters/alice/default.webp",
            "description": "平静站立。日常交流或没有更合适表情时使用。"
          },
          {
            "id": "restrained_smile",
            "asset": "sr-asset://assets/characters/alice/restrained-smile.webp",
            "description": "勉强维持微笑，眼神疲惫。适合掩饰担忧或安慰他人，不适合真正兴奋时。"
          }
        ]
      }
    ]
  }
}
~~~

字段规则：

- `sprites` 可省略或为空；非空时 ID 在角色内唯一，必须有且仅有一张 `default`。
- 每项 `id/asset/description` 均为非空字符串；不增设固定表情枚举。
- `spriteId` 同时表达表情、姿态、服装等素材变体，不再同时输出 emotion、expression 或另一套表情名。
- 角色继续使用既有 `character.id`；不复制角色 prompt、身份或人物表。
- 首版不增加素材级 `when`、解锁系统、数值坐标、动画参数。素材描述说明适用情境即可。
- 推荐透明背景 PNG/WebP、同一角色统一画布和脚底锚点；这是创作建议，不通过图片透明度检测阻断导入。

### 3.2 资源规则

`asset` 支持现有 HTTP(S) 资源，以及 ZIP 内 `sr-asset://assets/...`。在线素材推荐 HTTPS，是否实际可加载仍受源站和现有 iframe 策略影响。

需要把 `$.data.characters[i].sprites[j].asset` 纳入统一资源引用扫描：

- ZIP 导入和 `world:check` 校验包内文件存在，复用现有路径规则。
- 单独 JSON 导入不允许任何 `sr-asset://` 包内资源引用，立绘也不例外；包内素材必须随 ZIP 导入。
- 导出与重新导入后保留素材目录和资源引用。
- 远程资源只验证 URI，不在导入时批量下载或发起可用性探测。
- 模型不接收素材地址，输出也不能提供素材地址；SDK 用已有资源解析器将已声明 ID 映射到 URL。

### 3.3 开局初始画面

本期一并提供可选 `openings[].initial_portraits`，复用相同双槽结构：

~~~json
{
  "id": "arrival",
  "name": "抵达庄园",
  "content": "爱丽丝在门前等候。",
  "initial_portraits": {
    "left": {"characterId": "alice", "spriteId": "default"},
    "right": null
  }
}
~~~

- 左右字段都必须存在；角色、素材引用必须有效；左右不能重复同一角色。
- 未配置时初始为空，不自动挑前两个角色。
- 创建会话时随首条 assistant 原子保存成功的 portraitDisplay 结果，不另调模型。
- 继续只发送现有 `session.created`；其 entry 和随后 HTTP 读取已经包含初始结果，不伪造 run 事件。
- 初始画面不是世界状态，不产生 `state.changed`，也不替代 `initial_state`。
- `requireOpening` 再次解析开局时也要保留并验证该字段。

## 4. 自动启用、关闭与可选素材

### 4.1 启用公式

~~~ts
portraitEnabled =
  worldHasValidSprites &&
  (portraitNode === undefined || portraitNode.enabled !== false);
~~~

| 场景 | 本轮行为 |
| --- | --- |
| 世界没有 sprites | 不注入立绘资料/指令，不执行立绘能力 |
| 有合法 sprites，旧预设缺少新节点 | 自动补默认节点与 prompt，启用 |
| 有素材且节点 enabled=true | 使用该节点 prompt |
| 节点 enabled=false | 不注入、不执行立绘能力；保留已有历史结果 |
| 玩家关闭左/右胶囊 | 仅隐藏本地对应立绘，服务端照常生成与保存 |
| 无授权能力但模型偶然输出该标签 | 分离器隐藏保留块，执行器丢弃，不通过模型输出反向启用 |

旧预设使用“读取/运行时默认投影”：不批量重写数据库，不悄悄增加 revision。用户以后正常保存时，可把显示出来的默认节点一并保存。非空作者 prompt 保留，空 prompt 回退默认；明确的 false 必须保留。

当前 worldState/actionSuggestions 的旧 enabled 会被默认能力逻辑忽略。本次只为新 portraitDisplay 定义上述显式开关，不顺便改变其他能力行为。预设 UI 将开关说明为“生成立绘指令”；关闭后历史画面仍保留，用户可以用胶囊隐藏。

### 4.2 候选目录与角色 load 的关系

首版向模型注入**全卡已声明的合法立绘精简目录**，不把本轮 `activatedCharacters` 当作显示白名单。

理由：现有 `load` 决定角色 prompt 是否注入，不表示角色在场；角色可能仍在场但本轮未命中关键词，也可能在这轮正文首次登场。若以材料激活结果限制图片，会因裁剪、摘要或关键词变化无端改变可选画面。

目录只含角色 ID、姓名、素材 ID/描述和当前玩家角色 ID。角色完整 prompt 仍按原有 load 逻辑处理，不能从素材目录推定人物在场或获取完整设定。

这是首版明确的创作边界：sprites 的描述是公开展示资源说明，会参与立绘选择；不要依靠角色 load 隐藏素材描述中的剧情秘密。条件解锁以后再通过独立、明确的素材可见性规则扩展，本期不暗中复用 load 作为解锁系统。

全目录和当前快照必须纳入真实请求预算。沿用现有裁剪/摘要及超预算行为，不静默截断某些人物的素材，也不额外调模型筛选。

## 5. 预设节点、变量和提示词

### 5.1 新节点

~~~json
{
  "id": "portraitDisplay",
  "name": "立绘显示",
  "kind": "postprocess",
  "role": "system",
  "enabled": true,
  "prompt": "此处保存可编辑的立绘选择策略，默认正文见下节。"
}
~~~

加入现有 postprocess 内置序列，排在 worldState、actionSuggestions 之后。同步修改服务端与 Web 的内置 ID、排序、变量列表和恢复默认行为，旧系统节点相对顺序不变。

新建默认预设和 `initial-data/presets/标准叙事.json` 带该节点。main 的文案改为遵守“本轮启用的能力协议”，避免硬编码只有两种尾块。

新增变量：

| 变量 | 值 |
| --- | --- |
| `{{portraits.catalog}}` | JSON 文本：playerCharacterId、characters，角色含 id/name 和 sprites 的 id/description；没有 URL、角色 prompt 或图片数据 |
| `{{portraits.current}}` | 本轮开始时的左右快照；没有有效历史结果时为双 null |

两个变量在首次异步等待前对应的领域快照上确定，整轮不变。当前画面从完整持久历史投影，不能随着历史裁剪候选变化。无需再把立绘块追加到最近两条历史 assistant 的 model-notes。

能力节点继续禁止引用 `input.text/history.messages/history.summary`；故事上下文已经存在，不重复注入整段历史。模板一次渲染，替换值不递归解析。未启用立绘时不注入这些资料；其他节点引用它们时返回空值，不能绕过能力开关引入目录。启用时跨节点引用仍按现有变量机制处理并计入预算，默认只在立绘节点各引用一次。

### 5.2 默认策略 prompt

~~~text
你负责为本轮正文结束后的当前情境选择左右两侧的角色立绘。

【可用立绘】
{{portraits.catalog}}

【本轮开始时的画面】
{{portraits.current}}

根据最终正文中可确认的当前情境选择人物，不把回忆、提及、设想或尚未执行的行动当作人物在场。
每侧最多一人，同一角色只占一侧；优先显示当前互动的主要人物，最多两人。
已有角色仍适合显示时尽量保留原侧，避免无理由换位；只显示一人时优先保留原侧，新出现的单人默认放左侧。
依据素材描述选择贴合情境的表情、姿态或服装，没有更合适素材时使用 default。
不为展示立绘编造剧情，不根据角色材料被加载就认定角色在场。
人物离开当前画面且没有替代人物时，将对应侧设为 null；两侧都无需显示时全部设为 null。
如果本轮没有导致画面变化，仍输出当前完整左右快照。
只使用可用目录中的角色 ID 和素材 ID，遵守平台规定的输出协议。
~~~

创作者可以把策略改成“玩家在左、当前对话 NPC 在右”“对峙双方分列左右”等。平台只固定两侧槽位、合法引用和格式；不硬编码谁必须在左，不从名字或性别推断位置。

这里的显示是镜头选择，不能反向修改“在场人物”业务状态；世界需要在场状态时仍由既有状态能力维护。


## 6. 模型输出协议与独立解析

### 6.1 标准输出

~~~text
本轮普通叙事正文……

<state_update>
{"path":"inventory.keys","value":1}
</state_update>
<action_suggestions>
["询问宅邸的情况。","跟随爱丽丝进入大厅。"]
</action_suggestions>
<portrait_display>
{"left":{"characterId":"alice","spriteId":"restrained_smile"},"right":null}
</portrait_display>
~~~

状态更新和行动建议继续使用现有格式、启用及省略规则。立绘启用时要求输出一对完整标签，内部是一个 JSON 对象；没有 `sr_extensions` 外层或 Markdown 围栏，不改正文格式。

~~~ts
type PortraitSide = "left" | "right";
type PortraitSelection = {characterId: string; spriteId: string};
type PortraitSnapshot = {
  left: PortraitSelection | null;
  right: PortraitSelection | null;
};
~~~

- left/right 都必填，null 是明确清空。
- 两槽是完整替换，不是增量 patch；省略 right 不表示“右侧不变”。
- 槽对象只接受 characterId/spriteId；不接收 visible、URL、HTML、CSS、坐标、缩放、动画或状态路径。
- 同一 characterId 不能占两侧；没有立绘的角色不能作为图片来源。
- 首版不接受多快照、时间线或轮内逐段指令。
- 角色/素材 ID 区分大小写；保留标签继续沿用现有大小写不敏感匹配。
- 正文需要展示保留标签时使用 HTML 实体；JSON 字符串内的尖括号使用 Unicode 转义，沿用固定协议约束。

### 6.2 解析与回退

| 输入情况 | 结果 | 是否改变画面 |
| --- | --- | --- |
| 完整有效快照 | success | 两侧一起替换 |
| 某侧为 null | success | 清空该侧 |
| left/right 都是 null | success | 明确清空全部 |
| 标签缺失 | no_update | 保留上一有效快照 |
| 空标签、空对象、缺侧、槽对象缺字段或带未知字段 | invalid_display 或 invalid_json | 保留上一有效快照 |
| JSON 无效、重复 JSON 键 | invalid_json | 保留上一有效快照 |
| 自身标签损坏、嵌套、重复整块 | invalid_tag | 整项拒绝 |
| 未知角色、该角色无立绘、左右同一角色 | invalid_display | 整项拒绝 |
| 已知角色的非空 spriteId 不存在 | 规范化为该角色 default，记录回退诊断 | 保存规范化后的成功快照 |
| 处理代码异常 | processing_error | 保留上一有效快照 |

默认图回退是唯一的引用容错：不替换未知角色，不猜相近名字，不把错误 ID 当图片路径。槽对象没有 spriteId 属于结构错误；作者初始画面的引用错误直接在导入时拒绝，不用运行时回退掩盖卡错误。

左右只有两个槽，因此一次校验并原子应用，不实现逐槽 partial_success。若某处触发整项拒绝，另一侧也不改变，避免半更新带来意外同框。默认图回退后的存储只保存实际采用的 ID，原错误 ID 放在运行诊断，不另存一份原始/执行结果。

### 6.3 与现有能力的隔离

- 继续用 `extractCapability` 检查自身标签；重复完整块由立绘处理器明确拒绝，不改变其他能力原有规则。
- `stream-splitter` 加入新标签，包括跨分片和未闭合前缀；增量与最终 snapshot 都分离，结构块不进入用户可见正文。
- 分离器识别保留标签不依赖开关；执行器使用 context 的有效能力与同一份目录校验。
- 立绘、状态、建议分别处理和捕获异常。任何立绘失败不阻止另两项，也不把正常叙事改成失败。
- 停止、模型错误、长度截断、正文无效等继续遵守当前“不执行后处理”的规则，即使截断前刚好出现完整立绘块，也不单独执行。
- 不自动重试、不补发第二次模型调用修复数据块。

## 7. 消息存储与权威当前画面

### 7.1 消息结果

在既有 `extData.output` 加一个可选字段：

~~~ts
type PortraitDisplayOutput =
  | {status: "success"; snapshot: PortraitSnapshot}
  | {
      status:
        | "no_update"
        | "invalid_tag"
        | "invalid_json"
        | "invalid_display"
        | "processing_error";
      errors?: Array<{errorCode: string}>;
    };
~~~

示例为 output 的局部内容：

~~~json
{
  "portraitDisplay": {
    "status": "success",
    "snapshot": {
      "left": {"characterId": "alice", "spriteId": "restrained_smile"},
      "right": null
    }
  }
}
~~~

- 未启用时字段缺省；旧消息也保持缺省，不回填伪造的 success。
- 已启用且正常进入后处理时，缺标签保存 no_update，错误保存对应结果。
- 成功快照与正文、已有能力结果、状态候选、metrics 在同一次助手追加事务内保存。
- 成功快照不另存到 session/global/message state；它属于消息展示输出。
- 不增加 updates/results/applied 等重复数组，不保存图片地址、字节或模型原始尾块。
- 读取保留并校验新字段，旧 state/action 兼容投影不受影响；损坏的旧立绘记录不成为当前画面。
- 普通正文编辑沿用现有 output 保护规则：保留当时的处理记录，不重算立绘，也不允许通用 entry 编辑伪造/删除 output。用户需要重新判断画面时重新生成回复。

### 7.2 当前快照投影

新增共享公开类型：

~~~ts
type CurrentPortraitDisplay = {
  tipEntryId: string | null;
  sourceMessageId: string | null;
  sourceSeq: number | null;
  snapshot: PortraitSnapshot;
};
~~~

没有有效历史结果时，sourceMessageId/sourceSeq 为 null，snapshot 为双 null；tipEntryId 仍是会话实际 tip。显式成功清空则保留非空 sourceMessageId，可以区分“从未提供画面”和“这条消息明确清空”。

从当前会话仍存在、位于实际 tip 范围内的持久消息中，按消息顺序找到最近一个 schema 合法的 `portraitDisplay.status=success`：

1. 找到后立即返回，无论里面是否还有人物。
2. 缺失、no_update、无效结果、部分回复、用户消息和摘要记录不覆盖它。
3. 显式双 null 停止查找，不能继续找更早“有人物”的快照。
4. 历史读取校验结构，不用今天的世界素材重新否定过去已接受的结果；图片资源消失交由展示层降级。
5. 当前序号只用于本会话有序查询；来源身份用真实 messageId，不只用 runId/seq。

实现归属：SessionRepository 在本模块内查询候选，SessionService 提供 `getCurrentPortraitDisplay(sessionId)` 等公开只读能力。不得在 route、context 或 SDK 内写 SQL；也不用新增独立 Repository、状态表或常驻快照缓存。

context 在首次 await 前通过相同 Service 规则捕获 current，之后不随滚动摘要或历史裁剪重新推导。即使成功立绘来自很早的消息，本轮仍能获得正确起始画面。

### 7.3 HTTP 历史响应

扩展现有：

~~~text
GET /api/v1/sessions/:sessionId/narrative/runs
~~~

在现有 items/分页/activeRunId 等字段旁增加 `currentPortraitDisplay`，始终是上述对象：

~~~json
{
  "currentPortraitDisplay": {
    "tipEntryId": "m-assistant-12",
    "sourceMessageId": "m-assistant-12",
    "sourceSeq": 23,
    "snapshot": {
      "left": {"characterId": "alice", "spriteId": "restrained_smile"},
      "right": null
    }
  }
}
~~~

这是本次读取时的会话当前画面，与该页是不是旧历史页无关：

- 首次进入、刷新、重连、明确同步、轮次结束 catch-up 都使用它恢复。
- 即使 afterSeq 没有新增消息，也返回当前投影。
- loadOlder 只追加旧消息，不用返回投影倒退当前界面。
- 不新增立绘查询 HTTP 接口，不要求前端为找一张旧立绘把历史翻到底。
- 官方组件不随用户滚动到旧消息自动重放立绘；首版固定显示当前会话画面。未来历史逐段回看另行设计。

## 8. Server 生命周期与 SSE

### 8.1 一轮正常执行

~~~mermaid
flowchart TD
  A["Context 捕获素材、当前画面、预设"] --> B["主模型输出正文与能力尾块"]
  B --> C["分离公开正文"]
  B --> D["分别处理状态、建议、立绘"]
  D --> E["一次事务保存助手及 output"]
  C --> E
  E --> F["结算后按现有规则释放运行锁"]
  F --> G["现有会话 SSE 发布已提交变化"]
  G --> H["Host 投影后通过 SDK 更新舞台"]
~~~

context 返回有效立绘开关、用于 prompt 的目录和校验所需的捕获目录；execute 不在模型结束后重新读取另一版本的世界卡作为白名单。

正常结算顺序沿用现有流程：助手保存及结束记录处理 → 释放本轮写锁 → 已提交的 state.changed → action_suggestions.created → portrait_display.changed → run.usage → terminal。三项能力之间没有执行成功依赖；其中一条通知失败也不能阻断其他通知和终态。

若助手事务失败，不能发布立绘通知。若助手/output 已成功提交，但后续 run outcome 写入失败，立绘依然是已保存事实，应与 committed state 一样通知；不能因为终态失败就让已保存画面失联。

### 8.2 事件契约

复用现有 session SSE：

~~~text
event: portrait_display.changed
data: {"sessionId":"s-1","tipEntryId":"m-assistant-12","sourceMessageId":"m-assistant-12","sourceSeq":23,"snapshot":{"left":{"characterId":"alice","spriteId":"restrained_smile"},"right":null}}
~~~

data 是 `{sessionId, ...CurrentPortraitDisplay}`，与 HTTP 当前投影同构。sourceMessageId 指向产生当前画面的持久消息；不把未来的预分配助手 ID 当成已保存来源，也不凭 runId 判定重生成身份。

- 每次成功快照提交后发送，包含单侧清空、双侧清空，以及人物相同但来源消息更新的情况。
- no_update、解析失败、未启用不发 changed。
- 普通 run.created 保留上一帧，不先清空。
- 事件是“已提交画面”的通知，无需等 run.completed 才渲染。
- 没有立绘专用 SSE、队列、重放日志或轮询。断线依靠已有 HTTP 同步恢复。

### 8.3 删除、重生成及其他变更

| 操作 | 立绘行为 |
| --- | --- |
| 普通发言开始 | 沿用当前画面，等待新的成功结果 |
| 最新助手重生成 | 删除旧助手提交后立即从剩余历史回退，再等待新生成 |
| 新生成失败/取消 | 保留回退结果，不复活已删除助手的图 |
| 删除当前画面来源消息 | 重算当前投影；可回退到更早成功结果或双 null |
| 删除与当前来源无关的消息 | 校准 tip；画面不变，不要求发重复视觉变化 |
| 编辑正文 | 保留原 output，不把文字编辑当自动重跑立绘 |
| 只切换语言/主题 | 保持素材 ID 与业务画面；只更新系统文案/外观 |
| 世界素材已被替换/移除 | 记录仍保留原 ID，前端按当前资源可用性降级 |

重生成删除通知遵守现有特殊时序：在删除事务提交后发布 message.deleted 和回退后的 portrait_display.changed，但**继续持有该次重生成的运行锁**，不为了发通知先解锁再重新抢锁。普通执行完成才按结算规则释放锁。

当前生产代码中，消息删除仅由最新回复重生成调用。本期在 regenerate 的删除事务提交后，按剩余持久历史重投影并发送立绘变化；不新增普通消息删除 HTTP 接口或用例。当前画面投影保持为公开只读能力，未来增加其他消息删除入口时，由其所属用例复用相同的提交后通知规则。Repository 与 SessionService 不发布 SSE。上表描述删除语义，当前通过重生成触发，不代表已有独立的普通消息删除入口。

回退可能使 sourceSeq 变小或 sourceMessageId 变成 null，客户端必须接受合法回退，不能采用“只接收更大 seq”的过滤。删除回执已到但回退事件未到时，Host 立即令被删来源失效并触发已有同步，不继续展示已删除结果；随后权威投影补齐。


## 9. Host、SDK 与官方组件职责

### 9.1 三层分工

| 层 | 负责 | 不承担 |
| --- | --- | --- |
| Server | 素材与协议校验、消息保存、当前投影、提交后通知 | 屏幕尺寸、图片解码、用户开关 |
| Web Host portraits feature | 消费一次会话 SSE、同步当前投影、来源失效处理、本地显示偏好 | 再解析模型尾块、重复调用模型 |
| iframe Stage SDK / 官方组件 | 不可变镜像、展示命令代理、资源解析、图片与响应式布局 | 扫描历史重建业务画面、直接 HTTP/SSE、读父页面 DOM |

新增 `features/portraits`，由 session workspace 组合生命周期，不把逻辑塞入 StageHost。StageHost 继续只管理 iframe、MessagePort、appearance 和受限命令转发。

静态展示目录由 `loadStageWorld` 投影：角色 id/name、sprites 的 id/asset 即可；默认 UI 不需要角色 prompt/load/世界规则。通过 StageRender/SDK Provider 传入，沿用 assetBaseUrl。

动态快照与本地偏好进入 `StageSnapshot`：

~~~ts
type PortraitDisplayView = {
  current: CurrentPortraitDisplay;
  visibility: {left: boolean; right: boolean};
};
~~~

世界是否具备立绘由静态 manifest 得到；当前是否有人来自 current.snapshot，两个判断不能混为一谈。

### 9.2 恢复与数据竞争

portraits controller 是前端唯一归并点：

1. 首次 history.loadRecent 和普通同步从 currentPortraitDisplay 恢复。
2. 收到合法同会话 changed，完整替换 current；双 null 正常生效。
3. 普通 run.created 不清画面；若包含 deletedMessageIds，先令已删来源失效。
4. 接收 message.deleted、HTTP 重生成受理回执与 authoritative snapshot 时，使用真实消息 ID 协调来源，不仅看 runId。
5. 重连走现有 bounded recent 同步，旧页失效逻辑保持不变。
6. 复用 workspace 已有的 checkpoint/revision 思路：一次 HTTP 同步开始后若又发生立绘事件或来源删除，其旧响应不能覆盖更新后的画面；必要时纳入既有下一轮 synchronize。
7. 上翻历史只加载旧消息，不恢复当前立绘。
8. 切会话/销毁时取消订阅、清理展示对象；旧会话响应不能影响新会话。

SDK 订阅只是把 Host 的镜像提供给组件，不能再次处理同一个事件或追加一份自己的恢复算法。

### 9.3 标准公开接口

建议 SDK 根入口公开：

~~~ts
type ResolvedPortrait = {
  characterId: string;
  spriteId: string;
  characterName: string;
  asset: string;
};

useSRPortraits(): {
  available: boolean;
  left: ResolvedPortrait | null;
  right: ResolvedPortrait | null;
  visibility: {left: boolean; right: boolean};
  setVisibility(side: "left" | "right", visible: boolean): Promise<void>;
};

SR.Portrait // props: side: "left" | "right"，可选 className
SR.WorldStage // 官方完整组合，支持已有 WorldStory 的 showState 选项
useSRPortraitComposerButtons(options: {
  mode: "wide" | "narrow";
  previewSide: "left" | "right" | null;
  onPreviewSideChange(side: "left" | "right" | null): void;
}): SRComposerButton[]; // 只返回 descriptors，不自己注册按钮
~~~

这些是目标接口说明，尚未存在于当前包。图片 URL 仍通过 `useSRAssetUrl` 得到；不把 raw 模型输出作为 src。

WorldStage 或自定义舞台容器拥有响应式 mode、临时 previewSide 和回调，显式传给按钮 Hook；窄屏预览状态不进入 Host 业务镜像。`SR.Portrait` 只渲染指定槽，是否挂载由容器按宽屏 visibility 或窄屏 previewSide 决定，组件内部不再次应用宽屏 visibility，避免桌面隐藏偏好挡住主动的移动预览。

`setVisibility` 通过受限的 `portraitDisplay.setVisibility({side, visible})` 命令交给 Host feature，命令确认后 resolve，更新后的偏好通过 StageSnapshot 投影返回。该命令只改阅读设置，无网络/数据库/世界状态写入，也不受运行中会话写锁限制。介绍/开局作者预览不因此获得会话命令权限。

### 9.4 官方默认组合

概念结构：

~~~tsx
function WorldStageLayout({mode}: {mode: "wide" | "narrow"}) {
  // 外层 WorldStage 测量自身容器并传入 mode。
  const {visibility} = useSRPortraits();
  const [previewSide, setPreviewSide] =
    React.useState<"left" | "right" | null>(null);
  const portraitButtons = useSRPortraitComposerButtons({
    mode, previewSide, onPreviewSideChange: setPreviewSide,
  });
  useSRComposerButtons(portraitButtons);

  return (
    <div className="sr-world-stage">
      {mode === "wide" && visibility.left && <SR.Portrait side="left" />}
      <div className="sr-world-stage__story"><SR.WorldStory /></div>
      {mode === "wide" && visibility.right && <SR.Portrait side="right" />}
      {mode === "narrow" && previewSide && (
        <div className="sr-portrait-preview">
          <SR.Portrait side={previewSide} />
          <button onClick={() => setPreviewSide(null)}>关闭</button>
        </div>
      )}
    </div>
  );
}
~~~

示例省略外点/Escape、模式切换清理和实际布局样式，生产关闭按钮使用 i18n。CSS 为中央与左右槽显式分配网格位置，条件卸载一侧不能让正文自动换列。

`frame.tsx` 无自定义 stage_component 时回退到 `SR.WorldStage`。世界没有立绘目录时，组件按原 WorldStory 路径展示，不保留左右空列，也不显示无用胶囊。

显式设置自定义舞台的卡不会被平台强行插入立绘。创作者可以直接用 WorldStage，或者自行组合 Portrait/WorldStory 和按钮。WorldStory 本身仍是正文组件，作者现有调用不突然多出两个侧栏。

## 10. 两个官方胶囊与响应式交互

### 10.1 胶囊声明

必须由官方 WorldStage 统一调用一次 `useSRComposerButtons`：

- 左右 Portrait 只展示图片，不能各自注册胶囊。
- `useSRPortraitComposerButtons` 只生成两项 descriptors。
- 自定义舞台可把这两项和自己的按钮合并，然后统一调用一次 hook，仍遵守最多五项；不由 SDK 自动抢占或静默挤掉作者按钮。
- 胶囊放在已有宿主输入框动作区，复用紧凑尺寸、主题 token 和点击 revision；不新增移动底部导航。
- 按钮 ID 使用稳定的官方前缀，例如 `sr.portrait.left`、`sr.portrait.right`。
- 有素材目录时保留两项；当前某侧无人则该侧显示“左侧无人/右侧无人”并禁用，不弹空预览。
- 宽屏标签明确“显示左立绘/隐藏左立绘”，右侧对称；可以补充角色名，但长名字必须截断。
- 为按钮公开视图增加可选 `pressed?: boolean`，通过现有白名单验证并映射 aria-pressed；不扩展任意 HTML/class/style。

自定义组合示意：

~~~tsx
// mode 来自自定义舞台实际容器测量，previewSide 由该容器持有。
const portraitButtons = useSRPortraitComposerButtons({
  mode, previewSide, onPreviewSideChange: setPreviewSide,
});

useSRComposerButtons([
  ...portraitButtons,
  {id: "inventory", label: "背包", onClick: openInventory},
]);
~~~

示例中的作者自定义回调需遵循现有 ComposerButton 类型；同一舞台不能再嵌套一个自行注册胶囊的 WorldStage。采用完整 WorldStage 或自行组合二选一。

### 10.2 本地可见性

Host 按 sessionId 保存 `{left:true,right:true}`，初始两侧开启。使用本地阅读偏好存储，失败时退化为内存值：

- 左右独立。
- 关闭不修改服务端当前快照、消息 output、素材目录、预设或世界状态。
- 隐藏期间继续接收后端数据，重新开启显示当前最新结果。
- iframe 重挂和页面刷新可以恢复偏好。
- 本地值无需服务器感知，也不增加 AppSettings 或会话数据库字段。
- 关闭预设生成与隐藏画面是不同操作，界面说明必须明确。

### 10.3 宽屏：正文两侧的固定展示区

按 iframe 内实际可用容器宽度测量，用 ResizeObserver 或容器查询；不能用宿主浏览器总宽度决定。

初始设计参数：

| 元素 | 建议 |
| --- | --- |
| 三列模式 | 容器约 1200px 起启用，同时确保中央实际宽度至少 640px |
| 中央 WorldStory 容器 | 上限约 788px，对应现有正文 max-width 740px 加水平 padding |
| 单侧立绘 | 约 160–240px，可随剩余宽度缩放 |
| 对齐 | 图片完整显示、底部对齐；不按头像裁切 |
| 图片容器 | 透明底、弱装饰，不增加厚卡片边框 |
| 底部空间 | 复用现有输入区 inset，胶囊/输入栏不能盖住有效图片区域 |

三列为：左立绘 — WorldStory — 右立绘。左右图片不属于消息列表，不随每条消息重复创建；隐藏一侧或切换表情时中央阅读列保持稳定。

中央 WorldStory 宽度控制在现有状态栏展开阈值以下，让世界状态沿用已有浮层，避免“左立绘＋正文＋288px 状态栏＋右立绘”挤在一起。无立绘世界保持原状态栏行为。

最终断点以正文不被压窄、图片不与正文/输入框重叠为验收依据。模型只选择 left/right，不参与像素计算。用户收起平台侧栏后空间增加，可以自动进入三列；展开后空间不足自动退到窄屏模式。

### 10.4 窄屏：胶囊按需查看

默认不常驻大立绘，正文占用可用宽度；保留两个胶囊，文案改为“查看左立绘/查看右立绘”。

首版使用一个共用的轻量非模态预览层：

- 点击某侧打开当前侧，再点同侧收起，点另一侧切换；最多显示一张。
- 预览有明确关闭按钮；iframe 内点击预览外关闭，iframe 收到 Escape 时关闭。建议宽 140–180px、高不超过可视舞台的 40%，底部避开现有输入区 inset；图片完整显示，不改变消息列表高度或滚动锚点。
- 从宿主胶囊点击打开时不强行抢焦点，不用 showModal 让整个 frame 进入模态，也不自动锁住输入。
- 预览内控件可正常键盘到达；若关闭时焦点在预览内部，恢复到 frame 内稳定可聚焦容器，不能直接访问父 DOM 恢复宿主按钮焦点。
- 宽屏常驻可见性继续保存在 Host；窄屏 previewSide 是临时展示状态，不持久化。
- 桌面开启的偏好不导致手机首次进入自动弹图；窄屏查看也不隐式改桌面显示偏好。
- SSE 不主动打开预览、不抢焦点；已打开的侧跟随最新素材，变成 null 时收起。
- 切换到宽屏或离开会话时关闭临时预览。

宽屏按钮是“常驻显示开关”，窄屏按钮是“打开/收起预览”；两种模式各用清楚文案与正确 pressed 值，不显示与实际画面不一致的开关状态。Host 胶囊不设置指向 iframe DOM 的 aria-controls；焦点在 Host 时不能保证 Escape 传入 iframe，可再点胶囊关闭。预览是手动打开、局部覆盖、可随时收起的图片层，不承诺完全不遮住正文。若以后要把焦点精确送回宿主胶囊，应通过受限 Host 桥扩展，不使用父 DOM 特权；本期无需新增跨域焦点协议。

### 10.5 图片切换和异常

- 只请求当前显示/预览的素材与必要默认回退图，不全量预下载角色所有表情。
- 同角色换表情时等待新图解码再替换，可做短淡入淡出；显式 null 立即撤下，不等待图片任务。
- 切换角色时不能显示“新角色名字＋旧角色图片”；旧请求完成不得覆盖新角色。
- 图片加载以当前选择/请求代次守护，已取消或过期结果忽略。
- 选中图加载失败，尝试同角色 default；default 也失败则显示轻量角色名/缺图提示，不无限循环。
- 资源缺失不修改消息和服务端快照，不调用模型补图；重新访问或重新选择时可重试。
- 复用主题字体/颜色/间距/焦点 token，尊重 prefers-reduced-motion，提供有意义的 alt，不让每次表情变化都打断读屏。

系统文案同步中、英、日，包括节点名称、开关、查看/收起、无人、资源不可用等。角色名、素材 ID、作者说明保持作者原文。


## 11. 创作者工作流

保持现有“编辑世界卡与资源 → 检查 → 打包 → 导入”的流程，本期不增建在线立绘编辑器。

1. 在对应角色下添加 sprites，准备 default 及需要的表情/姿态图片。
2. 用简短 description 说明适合/不适合的情境，稳定保留角色 ID 和素材 ID。
3. 可为每个 opening 配 initial_portraits；不同开局可以有不同人物或全部为空。
4. 使用默认舞台时无需写 React：卡有立绘便可自动接入。
5. 自定义舞台从 SDK 组合 Portrait/WorldStory，或者使用完整 WorldStage；按钮统一声明一次。
6. 在预设“立绘显示”节点修改人物优先级和左右分配策略，格式继续由平台固定协议负责。
7. 复用仓库已有 `world:check`、`world:pack` 命令；素材校验通过不等于已在真实模型下跑通。
8. 在现有示例体系增加一个小型示例：两位角色、各 default 和一种表情、一个带初始画面的开局；实际导入与试玩结果单独记录。

正式实现时更新世界卡规范、创作者内容/打包指南、SDK 组件/会话文档和运行说明；本次只写 plan，不提前把未实现能力写进正式文档。仓库 author skill 引用统一规范即可，需要更新指引时再按对应 skill 维护流程执行，避免复制第二套字段定义。

## 13. 实施顺序与验收

### 13.1 阶段 A：Server 标准能力

1. **A1 契约与世界卡**：定义纯双槽类型、素材与开局校验，补资源扫描、导入导出往返。
2. **A2 预设与 context**：增加节点/默认投影/变量，使用同一捕获目录和 current；同步配置编辑器。
3. **A3 后处理与消息**：扩流式分离、独立解析、output schema、同事务保存和开局初始化。
4. **A4 查询与通知**：补 currentPortraitDisplay、SSE、删除/重生成回退，验证完整生命周期。

A 阶段通过标准 HTTP/SSE 和消息读取即可验证，暂时没有 UI 也不阻塞协议验收。

### 13.2 阶段 B：标准 SDK 与官方舞台

1. **B1 Host 数据接线**：增加 portraits feature、history 响应投影、统一事件与 checkpoint；接入最小素材 manifest。
2. **B2 SDK/组件**：Hook、偏好命令、Portrait、WorldStage；single-owner 胶囊与 pressed。
3. **B3 产品验收**：默认舞台接入、宽窄屏、状态面板避让、图片失败、主题与三语、示例/文档。

### 13.3 必须覆盖的行为

| 场景 | 预期 |
| --- | --- |
| 无素材的旧卡 | 原正文体验与原状态布局，不出现无用胶囊，不新增立绘 prompt |
| 有素材、旧预设没有节点 | 自动补默认并可生成，数据库 revision 不被读取改变 |
| 新节点显式关闭 | 停止该能力；旧 state/action 开关语义不变 |
| 角色本轮 load 未触发 | 素材目录仍可选；不能据此认定在场或清空 |
| 缩窗/滚动摘要 | 当前画面和素材捕获不随保留历史页漂移，实际预算包含新增内容 |
| 正常显示、换表情、换角色 | 双槽完整替换；不会看到错误人名/图片组合 |
| 单侧/双侧 null | 真正清空，保存 success，空画面也有通知 |
| 缺块、坏 JSON、错结构、错角色、重复块/角色 | 旧画面保留，另外两能力仍执行 |
| 未知 spriteId | 同角色 default 回退，存实际采用值并记录诊断 |
| 流式任意标签分片、最终 snapshot 修正 | 结构块不泄漏到正文，不提前宣称结果已保存 |
| 模型停止/错误/长度截断 | 仅保存公开部分，不执行立绘后处理 |
| 助手提交失败 | 不发布立绘变化 |
| 助手提交成功但 outcome 写失败 | 已提交画面仍可读取并通知 |
| 最近五轮均无成功立绘 | 当前投影仍能找到更早结果 |
| 最近一次成功结果是双 null | 不会复活更早角色 |
| 重生成先删除旧回复 | 立即回退；生成失败不恢复被删图；可接受更小 sourceSeq |
| SSE 丢失/重连、旧 HTTP 响应晚到 | HTTP 可恢复，旧同步不会覆盖后来的事件 |
| 上翻旧历史 | 当前画面不变化 |
| 左侧隐藏后继续生成再打开 | 右侧不受影响，左侧显示最新图而非旧缓存 |
| 自定义舞台已有按钮 | 作者明确合并；不产生第二 owner，不超五项 |
| 宽度不足/平台侧栏展开 | 中央正文可读，自动退到胶囊预览，不挤四列 |
| 图下载/解码竞态、资源404 | 旧请求不能覆盖新图；默认回退有限且不改业务快照 |
| zh-CN/en/ja、亮暗主题、减弱动效 | 系统控件完整，作者素材原文保留 |

## 14. 最终设计边界

- 人物与素材是世界卡作者数据；模型选择画面；用户决定是否看见；三者不互相回写。
- 立绘是持久消息的展示输出，不是通用业务状态，不反向证明人物在场。
- 服务端提供可独立消费的标准能力，官方舞台是它的一个 SDK 消费者。
- 完整双槽快照解决当前两侧展示，不引入命令重放、播放时间轴或通用演出引擎。
- 首版的自然限制是更新发生在本轮结束；逐句表情同步继续由独立视觉小说计划处理。
- 本方案按以上明确默认可以拆阶段实施，没有必须先另选数据库结构、runner 或传输方案的前置项。
