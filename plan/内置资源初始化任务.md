# 内置资源初始化任务

配套文档为 [内置资源初始化方案](./内置资源初始化方案.md)。以下是实施任务。

| 顺序 | 任务 | 验收条件 |
| --- | --- | --- |
| 1 | 建立 `initial-data/`，登记固定 ID，用既有预设导出器生成「标准叙事」便携 JSON，复制现有「小饭馆」原包。 | 用解析后的对象比对迁移前后模板，包括后处理提示词、模型参数及节点顺序。两个 ZIP 的 SHA-256 相同，三个发行文件均可由 Git 跟踪。 |
| 2 | 实现基于模块位置的清单读取器，解析资源相对路径并允许测试注入目录。 | 覆盖合法多项清单、重复 ID、无效默认引用、缺文件、越界路径、无效预设文档。更改工作目录或运行数据目录仍能找到同一套发行文件。 |
| 3 | 将预设补齐与默认模板读取切换到文件来源，保留单一同步事务补齐预设与设置。 | 固定 ID 的已编辑预设、revision、更新时间和自选默认值均保留。缺失可补建，名称冲突按既有规则处理。默认模板读取返回独立副本；任一预设或设置写入失败能回滚。 |
| 4 | 复用世界卡导入编排，为内置调用传入稳定 ID，手动上传沿用随机 ID。 | 使用真实「小饭馆」ZIP 在临时目录完成函数级导入，核对原件字节、世界名、初始状态、标签、封面与组件。手动导入同名卡得到独立世界；模拟写入失败只清理本次产物，遇到已有目录报告冲突并保留目录。 |
| 5 | 串联异步初始化与 Server 启动，补齐世界，输出可定位的启动错误。 | 空库得到 1 个预设、1 条设置、1 个世界、0 个会话和模型。模拟重启后世界 ID、状态及资产保持原样，已装 ZIP 不再读取解包。旧库保留同名手动世界与关联会话；添加第二项只补新项，删除内置世界后仅补建世界。第二个世界失败后，修复重试不重复安装第一个。通过函数级编排验证初始化失败在监听前返回。 |
| 6 | 更新项目及 Server 契约、运行文档和 README，完成回归验证。 | 文档说明新增资源步骤、固定 ID、删除重建及目录冲突处理。运行涉及目录、初始化、世界、预设的函数测试与现有架构测试，执行 `pnpm typecheck` 和 `pnpm lint`。测试使用临时数据库和目录，无需启动实际服务。 |

任务 2、3 依赖第一批资源，任务 4 可在资源就绪后独立实施。任务 5 汇合预设与世界两条流程，最后统一回归。
