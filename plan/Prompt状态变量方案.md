# 叙事 Prompt 状态变量方案 V2（待实施）

## 目标：世界卡是原文，模型看到的是本轮结果

世界卡导入和保存不解析 Prompt，不检查变量名、路径或字段是否存在；卡格式和状态定义本身仍按既有规则校验。构建模型上下文时，只在明确的模板入口解释原始文本，不修改卡文件、状态或历史。不支持的自定义变量不是错误，也不消费它的花括号。

假设已加载的状态是：global.城市 = 临安，session.人设.姓名 = 沈青，message.银两 = 0，没有门派。世界卡角色 Prompt 的效果如下：

| 作者原文 | 本轮发给模型 |
|---|---|
| `{{user}}在{{state.global.城市}}见到了{{state.session.人设.姓名}}。`（玩家名：小满） | `小满在临安见到了沈青。` |
| `银两：{{state.message.银两}}；门派：{{state.session.人设.门派}}。` | `银两：0；门派：。`（只移除占位，不删除标点或整行） |
| `别称：{{state.session.人设..别称}}；天气：{{ weather.today }}` | `别称：；天气：{{ weather.today }}`（未知引用连同空格原样保留） |
| `代号：{{state.session.人设.代号}}`，字段值为字符串 `{{user}}` | `代号：{{user}}`，不是“小满”；即便外层预设用 `{{persona.prompt}}` 注入，也不再展开。 |

下一轮银两变为 12，同一卡得到“银两：12”；这一轮与已保存历史不被重写。

## 两种入口，共用语法，不共用宽严策略

| 入口 | 首期处理的内容 | 不接管的行为 |
|---|---|---|
| 世界卡作者素材 | 已选中的玩家/角色 `characters[].prompt`、已激活世界书 `lorebook.entries[].content`：保留原有精确 `{{user}}`；新增闭合的 `{{state.<scope>.<path>}}`。 | 未知占位原样传给模型。预设专用的 `{{history.messages}}`、`{{state.session}}` 在这里仍是原文，不注入历史或整个状态域。 |
| 预设普通、自定义与 postprocess 节点 | 保留固定系统变量，增加三域路径取值；合法路径在本轮未命中也填空。 | 预设是受校验的结构化配置，保留既有未知变量报错、必需变量位置/数量、能力提示限制与默认回退。**不把预设校验器接到世界卡导入。** |
| 其他文本 | 不新增插值：开局、状态描述/规则维持原有 `{{user}}` 行为；摘要提示、历史、当轮输入、模型输出、状态值、HTML/脚本与展示字段不进入新扫描器。 | 不整体遍历世界卡，不对最终消息执行 replaceAll。 |

### 作者素材里的识别边界

- 保留 `state.` 为 SR 状态命名空间。三个整域名是预设专用的精确例外；其余闭合的 `state.` 引用由状态解析器认领。非法 scope（如 `state.player.姓名`）、空段、危险键、超深或不支持的方括号路径均只将该引用置空。非 SR 名称如 `stateful.name` 和 `weather.today` 不是状态变量，逐字保留。
- 状态路径沿用状态模块的点路径分段、深度和安全键校验，中文键合法。只读对象自有属性，不沿原型链、不执行表达式、不下钻数组。字符串直接插入；数值、布尔、显式 null、对象和整数组用紧凑 JSON。空字符串、0、false 都是有效命中；根未声明/未激活、子键不存在或中间不是对象则为空。
- 建议将**未配对的花括号视为普通正文**：没有完整占位就不猜测作者想删到哪里；再次遇到开符时从新开符识别，使坏片段不吞掉后面的合法变量。世界卡不套用预设的反斜杠解码，不改写普通文本与未知自定义语法；预设保持现有转义及精确 `state.entries` 迁移，不把它当作动态路径别名。

## 架构与执行顺序

**拆一个 Server 内纯函数模块，不建变量服务。** 目前预设 schema 和 context 模板编译各扫一次固定名，素材阶段还独立替换玩家名。共享“识别一段原文是什么”，但“哪些引用可用”和“去哪里取值”分别归入口策略和上下文所有。不加 HTTP、表、插件注册、全局缓存或任意对象路径访问。

1. **识别原始模板。** 扫描器接收原文和入口模式，保留原始片段边界，区分文本、固定名、已认领状态路径、已认领但非法、未认领。预设模式把非法/未知映射为现有模板错误；作者模式分别映射为空/原始切片。玩家名与状态变量在同一次作者字段扫描中处理，追加结果后只前进原文游标，无循环替换。
2. **先选根，再渲染。** 复用 captureContext 捕获的实际 tip 三域有效视图。materials 阶段用当前候选的关键词和 when 按既有规则选素材与各域已声明的可见根，每域只选择一次。将同一份根列表用于整域材料、细粒度读取，以及现有 message 可写根的派生。显式点名不能绕过 load，也不能扩张写权限；插出的文字不反馈到关键词选择。
3. **共享只读取值。** 输入仅为已识别的 scope、路径、捕获视图和当前候选可见根。先判可见再按路径读值，不查库、不补默认、不触发写入。作者字段展开后继续走现有 prose 转义；状态描述/规则不误用作者 Prompt 渲染器。缺值只影响当前占位，不中止生成或触发整个能力提示回退。
4. **按入口组装。** 每个选中的作者字段渲染后成为普通文本。预设编译器只扫描预设自己的源字符串，遇到角色/世界书固定变量直接追加已渲染素材；遇到状态路径复用同一个只读函数。历史仍按原生消息展开，而非转换为字符串。每个裁剪候选重算可见根和最终消息，用展开后的内容估算预算；不跨候选缓存渲染结果。首期不增加逐值日志或公共诊断协议。
5. **扩展新变量族。** 将来若支持 weather 等族，显式新增识别分支、入口许可、只读数据输入与测试。在支持之前原样透传；新增时应说明旧卡里同名标记会开始被解释。出现实际跨端校验需求再考虑共享包，不提前把 Server 运行时绑定到 SDK。
