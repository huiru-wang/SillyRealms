# 故事舞台与新版 `SR.WorldStory` 设计方向

> 状态：待实施、待视觉验收。日期：2026-11-13。

本节保存已讨论的设计方向，供后续正式设计和实施时使用；尚未完成界面验收，也不代表 Studio 已接入 SDK 或真实会话。

### 术语与范围

- **会话页**是平台提供的完整界面，包含全局导航、会话标题、上下文用量、连接状态、会话设置、故事舞台和输入区。
- **故事舞台（Story Stage）**是会话中由世界卡决定内容呈现的区域。它既可以是阅读界面，也可以包含角色、场景、状态和创作者定义的交互。
- **`SR.WorldStory`** 是 SDK 提供的官方默认故事展示组件，可作为默认舞台，也可被作者组合进自定义舞台；故事舞台本身不是 `SR.WorldStory` 的同义词。
- 消息展示规则只改变显示，不改写原始消息；故事舞台不取代平台拥有的输入、草稿、会话标题、用量和连接提示。

### 默认视觉与阅读体验

- 以当前 Studio 会话样板的阅读氛围为起点，AI 与玩家消息均不使用消息气泡；使用正文、来源标签和留白建立清晰层级。
- 消息内容沿稳定阅读轴排列；桌面默认正文最大宽度建议约 720–760px，字号默认 16px、行高约 1.8–1.9，最终以真实内容和多视口验收为准。
- 角色来源、玩家来源、链接、代码、列表、图片和表格可辨识；长文本、表格和图片不得撑破内容区。颜色、字体、间距和焦点采用经验证的语义规范，不直接引入旧 Web 页面样式。
- 玩家与 AI 消息保持可区分，不依赖颜色或左右气泡。AI 叙事按现有展示投影的相邻消息合并规则呈现，展示合并不改写原始记录。
- 自定义舞台有自己的布局与样式，平台视觉不强制覆盖创作者内容。

### 交互与状态

- 初次加载后定位最新内容；用户停留底部时跟随新增消息，用户向上阅读后不强制跳转，提供“回到最新”。加载更早内容、字号和布局变化时保持阅读锚点。
- 明确加载、空内容、生成中、失败、停止及连接中断状态；已可见正文按权威结果保留，不承诺断线增量重放或未确认状态已提交。
- 保留现有 `showState` 契约及默认行为；桌面状态区域不应使正文过窄，手机状态面板可覆盖舞台，并支持关闭、焦点管理和返回原焦点。
- 保持 Markdown/HTML 解析净化、世界卡展示规则、组件插槽和失败时原文降级。世界详情的开局为静态文档预览，正式会话中的开局是 AI 消息，仍经正常消息渲染处理。
- 适配 1536、1280、768、390、375px，覆盖深浅主题、键盘、长消息、图片表格和减少动态效果；操作和状态不能仅靠颜色传达。

### SDK 接入与后续验收

- 方向是经过规范设计后，让 Studio 使用 SDK 中真正的官方 `SR.WorldStory`，而不是将静态样板重命名为官方组件。现有 Studio 静态阶段的“暂不接 SDK”规则需在正式接入时依据已批准范围更新；本记录不修改现有规则。
- 组件的预览可使用本地样板，不要求真实模型或真实会话；正式接入继续遵守 Host、隔离 iframe 和公开 SDK 契约。预览适配应清楚限定用途，不自动成为创作者公开 API。
- 变更前核查现有组件消费者、`showState`、样式作用域和兼容性。保证默认组件与作者组合组件使用一致契约，不降低安全边界。
- 用户当前优先考虑先完成世界详情设计，再准备接入真实世界卡；是否先制作完整 SDK 模拟预览需结合投入重新决定。世界详情与 SDK 的接入顺序尚未作为实施计划批准。
- 验收应包含官方组件和创作者组合两种场景、长历史与滚动锚点、富文本和降级、响应式、焦点、深浅主题和减少动态效果。具体实施方案、兼容策略及其测试结果另行制定。
