# 故事舞台与新版 SR.WorldStory：阅读界面设计

> 状态：设计目标保留；2026-11-14 已按用户后续明确授权实施 SDK 阅读表面、Host 输入精简和 Studio 隔离本地预览。本期必要工程验证与文档收尾完成，开发/生产会话、最终构建及世界/导航/预设回归通过；提交推送待执行，用户视觉验收仍未完成，不代表 Studio 已接入真实 Server 会话。评估时事实与当前结果见第 10 节。

## 1. 目标和范围

用户进入会话后，看到连续、安静的故事阅读界面；自己的每次输入和 AI 的每次回应仍可辨认、可定位。没有消息气泡、正文外框或左右聊天对齐；以留白、来源标签和排版表达消息边界。视觉起点是评估时 Studio 会话样板的阅读轴、字色和节奏；当时玩家消息仍是气泡，新版明确移除它，不把样板所有细节照搬。

原稿的设计范围为：官方 `SR.WorldStory` 默认展示、会话页 Host 输入框的视觉与交互，以及 Studio 接入后两者的视觉衔接。历史分页、实时消息、恢复、消息规则和组件、会话状态、发送/停止等既有能力按当前实现保留，不设计新功能、不改动数据协议和运行逻辑。暂时移除输入区中“话语”“系统指令/叙事指令”快捷按钮；这是入口展示调整，不删除语法、历史内容或已有消息渲染行为，也不推断禁止手工输入。执行时已核对现有编辑器键盘、粘贴和序列化行为；不以静默改写用户输入代替取消按钮。

## 2. 术语与边界

- **会话页**：平台外壳，负责标题、返回、上下文用量、连接状态、设置及 Host 输入框。移动端会话详情不显示全局底部导航。
- **故事舞台（Story Stage）**：世界卡决定内容与布局的区域，可能是官方默认界面或作者自定义 UI。
- **`SR.WorldStory`**：官方默认故事组件，也可由作者在自定义舞台内组合。它与自定义舞台使用同一公开 SDK 契约；不是会话页或整个舞台的同义词。
- **消息边界**：保持当前消息身份、顺序及可访问的来源标识；沿用已有相邻 assistant 消息的展示合并规则，不要求将原始消息一一渲染成视觉块，也不把所有历史拼为一个无身份长字符串。展示不改写原始消息或状态。

当前 SDK 的 `StoryRun`、`MessageContent`、Run 反馈与建议、状态面板、Host 输入属于已有能力；本方案对它们的布局提出目标，不将重写 reducer、流式协议或状态处理列为设计目标。评估时 Studio 会话样板为静态示例；现已改用真实 SDK 的隔离本地预览，真实 Server 会话接入仍须后续单独验收。

## 3. 页面构图

```text
桌面：会话页
┌─────────────────────────────────────────────────────┐
│ 会话标题                         上下文 / 连接 / 设置 │
├─────────────────────────────────────────────────────┤
│                 故事阅读列                           │
│       来源标识                                       │
│       AI 叙事正文，可包含段落、图片和组件              │
│                                                     │
│       我                                             │
│       用户输入，以正文形式呈现                        │
│                                                     │
│       来源标识                                       │
│       后续 AI 叙事                                   │
│                                     会话状态入口      │
├─────────────────────────────────────────────────────┤
│       输入内容                         收起 / 发送    │
└─────────────────────────────────────────────────────┘
```

手机同样采用单列，顶部仅保留返回、标题和必要状态/操作；舞台占据输入框以上的剩余高度，不出现全局底部导航。输入区收起后将空间还给舞台，并保留清楚可见、可触达的展开入口。页面的滚动容器与 iframe 的边界仍按现有 Host/SDK 设计；不以视觉稿暗示可跨 iframe 直接操作 DOM。

阅读列桌面最大宽建议 720–760 CSS px，居中；中等宽度随容器收缩；手机正文左右约 16–20px。数值为视觉起点，最终以真实中英文、消息组件和 375/390/768/1280/1536px 的截图为准。不要把作者自定义舞台压入此宽度或替它加底色。

## 4. 阅读排版与视觉

- 深浅主题沿用 Studio 既有语义色、文本层级、间距和焦点样式。会话 iframe 中的官方组件使用经明确映射的阅读变量；平台样式不能全局注入或强制覆盖作者自定义舞台。无论主题，正文、次级信息、状态和焦点都须满足对比度及可辨识要求。
- 正文以常规字重、清晰段距呈现；初始目标约 16px、行高 1.8–1.9，手机可根据可读性微调。沿用现有阅读字号设置及其作用范围，不额外发明存储策略。长单词和 URL 换行；代码与表格可局部横向滚动；图片限制容器宽度、保持比例，并在加载和失败时保留合理阅读位置。
- 消息都沿同一左侧阅读轴。来源标识小于正文，使用文字而不是仅靠颜色：用户为“我”，AI 使用现有可获得的来源信息；如果没有可靠角色名称，使用中性的“故事”，不根据正文猜测角色身份。头像可缺省，不制造虚假角色头像。
- 同一 AI 消息中段落间距小于消息之间的间距；用户与 AI 块间留出明确节奏。用户正文也无气泡、无底色、无边框；保持换行和文本可选择，不用特殊边框把它变成卡片。触控、键盘和辅助技术均能识别来源及消息顺序。
- 空故事、正在加载、加载失败、重新加载更早内容、准备/生成/扩展处理、停止、失败及连接问题沿用实际状态；反馈紧邻相关区域，错误含现有重试入口。未保存的流式内容仍是暂态，终态以权威结果为准；不要虚构持久化、断线重放或保证。
- 行动建议沿用既有可用性与填充草稿/撤销语义：采用轻量文字和次级按钮，禁用历史建议；不因去除“话语/系统指令”快捷按钮而删除行动建议。

## 5. 文本渲染保持不变

官方组件继续调用现有 `MessageContent` 渲染 AI 与用户消息：保留现有角色扮演文本处理、用户指令段的处理、Markdown 与 HTML 混排、净化、安全链接、世界卡消息展示规则、作者消息组件和 React Portal 插槽；不把消息直接改成纯文本、静态 iframe 或 `dangerouslySetInnerHTML` 快捷实现。用户消息和 AI 消息既有处理细节不同，以当前代码和测试为准，不将它们误说成完全同一种解析流程。

作者内容内的结构、链接、代码、样式和交互按现有安全约束呈现，平台只定义外层阅读节奏；不通过 CSS 全局覆盖作者组件。规则超时、组件缺失或局部异常时维持当前原文回退及提示。自定义页面失败继续按既有错误规则处理，不擅自换成默认舞台。`showState` 的现有默认值与功能保持；桌面、移动端面板布局和焦点沿现有语义实现。

## 6. 简洁输入区

输入区属于 Host，不放进 `SR.WorldStory`。在现有平台输入容器中收敛视觉：一块低对比表面、清晰聚焦边界，主要呈现输入内容与发送/停止操作；取消“话语”“系统指令/叙事指令”快捷栏。文本允许自然换行和增长，到达上限后输入区域内部滚动。按钮、占位提示和无障碍名称清晰，不用占位文字代替可访问标签。

保留当前已实现的发送、换行、草稿、停止、收起/展开、键盘、建议填入与撤销规则。评估时引用的 Web 文档“Enter 发送”已过时；源码和回归确认普通段落 Enter/Shift+Enter 换行、Cmd/Ctrl+Enter 发送，既有类型块内 Enter 退出到旁白。Studio 现复用同一 Host 编辑器，不静默改写两条文本路径：普通输入仍按原规则转义，初值、外部 value 和 SDK setDraft 仍解析既有格式草稿。移动端软键盘、输入法组合、浏览器视口变化和安全区域必须验证；不可让输入框遮住当前光标、状态或“回到最新”。

## 7. 滚动、状态与无障碍

- 沿用现有历史分页、位置锚定、用户上翻停止跟随、回到最新及图片/组件高度变化处理；视觉变更不得重新挂载历史消息或 Portal 插槽。没有虚拟列表或可重放 SSE 的既有保证。
- 桌面状态面板展开不挤压阅读列至不可读；移动端面板临时覆盖并可关闭，焦点管理和退出后恢复焦点沿现有契约。`showState=false` 不显示官方状态入口或面板。
- 来源、错误、状态、操作的含义不能只靠颜色。阅读区可用键盘，交互控件有名称和可见焦点，移动触控目标建议至少 44px；尊重减少动态效果。滚动到新消息不能夺取焦点或让屏幕阅读器重复朗读整段历史。
- 等待和断线文案不提供超出现有接口的“已同步”承诺；空态、错误和重试均保持可读，刷新失败不能伪造空故事。

## 8. 接入与验证范围

本期已在隔离测试环境中以固定合成数据和现有 SDK/Host 契约展示默认及作者组合两种场景；无需真实 Provider、真实用户会话或付费调用。接入 Studio 不得绕过 Host、MessageChannel、iframe sandbox、CSP 和公共 SDK；不得通过复制私有渲染器或改变作者 iframe 的主题全局样式完成视觉统一。设计稿不预先确定新的公共 API 或需要变更的数据库。

视觉验收：1536、1280、768、390、375px，深浅主题；短/长中英文、长用户消息、混排、代码、表格、图片、组件、出错回退、状态面板和虚拟键盘。实际截图审查阅读列、角色识别、段距、遮挡及最后一行可见性，并以项目既有 Studio 样板对照。设计类 skill 的营销页面 gate 不代表此应用界面的验收结果。

交互回归：历史分页与锚点、滚动跟随与回到最新、流式阶段和终态、图片异步布局、规则及组件插槽稳定、失败和重试、状态面板、建议与草稿、输入法/快捷键、切换会话与取消、窄屏横向溢出、触控与键盘焦点、减少动态效果。运行 Studio 构建和对应 SDK/Host 浏览器测试；截图或测试未运行时明确报告，不能宣称视觉通过。

## 9. 实施顺序（已获后续授权）

1. 确认消息来源标签、文本尺度和输入快捷键基线，建立固定合成样本与现有行为基线。
2. 分别确定 Host 会话页与 SDK 默认故事的视觉边界，明确 iframe 内主题变量和作者组合兼容方式。
3. 只调整官方消息外层排版与状态面板外观，保留 `MessageContent`、消息身份、合并和运行反馈。
4. 在 Host 侧简化输入外观，移除两个快捷入口并验证原文本格式、草稿和发送行为。
5. 在 Studio 的隔离预览接入真实 SDK/Host 契约，分别验证默认舞台与作者组合场景；不在本阶段承诺服务端真实会话接入。
6. 按第 8 节检查跨端视觉、安全和回归，记录差异及未验证项；通过评审后再更新正式实现文档。

原设计稿本身不授权实现或上线；用户随后已明确要求执行方案并在完成后提交推送。本期按该授权实施与同步文档，交付范围仍限于 SDK/Host 展示和本地隔离预览。

## 10. 实施记录与验收状态（2026-11-14）

原有设计目标和阅读/输入/作者边界保留。本轮已新增 SDK 局部样式入口，采用最大 740px 正文、默认 16px/1.85 排版和 288px 状态侧栏；状态布局由组件实际 960px 宽度决定，窄列使用原生 dialog。Host 保留编辑器、草稿与发送语义，移除两个快捷按钮；官方及作者组合样例都在 opaque-origin iframe 中运行真实 SDK。

最新开发环境 sessions-only 回归已完整退出 0、无 stderr，覆盖真实 SDK 历史与 Portal、阅读锚点、状态弹层 Tab/Shift+Tab/Escape、草稿、流式/停止/失败、主题、容器响应式和 390×280 短视口。生成的 `session-changan-*`、`session-neon-*`、`session-state-overlay-wide-column.png`、`session-keyboard-height-390.png` 等截图位于 `apps/studio/tests/visual/output/`，本轮已人工检查官方 1536/390、组合浅色 1536、宽屏窄列 dialog 及 390×280 截图，未见可见遮挡或溢出；它们是开发证据，尚不作为用户认可的视觉基准。锚点自动断言已收紧到原计划的 2px，生产 SDK helper 的全部锚点场景通过；不扩展为未测浏览器的保证。
