## 任务与完成条件

| 顺序 | 交付与依赖 | 如何验收 |
|---|---|---|
| 1. 冻结边界和基线 | 对照现有 stage-contract、HTTP、SSE 和实际 mounted 页面列出操作、目标、权限、数据可见性与错误。记录默认卡、雾港、作者按钮卡的当前行为；取当前首开与流式跨桥字节基线 | 每个现有用户操作和 SDK 入口都映射到新所有者；“保留/兼容/变更”可逐项查。明确作品可观察草稿、可信退出、无重播及草稿丢失语义 |
| 2. 修复状态 HTTP | 两类 Host 先接同一个受限状态适配器。把 scope 和正确的目标放入请求体；读行投影、按 scope 分组写入并维持原始结果顺序；删除无调用的全域 PUT | 已挂载会话和预览的请求由真实 Server 路由在进程内响应。覆盖缺失/null、空域、继承、重复路径、逐项失败、锁和切换 tip；预览越权在发请求前拒绝 |
| 3. 建薄桥和版本选择 | 在同一 app 中保留可切换入口，提取已有握手和清理，明确 session/preview 两份操作表。世界内容、主题和连接事件使用独立消息。编译阶段静态识别 SDK 主版本声明 | 旧版仍能打开；错误来源、过时代次、未知命令/版本均有明确错误或回退。两个浏览标签各有一条会话 SSE，一个标签内重挂 iframe 仍只有一条；挂载另一作品不接收旧会话数据 |
| 4. 做无头 SDK 与恢复 | 依赖 2、3。把历史查询、叙事归并、建议、立绘、状态规则逐域迁移；一次事件只过桥一次。复用现有函数和测试，运行时由组件订阅触发加载 | 两个阅读器能使用不同分页游标；相同在途读取去重；仅有状态面板时不读历史。HTTP/SSE 先后互换、重生成复用 runId、seq 复用、断线漏 delta、终态只改 outcome 都收敛到持久结果 |
| 5. 迁移阅读和作品状态 UI | WorldStory 自行消费历史/叙事 hook；迁移视觉消息规则、reasoning 显示、滚动锚点、建议与立绘。发布纯 SDK 编写的默认组件 | 旧消息无 asset 可恢复，实时立绘直接加载，空数组清场；建议不从更老助手借用。两个部件可删除、替换或并排；替换组件时无 SessionPage 分支 |
| 6. 迁移输入及帮答 | 在 frame 内建立 composer Provider。输入框、发送/停止、重新生成、按钮、帮答、草稿和键盘布局迁入可组合组件。实现玩家选择可信官方舞台和主动切换时的未发送提示 | 普通输入、角色扮演、中文输入法、移动键盘、Tab/焦点、取消帮答及断线保留部分草稿均有验证。接受旧草稿的回执不会抹掉用户新输入。可信模式没有作者模块/消息组件执行，普通订阅收不到帮答草稿 |
| 7. 对齐管理端和预览 | 游玩壳保留导航、设置、诊断与恢复。五个管理页继续复用既有服务与 PageHeader。预览复用端口基建、只读查询；世界详情保留现有结构和实例管理 | 预览无发送、帮答、会话历史或写状态能力。保持十实例 FIFO、稳定 DOM、隐藏媒体暂停、释放与重试；打开会话与预览不串目标。预设保存、模型凭据及世界版本管理继续走管理端 |
| 8. 交付作者与第三方组合 | 新版默认舞台和雾港示例走公开入口；加入可重复的“无聊天列表舞台”和随卡第三方替换部件验证样例。补齐模块冲突、缺依赖、SDK 版本和资源路径诊断 | 官方组件和第三方替代品使用同一份 SDK 契约与权限表。可单独替换输入/阅读/立绘。未使用的部件不启动业务请求。world:check/pack 成功，单凭换世界包即可换玩法 |
| 9. 灰度、度量、退役 | 对默认、旧自定义、新版和可信回退分别验证，再移除旧 workspace 和不停推送的 StageSnapshot。同步根和子项目 AGENTS、设计契约、创作者教程及 SDK 迁移说明 | 一个会话页只有一个执行者；同一 delta 的过桥字节不随历史页数增长；旧卡受支持或收到主版本迁移说明。切回兼容入口后服务端记录可读，无数据库迁移、无重复提交 |

## 明确哪些 API 在哪里过渡

| 当前表面 | 迁移落点 |
|---|---|
| useSRSession.send/regenerate/stop/subscribe | 保留作者语义；RPC 仅代理绑定操作，frame 内叙事订阅处理活动执行。停止仍携带两个 ID |
| useSRHistory.query/loadMore/refresh | query 保留独立返回；loadMore/refresh 归当前阅读订阅。旧全页刷新如确有依赖，只在旧适配器中保留 |
| useSRStateAPI、useSRState、useSRWorldStateAPI | 按查询选择目标和路径；预览只读 global。旧 getter 兼容缺失值，所有写入由 Server 返回结果 |
| useSRStageSnapshot、旧原始 snapshot 消息 | 老卡过渡期可从领域订阅按需合成 facade。新版桥只出现业务查询结果和事件，禁止旁路推回全页缓存 |
| useSRActionSuggestions、SR.WorldStory、SR.ActionSuggestions | 保留名称和基础展示；订阅与显示迁入 frame。组件可被任意卡替代 |
| useSRComposerButtons、session.setDraft | 同一舞台的本地 Provider；兼容布局给老卡提供默认输入和工具条，保留按钮版本和卸载行为 |
| 官方立绘、AI 帮答、用量、设置 | 立绘/输入帮答进入舞台，按请求隔离帮答。用量可提供安全读视图，模型和预设修改留在管理壳。同步 SDK 类型、事件文档与生产路由 |

## 验证与放行记录

1. **协议与权限**：以函数级连通测试将 SDK 操作、Host 适配和 Server 的进程内 app.request 接起来；校验合法输入、错误包络、过大请求、弃用端口、越权会话/世界和共享草稿边界。无需新建模拟服务器。
2. **运行一致性**：测试先事件后回执和反序、丢失终态、写锁冲突、重复删除、旧助手迟到、重连时活动生成、全空历史、状态缺失/未变化、世界更新和资源撤销。提示“同步中”与持久成功分开断言。
3. **组合性与生命周期**：两个阅读器、一张状态面板卡、无默认输入的按钮卡、第三方 Composer、默认舞台、旧版卡、预览只读。移除最后消费者、换卡、换 session、重复挂载后验证取消读请求、端口/SSE 数及订阅释放。
4. **静态和构建**：根目录 pnpm typecheck、pnpm lint、pnpm test、pnpm build；使用仓库 world:check 和 world:pack 检查目标示例。分别核对管理构建和隔离构建入口，不将计划中的未来用例记作本次已通过。
5. **导入与试玩**：实施阶段按项目授权安排真实导入、桌面/移动浏览器、键盘与读屏、重连和回退。导入成功、实际试玩、静态验证各自记录证据；若阶段只允许函数验证，应在放行记录标出待验证项。
6. **发布判据**：具名记录已迁移卡、兼容卡、不可兼容原因及回退结果。既有完整会话在升级、回退后仍可继续游玩。关掉旧实现之前必须实际验证手头的代表性旧卡。

先执行 1–4 可以验证“薄 Host + 领域 SDK”是否成立，随后 5–8 验证“组件对等”是否真的能交给作者，最后才退役旧路径。任何一阶段都不以搬迁文件数量作为完成条件。
