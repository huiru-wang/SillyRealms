# SR.WorldStory 实施任务与验收清单

状态：首版实施完成。产品与接口约定见 [设计方案](sr-worldstory-design.md)。验证使用临时数据库、模拟 Provider 和本机浏览器，未调用真实付费模型。

## 执行顺序与任务

### 0. 修复测试对已删除文档的依赖（已完成）

- 将 `catalog-flow.test.ts`、`world-session.test.ts` 使用的测试样本迁移到 `apps/server/test/fixtures/`，由测试独立拥有；针对导入校验构造需要的有效和无效样本，不恢复或依赖用户删除的旧文档。
- 验收结果：受影响的 2 个测试文件、12 项测试通过；全量 `pnpm test` 的 22 个测试文件、58 项测试通过，`pnpm typecheck` 和 `pnpm lint` 通过。

### 1. 锁定世界卡格式及导入导出（已实施）

- 修改 `apps/server/src/domain/world-card.ts`：新增 `message_render.rules` 和唯一 `component_source` 的校验，按方案限制长度、flags、角色、ID、联合类型和组件 source 要求。
- 保证 `routes/worlds.ts` 的导入、数据库保存、读取与导出不剥离字段，旧卡无该字段仍通过；新增错误码使用全局领域错误码位置。
- 检查前端读取世界卡的数据流及类型声明，禁止仅通过 `extensions` 偷渡。
- 验收：有效规则顺序和源码原样往返；错误路径可定位；重复 ID、无效 flags/正则、缺 source、超长项失败；没有新字段的卡不受影响。

### 2. 平台输入区与 Host 命令（已实施）

- 在 `apps/web/src/host.tsx` 或拆分的会话组件中实现顶部、内容区、输入区布局；状态、错误、收起与无障碍语义见方案。
- 改造 `packages/sr-sdk/src/session-runtime.ts` 和 `apps/web/src/frame.tsx`：`setDraft` 通过受限 MessageChannel 更新平台草稿；移除 SDK 本地草稿副本及不再使用的监听。
- 抽出平台发送和作者 SDK 共用的 Host 命令执行器；统一连接校验、requestId、tip、202、终态与停止；只维护活动运行所需轻量 UI 元数据，不持久化草稿或维护历史快照。
- 验收：两个输入入口一致；并发发送及早于 202 的终态不导致卡死；中文 IME、草稿保留、收起后 `setDraft`、断线/恢复、停止和失败可验证。

### 3. 消息模块编译与注册（已实施）

- 扩展 `packages/sr-ui-compiler/src/index.ts` 与 `apps/web/src/frame.tsx`，分别编译/加载页面模块和唯一消息组件模块，验证对象、组件类型及组件静态 `srDisplay`（缺省 block，仅允许 inline/block）；仅在隔离 iframe 执行，React/SDK 单例。
- 为 Host 增加会话级世界卡热点数据模块，缓存 `message_render`、状态声明与页面源码/编译结果；切换会话或刷新重读，iframe 重建复用缓存，按代次隔离迟到响应；不缓存当前状态或历史。
- 通过已握手 MessageChannel 将世界卡规则、状态声明和消息模块编译产物作为 frame 初始化只读配置；默认界面和作者页面中的 `WorldStory` 使用同一个注册表。
- 对消息模块编译失败、缺少组件提供消息级原文降级；作者页面加载、编译、求值、默认导出、根组件错误必须按方案进入“世界卡数据异常”阻断状态，不回退 WorldStory。退出和 iframe 重建时清理通道/资源。
- 验收：单模块导出多个组件；无组件规则省略 source；默认/自定义页面一致；作者页面整体异常禁用输入并拒绝 iframe 写状态和发消息、已知 Run 触发停止且保留退出入口；无系统回退；局部消息组件错误只显示原文；不拓宽 import、网络或父页面访问权限。

### 4. 有界消息转换管线（已实施）

- 新增可测试的消息规则执行器及 worker，将原文映射为文本、静态替换和组件片段；先对原文产生范围，再映射结构；实现完整自闭合占位标签、多行捕获、规则优先级、捕获组、空匹配、数量/字节/单规则及整消息时限和过期结果处理。
- 新增结构化消息渲染器：Markdown/HTML 的安全解析、组件行内与块级插入、每个组件错误边界和稳定键；规范代码、链接、HTML、跨结构匹配回退，不执行 HTML 的脚本或事件属性。
- 将解析、替换、注册表和渲染器分层，预留未来替换 MDX 渲染实现的接口；第一版不执行消息里的表达式或 import/export。DOMPurify 并非 CSS 清理器，样式需单独约束与验证。
- 在可信 Host 创建固定平台同源 Worker，经 MessageChannel 转发受限匹配请求；opaque-origin iframe 直接创建同源 Worker 已在 Chrome 原型中失败，不能作为实现路径。为 Worker 响应配置严格 CSP，限制并发/大小、超时终止，清理请求并避免记录消息正文；不放宽 iframe sandbox、连接权限或 import allowlist。浏览器验证生产构建、Worker CSP 与终止。
- 验收：两个及以上组件、inline/block 和缺省 block、完整匹配及编号/命名捕获、多次匹配、跨结构回退、混排、规则交叠、HTML 净化、零长度、灾难回溯、迟到 worker 结果、流式拆分与卸载均有测试；消息原文不被改变。

### 5. 实现系统 `SR.WorldStory`（已实施）

- 在 `packages/sr-sdk/src/` 新增系统组件及必要内部 hooks，并从 `index.tsx` 导出 `SR.WorldStory`；不要复用使用旧事件及历史格式的 `apps/web/src/live-messages.ts`。
- 实现订阅先行的首屏历史加载、分页、Run 分组、按 messageId 增量、终态替换及错误显示；数据保留在组件而非 Host；首屏与事件竞态遵循方案中的缓冲取舍，已有 Run 的部分增量可能暂时缺失，终态可更正；不更改 RunEvent 契约，不做断线补偿。
- 实现默认响应式状态概览、状态栏展开/收起、历史滚动锚点、错误恢复和跳至最新；接入规则渲染与消息组件注册表。
- 替换 `frame.tsx` 的 `PendingOfficial`；可从作者页面引用同一系统组件。
- 验收：开局是第一条历史消息；分页不会分裂 Run；首屏与事件竞态不重复追加快照已有 delta，并明确覆盖可能的临时缺口与终态更正；预检失败无 created 时能正确结束；state.changed 更新可见。

### 6. 集成和回归（已实施）

- 使用临时数据库和模拟 Provider，创建世界卡、设置状态、配置消息规则和两个作者组件；覆盖会话创建时 opening.initial_state 默认初始化、默认按钮直接发送、另一个按钮先更新状态再发送、用户消息美化、后台原文和 Prompt 不变。
- 验证同一个组件模块在默认界面与自定义页面生效；验证作者页面整体异常阻断、无系统回退与局部错误隔离，以及部分更新、重复点击、iframe 重建及无实时事件重放。
- 补充本功能依赖的停止、预检失败、持久化与并发回归；不得通过跳过失败测试掩盖问题。旧同步测试此前按用户要求删除，此处的新增测试针对新 V1 契约。
- 验收：`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build` 通过；使用实际浏览器检查 375px 和 1280px、键盘与 iframe 安全边界，记录证据和未验证项。

### 7. 更新项目文档和示例（已实施）

- 在新建或现存项目文档中编写世界卡结构及完整可导入示例（不得恢复作为事实依据的旧文档），文档化正则语义、单组件模块、捕获组 props、组件 srDisplay 默认 block、静态替换限制与出错行为。
- 按实施后的实际代码编写相关 SDK、产品、服务端及数据格式文档，更新根 `AGENTS.md`；不得以已删除旧文档作为事实依据或恢复其旧内容；决策稳定后写入 `docs/decisions/`。
- 严格区分已实现和未来能力；标注模型写状态和用户编排非事务、断线不重放、原始酒馆脚本不兼容。
- 验收：文档示例可通过真实 schema/编译器运行，与测试和实际导出一致。

## 文件边界及依赖

`0 → 1 → 3 → 4 → 5 → 6 → 7`；任务 2 可在任务 1 后独立推进，但需在 5/6 前集成。修改统一的 `frame.tsx`、`host.tsx`、SDK 入口时先固定接口，避免并行覆盖。每阶段保持工作区中既有改动，不重置或清理用户数据。

## 明确非本期

AI 帮答、续写、重生及状态回退、生图、语音、从酒馆卡自动迁移/执行脚本、会话内开局切换、离线消息重放、可视化布局编辑器、作者组件任意网络访问都不在本期；需要时分别设计、评估并验收。
