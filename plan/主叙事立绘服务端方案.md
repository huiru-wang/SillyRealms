# SR 独立角色立绘服务端方案

日期：2026-11-24（Asia/Shanghai）。

状态：服务端能力已按本方案实施（2026-11-24），函数与接口契约验证通过；前端及 Stage SDK 接入另行实施。

设计基线：`main @ c147561`。服务端实际变更范围见第 12 节，实施与验证记录见第 15 节。

## 1. 目标与本期范围

立绘是 SR 的独立能力。服务端负责素材目录、预设资料注入、历史消息旁注、模型输出解析、消息级快照持久化、查询 API 和 SSE；不依赖某种演出模式或某个官方前端布局。

本期实施范围只有 Server 及其发行预设、契约文档和对应测试。Stage 的消费接口在本文定义清楚，Host 接线、SDK runtime/Hook、官方组件、模板、胶囊和响应式布局均不在本期实现。

### 1.1 本轮明确决定

| 事项 | 新版规则 |
| --- | --- |
| 预设 | 按新规则直接切换；不兼容旧预设、不运行时补节点、不自动补旧 prompt |
| 立绘节点构建 | 节点存在、enabled=true、世界有立绘素材，三者同时满足 |
| 历史立绘旁注 | 使用与节点相同的构建条件；附对应消息的有效条目，缺失或失败也附空标签 |
| 后处理 | 不读取预设、不接收 enabled；从实际模型输出发现块就解析，缺块不解析 |
| 能力命名 | characterSprite |
| 标签 | character_sprite |
| 数据编码 | JSONL，每行 position/characterId/spriteId 三个字段 |
| 行处理 | 按行序校验，失败行跳过；第一条有效行占用角色与位置 |
| 快照语义 | 本次全部条目构成整份快照，无跨消息 merge |
| 空快照 | 完整空标签保存成功的空数组，并通知 |
| 位置 | left、center、right、top、topleft、topright、truecenter |
| 数量与唯一性 | 角色、position 在一份快照中分别唯一；允许超过两项，七种位置自然最多七个有效条目 |
| 查询 | 素材目录查询、指定消息自身立绘结果查询 |
| 资源访问 | 返回资源引用，实际读取复用 AssetAPI 边界与已有资源服务 |

`character sprite` 采用适合现有标签解析器的 `<character_sprite>` 写法。用户示例中的 JSON 引号笔误按有效 JSON 修正，不保留格式错误。

### 1.2 两个判断层必须分开

~~~ts
// 只用于模型输入构建。
includeCharacterSprite =
  node !== undefined &&
  node.enabled === true &&
  capturedCatalog.length > 0;

// 后处理没有这个开关参数。
parseCharacterSprite(rawModelOutput, capturedCatalog);
~~~

节点关闭后，模型输入不再引导这项能力，历史也不附对应块；但模型如果仍实际输出了合法数据块，后处理照常解析、保存并通知。

这是本期明确契约，不能在 execute 再增加 allowedCapabilities/characterSpriteEnabled 拦截，把两层重新耦合。

## 3. 统一命名与数据类型

| 层面 | 名称 |
| --- | --- |
| 能力、预设节点、消息结果字段 | `characterSprite` |
| 预设系统变量 | `{{characterSprite.catalog}}` |
| 模型/历史数据块 | `<character_sprite>…</character_sprite>` |
| 历史旁注 source、处理文件 | `character-sprite` / `character-sprite.ts` |
| SSE | `character_sprite.changed` |
| HTTP 资源名 | `character-sprites` |
| 后续 Stage 门面 | `CharacterSpriteAPI` |
| 世界卡素材 | `data.characters[].sprites` |

本期只接受新命名，不增加旧节点、旧变量、旧标签或旧事件别名。

~~~ts
type CharacterSpritePosition =
  | "left"
  | "center"
  | "right"
  | "top"
  | "topleft"
  | "topright"
  | "truecenter";

type CharacterSpriteItem = {
  position: CharacterSpritePosition;
  characterId: string;
  spriteId: string;
};

type CharacterSpriteSnapshot = CharacterSpriteItem[];
~~~

### 3.1 position 是语义位置

用户所说的 transform，首版按以上七种预定义语义位置表示，协议字段统一叫 `position`。

服务端校验位置枚举及快照内唯一性，不把位置翻译为 CSS、坐标、左右组件、缩放或 z-index。未来一个组件可以接收 left 与 topleft 的全部条目，另一个组件可以展示所有位置，也可以按自身策略组织多个人物。

### 3.2 角色与位置分别唯一

每条记录表示“某个角色使用某张立绘，占用一个语义位置”。保持扁平三字段，不增加 op、instanceId 或嵌套对象。

一份快照中：

- characterId 最多出现一次，同一角色不能占多个位置，也不能用不同素材重复出现。
- position 最多出现一次，同一位置不能放多个角色。
- spriteId 仅在所属角色内解析，不要求不同角色的素材 ID 全局唯一。
- 完全重复行也属于重复角色/位置，按失败行跳过。
- 允许超过两个有效条目；当前七种 position 且各自唯一，自然最多七项，不额外限制原始 JSONL 行数。
- 唯一性只针对本次快照，下一消息重新计算；不是跨消息锁定角色或位置。

### 3.3 冲突按第一条有效行处理

从上到下读取每个非空行。只有 JSON、字段、引用、position 和双唯一性都通过后，才同时占用 characterId 与 position，并加入 items。

后续冲突行记录错误并跳过，不覆盖先前已接受的行。失败行不占用任何角色或位置，后续合法行仍有机会通过。

| 行 | 内容概要 | 处理 |
| --- | --- | --- |
| 1 | alice → left | 接受，alice 和 left 被占用 |
| 2 | bob → left | 位置重复，跳过；bob 尚未占用 |
| 3 | bob → center | 接受 |
| 4 | alice → top | 角色重复，跳过；top 尚未占用 |
| 5 | carol → top | 接受 |

位置唯一性按枚举值判断，不在服务端计算图片是否视觉重叠。语义不同的位置仍由前端决定具体呈现。

## 4. 世界卡素材与资源

### 4.1 素材结构

以下为角色字段片段：

~~~json
{
  "id": "alice",
  "name": "爱丽丝",
  "sprites": [
    {
      "id": "default",
      "asset": "sr-asset://assets/characters/alice/default.webp",
      "description": "平静站立，适合日常交流。"
    },
    {
      "id": "restrained_smile",
      "asset": "sr-asset://assets/characters/alice/restrained-smile.webp",
      "description": "勉强微笑，适合掩饰担忧或安慰他人，不适合真正兴奋时。"
    }
  ]
}
~~~

- sprites 可省略或为空；非空时素材 ID 在角色内部唯一，必须包含 default。
- id/asset/description 非空，沿用角色稳定 ID。
- 表情、姿态和服装变化通过 spriteId 选择，不再增加另一套 emotion 字段。
- 不在素材中固化左右槽位或前端组件名。
- 本期不增加素材级解锁条件、动画时间线或初始开局立绘配置。没有模型/明确结果的开局消息，不自动制造立绘快照。

### 4.2 资源校验与持久化

asset 支持现有 HTTP(S) 或 `sr-asset://assets/...` 引用：

1. 将 `$.data.characters[i].sprites[j].asset` 纳入统一引用收集。
2. ZIP 导入、world:check、打包验证复用路径与存在性检查。
3. 单独 JSON 导入不允许包内 sr-asset 引用，包内资源必须随 ZIP 提供。
4. 在线地址只校验 URI，不在导入时批量下载或探测。
5. 导入/导出保持素材元数据和引用；现有 characters_json 即可承载，无 DDL。
6. 输出快照只存 ID 与 position；图片字节、HTTP 地址或本机磁盘路径不写入消息结果。

合法角色和素材 ID 是引用校验的依据。未知角色/素材使该行失败并跳过，其他行继续；服务端不自行替换为另一张图，默认素材由模型明确选择 `default`。图片实际无法加载后的展示回退属于后续资源/组件策略。

### 4.3 同一目录的两种用途

捕获世界时始终取得本轮内部素材目录。内部校验目录即使在节点关闭时也保留，供输出解析校验引用。

模型看到的是精简目录：角色 ID/姓名、素材 ID/说明、当前玩家角色 ID；不包含 asset 地址、角色完整 prompt 或图片数据。

目录取全卡已声明的合法 sprites。既有角色 load 继续控制角色 prompt 注入，不作为“人物在场”或“允许显示图片”的判断。素材描述是公开选择材料，不依靠 load 隐藏说明中的剧情信息。本期不增加条件解锁机制。

所有实际注入的目录、模板和历史块均计入上下文预算，不在估算后偷偷追加，也不静默截断一部分素材。

## 5. 新版预设与构建规则

### 5.1 直接使用新版节点

发行预设显式包含：

~~~json
{
  "id": "characterSprite",
  "name": "角色立绘",
  "kind": "postprocess",
  "role": "system",
  "enabled": true,
  "prompt": "基于 {{characterSprite.catalog}} 与本轮故事，输出当前完整立绘快照；具体默认正文见本节。"
}
~~~

新增节点接入现有单层叙事预设。内置能力顺序为 worldState → actionSuggestions → characterSprite，保留当前系统节点相对顺序要求；不以本功能为由改成另一套多场景预设结构。

新版统一使用“实际声明驱动”：

- 节点不存在就不构建，不在读取、编译或执行时补节点。
- enabled=false 就跳过该节点，也不注册它的历史旁注来源。
- 默认 prompt 只来自新建默认模板或明确的恢复默认操作。
- 启用的能力节点 prompt 为空，在预设保存/导入时拒绝；编译失败明确报告，不回退默认。
- 增加正式变量白名单，模板按原规则只渲染一次。
- 移除旧 state.entries→state.message 的预设变量转换，不做旧格式转换、迁移或运行时补救。
- 数据清理后重新初始化新发行预设；本次“更新方案”不执行数据删除。

统一规则同时覆盖 worldState/actionSuggestions/characterSprite 的 prompt 和历史来源，避免继续保留“旧节点关闭仍被系统补回”的行为。各能力需要的数据条件仍单独判断，例如 worldState 是否有适用状态材料、characterSprite 是否有素材目录。

本次不顺带重写历史 output 存储格式的其他兼容处理；“不兼容旧预设”不等于额外修改所有不相关模块。

### 5.2 立绘构建条件

~~~ts
const includeCharacterSprite =
  characterSpriteNode !== undefined &&
  characterSpriteNode.enabled === true &&
  characterSpriteCatalog.length > 0;
~~~

此条件同时控制：

1. characterSprite prompt 节点。
2. 立绘固定输出协议说明。
3. 模型输入中的 characterSprite.catalog 变量值。
4. characterSprite 历史旁注来源。

条件不满足时，不通过 main、固定协议或默认模板再补回立绘指令；立绘模板变量对模型为空，内部引用校验目录仍完整保留。

main 使用“遵守本轮已构建的能力协议”的通用措辞，不无条件要求每种尾块。

### 5.3 默认策略 prompt

~~~text
你负责根据本轮最终正文，记录当前故事场景的完整角色立绘快照。

【可用立绘】
{{characterSprite.catalog}}

选择有当前情境依据的角色与素材，不把回忆、提及、猜测或尚未发生的行动当作在场事实。
根据素材说明选择表情、姿态或服装，没有更合适的素材时选择 default。
位置使用 left、center、right、top、topleft、topright、truecenter。
位置表达故事中的相对安排，不依赖某个前端组件；不要因为预想界面只显示两侧，就限制人物数量或只输出左右。
每条记录只包含 position、characterId、spriteId。同一份快照中，一个角色只能出现一次，一个位置只能分配给一个角色。
可以显示超过两个人物，使用不同的合法位置；不要重复人物、重复位置或重复记录。
每轮输出当前全部展示条目，即使没有变化也重新给出完整快照；不要只输出变化部分。
不要为了展示素材编造剧情，不输出图片地址、CSS 或坐标。
当前场景无需任何立绘时，输出完整空标签。
遵守平台的 character_sprite JSONL 输出协议。
~~~

创作者可以编辑人物优先级、表情选择和相对位置策略。服务端不把角色身份、素材数量或 position 变成某个官方组件的布局规则。


## 6. 历史消息末尾的立绘旁注

### 6.1 沿用现有旁注窗口

本期沿用当前 model-notes 机制：

1. 先选最近两条有可见正文的 assistant 消息。
2. 再读取它们各自保存的 output，不为凑满有立绘结果的消息继续向前补足。
3. 只有最终仍保留在模型请求中的消息才附旁注；已裁剪或由摘要覆盖的消息不附。
4. 正文后空一行，按 state_update → action_suggestions → character_sprite 顺序追加已启用且可用的来源。

不新增旁注窗口配置，不改变真实消息角色。旁注仅为本次模型请求的内存投影，不修改用户看到的正文或数据库原消息。

### 6.2 对应消息的有效条目或空标签

立绘历史来源启用时，对窗口内每条被保留的助手消息都附一个立绘块：

| 该条历史消息的 characterSprite 结果 | 历史旁注 |
| --- | --- |
| success，items 非空 | 将该条消息 items 序列化为 JSONL |
| partial_success | 只序列化该条消息通过的 items，不附失败行或诊断 |
| success，items=[] | 完整空标签 |
| 没有 characterSprite 字段 | 完整空标签 |
| 全部行失败、坏标签或能力处理失败 | 完整空标签 |
| 保存数据损坏、读取或序列化失败 | 完整空标签 |

历史数据仍来自对应消息，不从前一条消息或所谓当前画面借条目。

空标签在历史中承担统一格式占位：它可能来自真实的空快照，也可能表示该消息没有可用立绘结果。这个投影不回写原消息，不把 null/错误结果改成 success，也不触发清场 SSE。

有效条目示例：

~~~text
爱丽丝在门旁停下，勉强露出一个微笑。

<character_sprite>
{"position":"topleft","characterId":"alice","spriteId":"restrained_smile"}
</character_sprite>
~~~

空数组、缺失或失败结果的历史格式相同：

~~~text
众人离去，大厅里只剩下摇曳的烛光。

<character_sprite></character_sprite>
~~~

上述示例只展示格式，正文内容不参与“是否补空标签”的判断。

节点不存在、disabled 或本轮无素材时，整个立绘历史来源仍不构建，不附任何立绘块；新要求的空标签补齐只适用于该来源已经启用的消息。

### 6.3 接入位置

在 `model-notes/character-sprite.ts` 增加独立 source，复用现有 entryId 关联与序列化。在 capture 阶段根据启用节点选择来源集合，由 assemble 在预算计算前追加。

立绘 source 自身对结果读取、校验或序列化异常返回常量空标签，不能仅依赖通用 model-notes 的 catch 后忽略来源，否则会漏掉要求的空标签占位。其他来源的异常隔离规则保持原有职责。

各裁剪候选使用同一捕获的消息结果，只对保留消息展开旁注。真实模型请求预算包含立绘 JSONL；关键词激活与摘要输入保持原始干净正文。

历史旁注不执行输出解析、不重新校验今天的素材可用性、不更新状态，也不发 SSE。

## 7. 模型输出协议

### 7.1 三字段 JSONL 完整快照

每行以 position 开头，便于直接阅读位置分配；JSON 对象键顺序不影响解析。示例假设世界目录已经声明 alice、bob、carol 及对应素材：

~~~text
本轮叙事正文……

<character_sprite>
{"position":"left","characterId":"alice","spriteId":"restrained_smile"}
{"position":"center","characterId":"bob","spriteId":"default"}
{"position":"right","characterId":"carol","spriteId":"serious"}
</character_sprite>
~~~

每个非空行是一个完整 JSON 对象，只有三个必填字段：

| 字段 | 含义 |
| --- | --- |
| position | 七种合法语义位置之一；本次接受结果中唯一 |
| characterId | 世界卡中的角色 ID；本次接受结果中唯一 |
| spriteId | 该角色已声明的素材 ID |

块内没有 JSON 数组外壳、嵌套槽位或操作指令。后处理按行筛选，通过的条目按原始顺序组成本次完整快照，不从上一消息补回被跳过的角色。

其他已构建能力的块仍与立绘块并列在正文之后。

### 7.2 空快照

~~~xml
<character_sprite></character_sprite>
~~~

以下只有空白行的写法语义相同：

~~~xml
<character_sprite>

</character_sprite>
~~~

两者都保存 `status=success, items=[]`。后续消费者接收的是一份完整空快照。

块内写 `[]` 不是本协议的 JSONL 行，不把它作为另一种空快照别名。

### 7.3 逐行处理与结果状态

| 情况 | 持久结果 | 立绘变化通知 |
| --- | --- | --- |
| 完全没有标签 | 没有 characterSprite 字段 | 不发 |
| 完整空标签/只有空白行 | success，items=[] | 发，明确清场 |
| 所有非空行通过 | success，items 为全部有效行 | 发，完整 items |
| 部分行通过、部分行失败 | partial_success，items 仅为有效行，附错误行诊断 | 发，完整有效 items |
| 非空块全部行失败 | invalid_items，items=[]，附行诊断 | 不发；未形成有效快照 |
| 自身标签损坏、嵌套、重复整块 | invalid_tag，items=[] | 不发 |
| 无法完成能力级处理 | processing_error，items=[] | 不发 |

逐行规则：

1. 忽略空白行，其余每行单独解析一个严格 JSON 对象；errors.line 按非空数据行从 1 开始编号，空白行不占序号。
2. JSON 无效、重复 JSON 键、缺/多字段、错误类型、未知角色/素材、非法 position，均使该行失败并跳过。
3. 检查角色唯一性，再检查位置唯一性。与已接受行冲突时跳过，不覆盖旧行。
4. 只有全部通过后才加入 items 并占用两个键；失败行不占位。
5. 某行的解析/校验异常只记录该行诊断并继续，不中止其他行。标签边界错误和无法完成整体能力处理的异常才属于能力级失败。

建议行错误码按原因区分 invalid_json、invalid_item、unknown_character、unknown_sprite、invalid_position、duplicate_character、duplicate_position、processing_error；统一存入 errors 的 line/errorCode，不另存一份完整原始行列表。

partial_success 中的 items 仍是一份完整新快照。失败行对应的人物不会从上一消息被补回，也不保留前一快照中未出现在本次有效数组里的角色。

明确空标签与全部行失败要区分：前者主动提供了有效空快照；后者没有有效条目，所以不发布清场事件。错误结果中的 items=[] 仅表示没有可用项，消费者必须结合 status 判断能否应用。两者用于历史旁注时都输出空标签。

### 7.4 分离、转义与流式

- 保留标签匹配沿用当前大小写不敏感规则，角色/素材 ID 按原值匹配。
- 处理器只匹配自己的标签，不用其他能力的标签修复坏边界。
- stream-splitter 无条件识别新保留标签，覆盖跨分片、部分标签与最终 snapshot 修正；是否隐藏结构块不依赖预设。
- JSON 字符串中的保留标签使用 Unicode 转义；正文要显示保留标签使用 HTML 实体。
- 复用现有严格 JSON/深度等合法性检查，不增加独立能力 token 配额或原始 JSONL 行数上限；有效条目最多七项来自 position 唯一性，不来自前端双侧布局。
- 不生成第二次模型调用修复格式，不增加后台重试任务。

## 8. 输出驱动的独立后处理

### 8.1 输入边界

立绘处理函数接收自身标签的提取结果，协议分离与逐行处理分别复用现有层次：

~~~ts
processCharacterSprite(
  extraction: CapabilityExtraction,
  catalog: readonly CharacterSpriteCatalogItem[]
): CharacterSpriteOutput | undefined;
~~~

不接收 preset、节点、enabled、前端布局或有效能力集合。返回 undefined 表示没有发现该块，不制造 no_update，也不制造空数组。

捕获素材目录与注入素材目录是两件事：即使本轮不向模型注入立绘 prompt，执行器仍拿到同一时点捕获的完整目录，避免无法校验模型实际输出或模型请求与处理使用不同世界版本。

### 8.2 关闭节点仍有输出

| prompt 构建状态 | 实际输出 | 后处理 |
| --- | --- | --- |
| 节点开启且有素材 | 有数据块 | 按行处理，有可应用结果则保存并通知 |
| 节点关闭/不存在 | 有数据块 | 同样按行处理，不以开关拒绝 |
| 任意节点状态 | 无块 | 不解析，不产生该能力结果 |
| 世界没有素材 | 完整空块 | 合法空快照，保存并通知 |
| 世界没有素材 | 非空角色/素材行 | 对应行引用失败；若全部失败，保存 invalid_items，不通知 |
| 任意节点状态 | 部分行失败且存在通过行 | 跳过失败行；有效项形成 partial_success |
| 任意节点状态 | 坏标签或全部行失败 | 保存错误结果，不发可应用快照通知 |

引用失败和重复冲突是行校验，不是能力开关控制。已保存结果查询也不受预设 enabled 影响。

历史来源已启用时，success/partial_success 回填有效项，缺块或失败回填空标签。该历史格式投影与本轮输出处理分别完成，不能在后处理补造缺失标签。

### 8.3 与现有执行生命周期共存

继续在现有正常模型输出进入后处理的时机处理：正常 stop、正文有效且无不支持的工具执行。取消、模型失败、长度截断等仍走当前公开部分保存规则，本期不新增中断时提前执行能力的路径。

状态、建议、立绘各自解析并隔离异常。状态的路径/类型/允许根校验、建议的内容校验保持其业务规则；移除 prompt fallback 不等于删除这些结果校验。

主模型正常结束且成功保存正文时，某个立绘块出错只影响该能力结果，不改变其他能力的执行，也不把整轮正常完成改成失败。

## 9. 消息存储与 SSE

### 9.1 结果存储

~~~ts
type CharacterSpriteOutput = {
  status:
    | "success"
    | "partial_success"
    | "invalid_items"
    | "invalid_tag"
    | "processing_error";
  items: CharacterSpriteItem[];
  errors?: Array<{errorCode: string; line?: number}>;
};
~~~

结果约束：

- success：没有失败行；items 可以非空，也可以是明确空标签产生的 []。
- partial_success：items 非空且有失败行诊断；items 已满足角色/位置双唯一。
- invalid_items：非空块没有任何通过行，items=[]，有行诊断。
- invalid_tag/processing_error：未形成可信可应用快照，items=[]，有对应诊断。
- 完全没有标签：不创建 characterSprite 字段，不制造任何 status。
- 行级 errors.line 为非空数据行的 1-based 序号；能力级错误可不带 line。

部分通过的存储示例：

~~~json
{
  "extData": {
    "output": {
      "characterSprite": {
        "status": "partial_success",
        "items": [
          {"position": "left", "characterId": "alice", "spriteId": "restrained_smile"},
          {"position": "center", "characterId": "bob", "spriteId": "default"}
        ],
        "errors": [
          {"line": 2, "errorCode": "duplicate_position"}
        ]
      }
    }
  }
}
~~~

例如输入依次为 alice→left、bob→left、bob→center：第二条失败不占用 bob，第三条可以通过。既有 stateUpdate/actionSuggestions 字段仍按各自契约存在。

- success 和 partial_success 都把本次通过的全部 items 作为完整新快照，不从上一消息补条目。
- 明确空标签保存 success + []；全部失败也有 items=[]，但 status 不同且不触发清场。
- 只存一份有效 items 和失败诊断，不保存重复的 updates/results/applied 或完整原始行列表。
- 复用现有 entries.ext_data，无新表、列或立绘运行状态缓存。
- 正文、output、状态候选和 metrics 在同一次助手追加事务内保存。
- 通用正文/扩展编辑继续保护 output，不允许伪造或覆盖立绘结果。
- 编辑正文不自动重跑模型、不修改原处理记录。
- 没有输出结果的开局、用户消息和部分回复不自动补持久立绘结果。历史模型输入需要的空标签由 context 临时构建，不写数据库。

### 9.2 SSE 契约

~~~text
event: character_sprite.changed
data: {"sessionId":"s-1","runId":"r-1","messageId":"m-1","items":[{"position":"topleft","characterId":"alice","spriteId":"restrained_smile"}]}
~~~

清场：

~~~text
event: character_sprite.changed
data: {"sessionId":"s-1","runId":"r-2","messageId":"m-2","items":[]}
~~~

事件表示“这个持久消息已产生新的完整立绘结果”，不定义客户端必须显示哪个消息。

- 复用现有 session SSE，不增加通道、队列或回放日志。
- 只有 success 或 partial_success 的可应用快照提交后通知；success 的空数组也通知，人物相同但消息来源更新也通知。
- partial_success 发送全部有效 items，消费者整体替换；SSE 不重复发送行错误诊断，诊断通过对应消息查询读取。
- 无块、invalid_items、invalid_tag、processing_error 或助手事务失败均不发变化事件。部分行错误但存在有效项的 partial_success 会正常发出变化事件。
- 消息确已保存而后续 run outcome 写失败，立绘仍作为已提交事实通知。
- 正常结算沿用提交、锁释放、能力通知、usage、terminal 的顺序，各通知异常隔离。
- messageId 使用实际保存的助手 ID，不用可复用的 runId/seq 单独作为来源身份。

### 9.3 不提供隐式继承画面

本期不增加“从所有历史选最近可应用快照”的便捷投影，不在历史分页响应里增加另一份当前立绘事实源。

客户端可以展示某条消息、最近一条可应用快照或自定义面板；选哪条由消费者决定。可应用结果包括 success 与 partial_success。服务端保证各条消息结果可准确读取，SSE 携带完整有效数组，绝不把多条消息拼成一帧。

重新生成沿用现有 message.deleted：旧消息被删除后，查询该消息返回不存在；新回复使用新的助手 messageId。客户端据消息事件使旧来源失效，不由服务端自动合成更早画面或发送伪造的回退快照。


## 10. 面向 Stage 的服务端 API 与 AssetAPI 边界

本期落实下列服务端契约；Stage 后续通过标准 SDK/Host 代理消费。查询接口不读取预设，不受节点开关控制。

### 10.1 查询立绘素材列表

~~~http
GET /api/v1/worlds/:worldId/character-sprites
~~~

返回已有 HTTP 成功包络中的 data：

~~~json
{
  "worldId": "w-1",
  "items": [
    {
      "characterId": "alice",
      "characterName": "爱丽丝",
      "spriteId": "default",
      "description": "平静站立，适合日常交流。",
      "asset": "sr-asset://assets/characters/alice/default.webp"
    },
    {
      "characterId": "alice",
      "characterName": "爱丽丝",
      "spriteId": "restrained_smile",
      "description": "勉强微笑。",
      "asset": "sr-asset://assets/characters/alice/restrained-smile.webp"
    }
  ]
}
~~~

- 这是已声明素材目录，不是当前在场人物或某条消息画面。
- 没有素材返回 items=[]，不调用模型。
- 每张素材一项，以 characterId + spriteId 查找；按世界卡角色/素材原顺序返回。
- 只返回必要展示资料和 asset 引用，不返回角色 prompt/load/世界规则、图片字节或磁盘路径。
- 素材目录读取通过 Worlds Service，Repository 继续只处理属主数据。
- 目录很小时无需分页；本期不新增过滤、索引、上传或资源管理 API。

### 10.2 查询指定消息的立绘结果

~~~http
GET /api/v1/sessions/:sessionId/entries/:messageId/character-sprites
~~~

非空快照：

~~~json
{
  "sessionId": "s-1",
  "messageId": "m-1",
  "result": {
    "status": "success",
    "items": [
      {
        "position": "topleft",
        "characterId": "alice",
        "spriteId": "restrained_smile"
      }
    ]
  }
}
~~~

明确空快照：

~~~json
{
  "sessionId": "s-1",
  "messageId": "m-2",
  "result": {
    "status": "success",
    "items": []
  }
}
~~~

没有该能力结果：

~~~json
{
  "sessionId": "s-1",
  "messageId": "m-3",
  "result": null
}
~~~

部分通过时同样返回该条消息的有效快照与诊断：

~~~json
{
  "sessionId": "s-1",
  "messageId": "m-4",
  "result": {
    "status": "partial_success",
    "items": [
      {"position": "left", "characterId": "alice", "spriteId": "restrained_smile"},
      {"position": "center", "characterId": "bob", "spriteId": "default"}
    ],
    "errors": [
      {"line": 2, "errorCode": "duplicate_position"}
    ]
  }
}
~~~

非空块全部行失败时，返回失败记录而不是清场快照：

~~~json
{
  "sessionId": "s-1",
  "messageId": "m-5",
  "result": {
    "status": "invalid_items",
    "items": [],
    "errors": [
      {"line": 1, "errorCode": "unknown_character"},
      {"line": 2, "errorCode": "invalid_json"}
    ]
  }
}
~~~

规则：

1. 只读指定消息自身结果，不向前继承、不选最近可应用结果、不与其他消息 merge。
2. 结果统一使用 status/items/errors。success/partial_success 的 items 可作为完整快照应用；失败状态的 items=[] 仅表示没有可用项，不能转换为 success + []。
3. 用户消息或没有立绘结果的助手消息返回 result=null。历史旁注补出的空标签不改变这个读取结果。
4. 非 message 的 compaction 条目不是合法查询目标。
5. 先复用 requireSessionAccess，再通过 sessionId + entryId 验证消息归属。
6. 会话不可访问/不存在沿用 SESSION_NOT_FOUND/404；消息不存在或属于其他会话沿用 ENTRY_NOT_FOUND/404；目标类型或参数非法沿用 INVALID_REQUEST/400。
7. 历史读只验证保存结果结构，不用最新世界素材重新否定过去合法保存的 ID。世界资源变动不回写旧消息。
8. 普通 narrative/runs 中的 entries.extData.output 同样带该字段，指定消息接口供不想加载整轮的消费者使用。

Server 不增加立绘写入 API，调用方不能用这个接口修改快照。

### 10.3 资源访问走 AssetAPI 边界

立绘目录只返回 asset 引用。后续组件需要图片资源时，把该引用交给资源访问能力，而不是通过消息结果下载图片。

当前已有能力是：

- `resolveSRAssetUrl`、`useSRAssetUrl` 等资源解析能力。
- `GET /api/v1/worlds/:worldId/resources/*` 包内资源入口。
- HTTP(S) 引用按既有规则解析，最终由资源来源提供。

当前没有一个正式名为 AssetAPI 的统一 SDK 对象。本文的 AssetAPI 表示资源解析/访问边界；后续需要同名 SDK 门面时，在现有能力上包装。

本期不新建立绘下载路由、媒体代理、资源索引表或通用文件读取服务，也不扩展 iframe 直接跨源访问业务 API 的权限。包内资源保持现有路径校验、MIME 和资源访问边界。

### 10.4 后续 Stage 门面映射

以下为后续接入目标，不是本期 SDK 实现任务：

~~~ts
interface CharacterSpriteAPI {
  list(): Promise<CharacterSpriteCatalog>;
  getMessageState(
    messageId: string
  ): Promise<CharacterSpriteOutput | null>;
  onChanged(
    listener: (event: CharacterSpriteChangedEvent) => void
  ): () => void;
}
~~~

- list 绑定当前会话 worldId，映射素材目录 GET。
- getMessageState 绑定当前 sessionId，映射指定消息 GET。
- onChanged 复用现有会话事件通道，不开第二条 SSE。
- 素材查询和画面选择彼此独立；资源引用继续交给 AssetAPI。
- 前端未来可以做左右简版、多个 position 组合区域或完整立绘面板，服务端无需改变数据协议。

## 11. 实施分层与数据流

~~~mermaid
flowchart TD
  A["捕获世界目录与预设"] --> B{"节点存在、启用、有素材"}
  B -->|满足| C["构建 prompt 与对应消息旁注"]
  B -->|不满足| D["省略立绘输入引导"]
  C --> E["一次主叙事模型调用"]
  D --> E
  A --> F["保留内部引用校验目录"]
  E --> G["按实际 character_sprite 标签解析"]
  F --> G
  G --> H["同事务保存助手与结果"]
  H --> I["可应用结果提交后发完整数组 SSE"]
~~~

核心职责：

| 位置 | 职责 |
| --- | --- |
| Worlds | 素材 schema、目录读取、资源引用检查 |
| Presets | 新版节点/变量校验、实际启用节点读取、默认模板 |
| Context | 同步捕获、条件构建 prompt 与 model-notes、预算 |
| Narrative postprocess | 按实际输出逐行校验 JSONL，跳过错误/冲突行，生成完整有效数组 |
| Sessions | output schema、受控持久化、指定消息结果读取 |
| Narrative usecase | 模型生命周期、事务、提交后事件 |
| Routes | HTTP 参数、现有访问检查、公共 Service 调用 |
| 现有资源层 | 包内资源读取与安全路径规则 |

公开类型经所属模块 service.ts 显式导出，跨模块不导入内部 schema/Repository。position 枚举与持久快照结构保持单一来源，解析器通过公开契约复用，避免多份枚举漂移。本期不为共享纯类型改动前端 SDK 包，不建立通用演出引擎或能力注册框架。

### 13.2 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 立绘节点存在、开启、有素材 | 构建节点、固定协议和历史来源 |
| 节点缺失、关闭或无素材 | 不构建节点，不附任何立绘历史块 |
| 已开启节点 prompt 为空/变量非法 | 明确校验失败，不静默回退 |
| state/action 节点关闭 | 相应 prompt 与历史来源也关闭 |
| 节点关闭但模型仍输出有效块 | 仍逐行解析、保存和通知 |
| 无素材时输出空标签 | success + []，发送清场 |
| 无素材时输出非空条目 | 每行引用失败；invalid_items + []，不发清场 |
| 七种 position | 均可用，按枚举值唯一，不映射为双侧组件 |
| 3–7个不同角色占不同位置 | 全部有效，不受两人限制 |
| 同角色重复/同位置重复/完全重复行 | 第一条有效行保留，冲突行失败跳过 |
| 失败行后有同角色或同位置的合法行 | 失败行不占位，后续合法行仍可通过 |
| 部分坏 JSON/字段/引用/位置行 | 只跳过这些行，其余组成 partial_success |
| partial_success | 保存有效 items 与 errors，SSE 发送完整有效数组 |
| 非空块全部行失败 | invalid_items + []，不发变化事件，历史仍补空标签 |
| 明确空标签/只有空白行 | success + []，保存并通知 |
| 完全缺标签 | 不保存该能力结果、不发 SSE；历史来源启用时补空标签 |
| 坏标签/重复整块 | invalid_tag + []，不发 SSE，历史补空标签 |
| 单行处理异常 | 该行错误并继续，不阻止后续行 |
| 能力级异常 | processing_error + []，其他能力不受影响 |
| 历史 success/partial_success 非空 | 只回填该消息的有效 items，不带错误诊断 |
| 历史空数组、缺失或失败 | 都输出一个完整空标签，不向其他消息借数据 |
| 历史结果读取/序列化异常 | source 内部返回空标签，不被通用 catch 丢掉 |
| 历史空占位 | 不回写持久结果、不把 null/错误变成 success、不发 SSE |
| 最近两条有正文助手消息 | 沿用原窗口，不为查有结果的消息向前补足 |
| 历史裁剪/摘要 | 旁注仅用于保留消息且计入预算，不污染摘要/关键词 |
| 流式任意分片/最终 snapshot 修正 | 结构块不泄漏到公开正文 |
| 助手事务失败 | 不发立绘变化 |
| 助手已提交、outcome 后续失败 | 可应用的已提交结果仍可读取并通知 |
| 查询消息 B，只有 A 有结果 | B 返回 null，不返回 A；其历史旁注可为空标签 |
| 查询 success[] / invalid_items[] | 通过 status 区分明确清场和未形成有效快照 |
| 查其他会话消息/已删消息/compaction | 正确归属/目标类型错误 |
| 重新生成 | 旧消息删除、新 ID 保存，不拼接新旧数组 |
| JSON/ZIP 往返、缺包资源 | 新字段完整，资源检查复用现有机制 |
| 素材目录查询 | 与预设开关无关，返回必要元数据和资源引用 |

验证集中于对应函数、临时库/文件和现有 HTTP 契约测试，随后运行受影响范围的 typecheck/lint。遵守当前仓库验证边界，不启动服务、不做前端浏览器验证、不新增 mock 端到端系统。
