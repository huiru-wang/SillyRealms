# ServerV2 叙事输出数据块实施任务

状态：待实施。本轮仅修订方案，不修改业务代码。

设计依据：[server-v2-narrative-output-design.md](server-v2-narrative-output-design.md)。协议细节与边界以设计文档为准；本文件用于拆分实施顺序和验收事项。

## 1. 定义能力结果与受控保存契约

- 在 sessions 模块定义并公开 `extData.output` 的结果类型，首期包含 `stateUpdate`、`actionSuggestions`。
- 能力级和状态更新行级的 `status` 均只允许 `success | fail`。出现失败时保存诊断，不引入部分成功、未变化、跳过等业务状态。
- 状态结果分别保存成功接受的更新及逐行处理结果。能力整体为 `fail` 不代表成功行被回滚，也不代表没有状态变化。
- 主模型正常完成时，状态与建议的标签缺失、空白标签均保存 `success` 和空结果；建议的合法空数组同样表示无建议。
- 增加受控的叙事助手保存能力。公共追加、编辑不能伪造或删除能力结果；普通正文编辑不重新执行已记录的更新。
- 删除本期的 `contextEligible` 及其专用编辑失效设计。`extData.output` 用于处理结果保存与查询，不承担模型旁注契约。

验收：所有新增结果状态仅为 success/fail；旧 entry 无 output 时正常读取；失败诊断与成功数据可以共存；无新表或 schema version 变更。

## 2. 实现流式分离与独立标签扫描

- 增加叙事内部的流式分离和标签扫描能力，流式与最终快照使用一致的正文隔离规则。
- 支持大小写不敏感的开始、结束标签；正确处理跨分片标签、未完成前缀及 UTF-16 代理对。
- 外层先定位能力片段，各能力再解析自己的内容。后续标签定位不得依赖前一个能力的 JSON 是否闭合或字符串状态是否完整。
- 当前能力缺少闭合标签时，遇到后续完整的能力开始标签，按设计规则结束当前片段、记录局部错误并继续扫描。
- 标签损坏、重复、顺序变化和未知片段均不得触发整个尾部失败。无法可靠识别的损坏内容不猜测修复，也不阻止后续正常能力处理。
- 状态片段即使有边界错误，仍按设计处理其可完整解析的独立行；建议的损坏片段不能覆盖此前有效候选。
- 最终模型快照重新分离；最终 snapshot、持久化正文与能力处理输入来自同一份最终结果。
- 删除原方案全尾部 256 KiB 上限和固定 100 条更新要求；不预设新的能力总长度或条目总量配额。既有单值资源校验失败仅作用于本行或本片段，后续扫描继续。

验收：已识别的数据块不进入公开正文；一个能力少引号、少闭合标签或处理失败时，后续完整能力仍可识别；大小写与跨分片不改变语义。

## 3. 实现 JSONL 状态更新与逐行隔离

- `state_update` 改为 JSONL：每个非空物理行是一个完整的 `{path,value,reason?}` 对象，不使用外围数组。
- 兼容单条更新与开始、结束标签位于同一行的写法；空白行忽略，字符串内换行使用 JSON 转义。
- 每行独立完成 JSON 解析、对象结构检查、路径和值校验、候选快照更新。任一步骤失败只记录该行 `fail`，继续后续行。
- 扩展 StateService 的模型更新候选能力，复用既有路径、类型、rules 和继承快照处理，限制为 message scope 与本轮激活根。
- 路径不存在时记录该行失败；公共 PATCH 的缺失路径忽略语义保持原契约。
- 成功行按原顺序更新候选快照，重复路径按顺序覆盖。同值替换仍为 `success`，是否产生事件由实际变化决定。
- 单行计算使用可回退的工作副本，失败不得留下半次修改，也不得抹去此前成功行。保留非目标根与已有条目元数据。
- 无激活根且无更新为成功无操作；非空更新逐行拒绝，不妨碍其他能力。

验收：覆盖坏 JSON、缺失字段、非法 path/value、类型与规则错误、重复路径、同值、空标签和缺失标签；任意坏行前后的有效行均可成功提交。

## 4. 接入提示词及能力执行隔离

- PresetService 提供内置输出提示词解析与默认补足；narrative 通过公开能力取用，不依赖 presets 内部文件。
- 更新状态 JSONL、空标签、标签大小写及字符串中的保留标签转义规则；静态示例只用于说明格式，不要求模型照抄值。
- 保留两项默认叙事能力的既定方向：状态材料按最终激活根提供，建议提示词正常参与；没有输出标签不报缺失错误。
- 内置节点缺失/提示词为空时补默认提示词，旧 enabled 不再禁用服务端执行，不批量修改预设或 revision。
- `action_suggestions` 保持 JSON 数组格式。有内容时沿用三条非空、去重字符串及每条不超过 50 个 Unicode 码点的内容规则。
- 每个能力设独立异常边界。状态读取、定义获取、候选计算或建议处理抛错，只转为对应能力的失败结果。
- 进入 SessionService 前受控校验各能力结果；状态行的更新、记录和诊断在该行接受前完成规范化。保留已验证行及对应快照，确保 updates 与实际提交一致，不因单行或其他能力异常清空有效结果。
- 正文主流程正常完成时，任意能力失败均不改变 `run.completed`；不增加修复请求或辅助模型调用。

验收：状态基础读取失败仍能保存正文并处理建议；建议处理异常不影响有效状态；缺失和空结果均成功；能力错误不成为 run 的停止原因。

## 5. 接入叙事收尾与提交

- model-call 在叙事调用中接入正文分离；摘要调用继续使用既有纯文本处理。
- 主流程校验当前实际 tip/expected parent；收尾事务内读取状态材料的能力错误仍在状态能力内部收敛。
- 通过同步事务保存助手正文、能力结果、有效状态候选及 metrics，并原子推进 seq/tip。
- 能力整体 `fail` 时仍提交该能力中已经验证成功的数据；状态失败不阻止保存有效建议。
- 有实际状态变化时保存完整更新快照；无变化或没有可靠候选时继续采用既有继承方式。
- 用户终态仍按既有流程独立保存，收尾形成已提交结果和通知列表后再发布事件。
- 模型错误、取消、length 等主流程未正常完成时，不执行本轮能力副作用；保存部分助手时按设计用 `fail + MODEL_NOT_COMPLETED` 记录，不新增 skipped，不报标签缺失错误。
- 模型、正文有效性、tip 冲突及正文/终态持久化失败继续使用既有主流程失败语义，不伪报完成。

验收：成功行不会因其他能力或其他行失败回滚；助手追加失败不产生状态或建议成功通知；取消不应用能力；执行锁覆盖处理与落库。

## 6. 更新事件与读取契约

- 实际状态变化提交后，发布既有 `state.changed`，空 path 表示完整有效 message 快照。
- 建议事件统一为 `action_suggestions.created`，保留 sessionId、runId、messageId、items 的扁平结构。
- 仅在本轮保留了有效非空建议、结果已保存且主流程完成时发布 created。空或缺失标签不制造建议事件。
- 新一轮通过 `run.created` 清空旧建议，不发送 messageId=null/items=[] 的 created 清空事件，也不另增清空事件。
- 状态与建议是否通知分别依据实际提交的数据，不以另一个能力的结果为条件；同能力其他片段失败也不抹去已验证的有效数据。
- 能力诊断通过已有单轮详情与历史 entry 读取；首次恢复只认最新轮次的真实结果，不向前寻找旧建议冒充当前结果。
- 每条能力通知独立捕获发布异常，继续发布剩余能力通知、run.usage 和唯一终态；不回滚、不重执行能力，不反向改变已提交结果或其他能力。

验收：能力为 fail 但有成功状态变化时仍正确通知；无有效建议不发 created；通知在对应提交后产生，终态后不再发布本轮能力通知。

## 7. 收敛上下文与预算边界

- 删除本期的输出块重建模块、双历史投影、历史标签拼接和相关验收任务。
- 聊天、关键词激活、摘要及当前主模型历史继续使用干净正文；历史读取不重放状态操作。
- 条目级 `model-only notes` 后续单独设计，可服务 user、assistant 等条目的模型输入附加内容；本期不确定其存储结构或建立框架。
- 状态更新和行动建议未来作为模型旁注来源接入统一输入上下文能力，本期不直接拼接这两类标签。
- 按模型实际输出处理，不新增按能力分配的输出 token 预算；调用复用既有 `max_output_tokens`，实际用量以模型返回 usage 为准，包含隐藏输出。
- 输入上下文仍由既有上下文模块管理，实际参与请求的提示词纳入原流程；本方案不另行设计压缩预算，不以输出 tokens 替代输入预算。

验收：本期没有历史能力块回填、contextEligible 或 notes 实现；新增提示词进入正常请求构建；不根据能力输出推算另行判定 run 超预算失败。
