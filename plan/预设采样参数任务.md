# 预设采样参数实施任务

按下列顺序实施，每项以右栏条件验收。

| 任务 | 改动位置与交付 | 验收条件 |
|---|---|---|
| 1. 扩展预设契约 | Server 的 `modules/presets/{schema,card,repository,service,default}.ts` 与 Web 的 `features/presets/{types,adapter}.ts`。补齐三项可选数值、双向字段映射及两端校验。 | 旧记录、旧文件正常读取；新增值经过创建、保存、读取、复制、导出再导入仍相等；缺省、0、负数和高精度值可区分，越界及非法类型被拒。 |
| 2. 制作数值控件 | 在 Web `components/ui` 增加主题化原生范围控件；在预设功能中组合滑块、精确输入和默认态，复用 Field、Button 与焦点样式。 | 方向键、Home/End、标签、错误关联和恢复默认均可用；包含端点和双向同步，滑动步长不会丢失既有温度精度。 |
| 3. 接入预设编辑页 | 在 `PresetLibraryPage.tsx` 的模型参数区放置四个范围字段，接入 `PresetStore` 已有草稿、复制、保存和撤销语义。 | 初次打开无脏标记，旧显式温度正确回显；手输到一半不会误保存，恢复默认后提交不含该键；手机单栏和浅深主题符合 UI-SPEC。 |
| 4. 落实后端能力规则 | 盘点当前 SDK 目录和现有温度通道，在 `infrastructure/pi` 建立逐路由、逐模式的采样投影和对应的来源／测试样例。至少覆盖方案中的全支持、部分支持、未知及组合受限情形。 | 相同模型名不同路由独立匹配；模式回退、开区间、固定参数、冲突及未知参数均产生预期的应用或忽略结果。 |
| 5. 接通两条模型请求 | 从 `usecases/context` 既有快照经 assemble / summarize、`usecases/narrative` 调用点传至 `infrastructure/model/client.ts` 与 `infrastructure/pi/client.ts`；在 Pi 边界一次过滤和映射。 | 同一轮中预设被编辑也不影响已接受的主请求与摘要；验证实际 SDK 编译的 payload，覆盖目录默认值的优先级、显式 0、遗漏字段及只读诊断。 |
| 6. 回归并更新项目契约 | 扩展 Web 数据／参数测试和 Server 预设、context、Pi 适配测试。将已实现行为写入 `docs/runtime/server-http.md`、`server-narrative.md`、`web-management.md`、`docs/design/UI-SPEC.md` 与相关 AGENTS.md。 | 通过两端函数级测试及根目录 `pnpm typecheck`、`pnpm lint`。以现有 SDK 测试接缝或内存 fetch 拦截验证最终请求，不启动服务、不调用付费模型。 |
