# WorldStory 消息操作任务

状态：待实施；本文不是执行授权。配套方案见 [消息操作方案](WorldStory-消息操作方案.md)。按依赖顺序实施，所有任务当前未完成。

## 1. 定义产品与共享协议

- [ ] 固化最后回复资格、开场保护、纯正文编辑、连续尾部删除、失败保留旧回复和等待回复状态。
- [ ] 在 Server 与 SDK 公共契约中定义 historyRevision、attemptId、操作结果、冲突错误、变更事件与操作资格投影；更新 stop 协议使其准确指向 attempt。
- [ ] 验收：普通发送和重生成的身份语义无歧义；不能伪造新用户消息适配旧接口。

## 2. 增加存储与计量基础

- [ ] sessions 增加历史版本及单调 seq 分配；为实际删除/替换提供 sessions 域私有原子存储方法。
- [ ] 增加请求计量记录，按 requestId 从现有 metrics 迁移去重；汇总改为单一来源，latestContext 识别失效历史。
- [ ] 验收：迁移可重复执行；截断后新消息不复用 seq；删除/替换后旧用量仍在且不重复统计；未知用量不变零。

## 3. 实现正文编辑用例

- [ ] 增加正文专用输入校验、会话权限、锁、tip/revision 冲突检查和编辑标记。
- [ ] 接入既有通用 PATCH 的版本/通知路径；保留系统字段和原后处理记录，复用摘要 sourceHash 校验。
- [ ] 验收：编辑不调用模型或更新状态；冲突不覆盖新内容；修改摘要覆盖内正文后旧摘要不可再用。

## 4. 实现删除范围预览和尾部删除

- [ ] 服务端返回真实删除范围、消息数和保留边界；保护初始开场。
- [ ] 在 usecase 中原子删除尾部与关联 compaction、修正 tip/轮次结果/revision；重新投影有效 message 状态和建议。
- [ ] 验收：删除 AI 留下待回复用户；删除用户同时移除其后内容；session/global 不回退；确认期间版本变化则拒绝执行。

## 5. 扩展上下文候选准备

- [ ] 将“新保存用户生成”与“复用已有用户生成”输入显式区分，复用 context 内部算法。
- [ ] 候选排除旧回复正文、模型旁注与 message 状态；摘要草稿不提前推进有效历史。
- [ ] 验收：新生成不含被替换内容；正常发送的用户先保存与成功摘要持久化契约保持正确；失败候选摘要的计量与有效历史分离。

## 6. 实现重新生成与补生成

- [ ] 复用执行、停止、模型调用和后处理能力，按 attemptId 隔离执行；用户输入 ID 保留。
- [ ] 有旧回复时成功后原子替换；失败/停止保留旧回复。没有旧回复时复用普通部分输出保存语义。
- [ ] 按 permit 与版本结算，持久化真实请求计量及最近尝试结果，提交后发布事件。
- [ ] 验收：无重复用户；不中途执行新状态；失败不损坏旧历史；旧 stop/delta 不影响新 attempt。

## 7. 接入 Web feature 与 Stage SDK

- [ ] history 支持按 revision 更新/删除、分页失效和重连重读；narrative 支持候选覆盖与持久化交接。
- [ ] workspace 组合操作、宿主删除确认与各 feature 刷新；新增 SDK 窄命令，保持 stage-host 只负责桥接。
- [ ] 验收：漏事件、乱序 HTTP、旧分页、多个窗口修改均不复活已删除内容；状态/建议/用量一致。

## 8. 实现 WorldStory 交互

- [ ] 紧凑消息菜单、最后回复重生成入口、原位编辑、保存/取消、已编辑标记、补生成入口和停止反馈。
- [ ] 删除确认准确显示级联范围；移动端不依赖 hover；错误保留草稿和旧回复；保持滚动锚点与键盘焦点。
- [ ] 验收：生成中/未同步/离线的操作状态一致；正文编辑影响说明清楚；复用现有 token 与尺寸。
