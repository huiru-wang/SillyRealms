# SR World Author

## 建立当前任务边界

1. 确认所在仓库及其 AGENTS.md，检查现有源目录和未提交修改。以本 Skill 所在的 `skills/sr-world-author/` 向上两级确定仓库根；所有相对命令在该根目录执行。不要硬编码用户路径或安装目录。
2. 识别用户要新建、修改还是排错；保留已有角色、设定、素材和明确约束。先完成已授权且可判断的工作；只在无法继续的关键创作选择或缺失原材料处询问。
3. 用简短说明确定玩家身份、当前目标、核心人物、开局、需要持久化的变化及呈现方式。没有自定义 UI 需求时复用官方正文。
4. 编辑创作源，不直接改运行数据库或 data 下已导入的副本。源目录与输出文件可由用户指定；没有指定时选清晰的新目录，避免覆盖同名作品。

本 Skill 是仓库内流程，依赖同一 checkout 的 docs、examples 与 scripts；不要求全局安装、AgentDock 专用命令或私有环境变量。

## 制作

1. 从最小示例或用户现有作品出发，保留稳定 ID，写清玩家能做什么。至少提供可扮演角色和有效开局。
2. 先把内容跑通，再增加最少必要状态。为每个状态选择生命周期、初值、含义和容易误判的更新依据；让界面与叙事读取同一事实。按格式参考区分定义、开局覆盖和当前值。
3. 需要 UI 时确认它运行在介绍、开局预览、会话舞台还是消息片段。按 SDK 的实际环境选接口；保留平台输入和历史同步职责，优先组合 SR.WorldStory。
4. 把可分发素材放入包内，按声明登记组件和资源。保留作者与来源说明；缺少素材时明确记录，不能用失效占位 URL 冒充完成。
5. 将作品说明保存在创作源目录，记录身份、开局、玩法、状态、版本和试玩步骤。JSON 与 TSX 保持可读，不压成难以继续修改的一行。

不得凭空发明 SDK API、模型变量、状态更新协议、自动迁移能力或支持的第三方 npm 包。拿不准时读取链接的参考与源码。

## 检查实际交付物

在仓库根执行：

~~~sh
pnpm world:check <source-directory>
pnpm world:pack <source-directory> --out <output.zip>
pnpm world:check <output.zip>
~~~

用实际路径替换占位。输出已存在时选择新版本文件名，保留已有交付。JSON 单文件作品也可先用 world:check 检查该 JSON；外置组件或包内素材必须随 ZIP 交付。

检查失败就按诊断修复并重跑有关步骤；不要通过删除原内容、跳过检查或放松校验器使作品“通过”。不需要为低影响文字修改增加与风险无关的测试。

有适用的浏览器和模型环境时，导入最终包，检查介绍、开局、会话、关键交互与窄屏布局，并验证一次状态变化。环境不可用时仍完成静态可交付部分，清楚标明尚未实测的行为。不要把组件静态编译或模拟数据称为真实试玩。

## 交付

给出：

- 源目录和最终 JSON / ZIP 路径，以及本次改动摘要。
- 玩家身份、开局和核心玩法；已有作品的保留范围。
- 已执行的检查命令与结果，失败或未执行项及原因。
- 三到五步试玩说明，包括应观察的结果。
- 素材来源、依赖与真实已知限制。

不要声称修改创作源会自动更新既有会话。发布、安装全局 Skill 或修改平台业务代码不属于本流程。
