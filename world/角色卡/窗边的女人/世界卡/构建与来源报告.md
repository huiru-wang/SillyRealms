## 玩家体验与改编范围

玩家在 2016-02-01 登录宁温河馨论坛，从一名原作角色的私密经历出发。AI 扮演其他五人及主持/游客。调查对象仍是 2006 年邓爱欣案。保留第一幕地图寻尸、第二幕人物资料、第三幕事件与日记、终局选择和复盘。

六个角色版本保持相同案件与证据，只改变首位可扮演角色、角色专属开局和手册身份。每版提供一般/困难开局，仅 8 号图片差异。没有另造调查员，没有更换直接凶手、分尸者、旧案因果或最终操盘者。

文字重新组织为第三人称主持信息与第二人称玩家私密角色本，保留事件、动机、主观误判、关系、目标与知识边界；不逐句移植全部角色本。重复游客对白合并为主持阶段说明，以允许真实对话。暴力、性侵及遗体处理描写压缩为非露骨事实和证据，保留责任与推理关系。原作中的疾病、职业与性别偏见归属于角色错误，不写成旁白定论。

## 加载与状态

六个角色 prompt 和五个 lore 条目采用 `always`。这个封闭案件的 NPC 动机、主持真相和35张有限证据必须随时可供主持查询，不能因为本轮没有命中名字而失忆。常驻不等于全部公开；信息发放由阶段和人物知识边界规约约束。角色公开简介没有注入模型。当前玩家的私密角色本同时作为首条消息供玩家阅读，这是有意的少量重复，保证长会话压缩后角色动机仍在常驻 prompt。

lore 顺序：主持规则0 → 公共案情10 → 地图20 → 真相30 → 证据40。没有关键词加载、停用项、when 或伪装成确定权限的隐秘字段；因此关键词命中/排除/when测试不适用。

| message 项 | 含义 | 初值 | 更新与展示 |
| --- | --- | --- | --- |
| chapter | 1–5阶段 | 1 | 模型在玩家确认推进时更新；必须整阶段 |
| progress | 身份、难度、日期、已确认路线 | 本角色/对应难度/2016-02-01/[1] | 身份与难度固定，路线只累积已发现点 |
| publicClues | 公开证据ID | [30] | 调查手册公开区 |
| privateClues | 仅当前玩家已见未公开证据 | [] | 调查手册私密区 |
| ledger | 六人抽卡、屏蔽、私聊、隐藏 | 各抽卡[]、其余[] | 模型检查去重及配额；面板只显示本人的使用量 |
| notes | 已知事实和假设 | [] | 明确标注事实/假设，不存未来谜底 |
| ending | 终局选择、结算、投票 | 空选择、未结算、空死亡名单、null投票 | 不提前填答案；允许所有人拒绝报复 |

每个开局显式提供所有状态项的完整快照；无 global/session 状态，不会让另一局读取本局进度。面板只读 SDK 已提交状态，自身仅保留展开、图像旋转与地图缩放。官方 `SR.WorldStory` 承担历史/流式/失败/停止提示，未重做会话循环，未读取父页面或直接调用 Server HTTP。

`ledger`、阶段门槛、隐藏信息和终局同时结算是模型遵循的业务规则，不具有服务端强制约束。`json` 类型只做通用校验。必须与实际主持模型进行人工实玩才能评价它能否始终遵循。

## 独立审查与修复

完成初稿后单独检查了原件、卡面、prompt与实际渲染，发现并修复：

1. 地图34号最初误归为垃圾站，按原图矩形图例改为废品站。
2. 资源/线索模块最初默认导出普通对象，虽过结构和依赖检查，但运行加载器要求 React 组件。已改为默认导出无UI组件并附静态数据，保留卡内默认静态导入；未修改应用加载器。
3. 手机手册覆盖正文时，增加对被覆盖故事区的可见性隐藏，避免键盘落到遮挡区域；Escape恢复触发按钮焦点。
4. 在375px/1280px截图中发现宿主输入框覆盖手册底部，增加 `--sr-story-bottom-inset` 对应滚动留白，并验证滚至底部时旋转按钮完全位于输入框上方。修正两处中文标点相邻的 Markdown 粗体标记。
5. 隔离测试启动文件改用 `.mts`，并把路由注册移到首次请求之前。这些仅为本卡验收工具修复。

源材料仍有上述缺失与冲突，不能声称“原音视频完整还原”或“真实模型全程体验已通过”。
