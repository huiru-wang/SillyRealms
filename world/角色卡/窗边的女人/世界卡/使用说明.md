# 窗边的女人 · 世界卡

按 75先生《窗边的女人》原作改编：你扮演一名原作角色，其余五名角色、游客与主持人由 AI 演绎。保留原作案件、三幕推进、人物秘密、地图调查和终局选择。

## 导入哪个文件

当前 Studio 创建会话使用第一名可扮演角色，尚无角色选择控件。因此分别提供六张卡；每张只将对应人物设为可扮演，另外五人作为 NPC。无需全部导入。

| 黑弥撒 | [窗边的女人-黑弥撒.json](窗边的女人-黑弥撒.json) |

1. 在 Studio 世界卡页面导入选定 JSON。
2. 配置可用模型、凭据与预设。本次构建没有修改你的应用配置或数据库。
3. 建议使用至少 128K 上下文的模型，预设输入预算先设为 65536、输出预算 4096，开启 `state_update`；行动建议可选。预算是保守起点，不是实测 token 数或对所有模型的保证。
4. 选择一般或困难开局。二者只沿用原作第 8 号线索的区别，不改变谜底。
5. 阅读开局里的“你的私密角色本”，然后开始自我介绍或调查地图。私密角色本不是你已经公开的发言。

所有图片已嵌入 JSON，导入时不必另外上传 `assets/`。这些原作素材不依赖外链；模型推理是否可离线取决于你的本地模型配置。

## 怎样玩

直接在输入区表达行动，例如“询问黑弥撒当晚几点下班”“我想查看某人的一条线索”“这条线索暂时隐藏”“我申请与某人私聊”。你可以请求提示、回顾证据，或明确表示准备进入下一幕。AI 不应替你坦白、投票或作出终局决定。

“调查手册”只显示已提交的公开线索、你自己的私密线索、原地图及记录；8 号图像线索获得后可以旋转。地图可放大、滚动。搜证、公开和私聊仍通过对话进行，面板本身不修改剧情状态。手机上可用“返回对话”收起手册，键盘可按 Escape。

世界书、`角色与线索.json`、构建脚本和来源报告包含主持人秘密。首次体验只看介绍与自己的开局，避免提前翻阅这些文件。此为本地单用户作品，保密是叙事规则，不是防止文件检查的访问控制。

## 已验证与限制

已完成结构/引用校验、隔离库导入导出、十二个开局状态核对、真实 Studio 浏览器组件加载和离线模型管线检查。具体结果见[验收记录](验收记录.md)。

原作音视频没有随素材提供。本版只把组织者手册明确说明的信息改为文字证据，没有制作或冒充缺失视频。原作医学、药物和眼球成像有架空设定；性侵与暴力以非露骨事实呈现，疾病与谣言不被视为人物有罪的依据。

搜证配额、人物知识边界和推进节奏由叙事模型执行，平台只校验状态类型与提交；本卡不是确定性剧本杀裁判。尚未用真实模型完成六角色全流程实玩，不能将离线合成回复的测试当作推理与主持质量验收。

## 文件维护

- `构建.py`：角色设定、主持规约、真相底稿和证据目录，离线生成六张卡。
- `components/`：介绍、官方故事舞台的包装、只读调查手册与资源模块。
- `assets/`：原地图的显示副本、原作封面、两种 8 号线索卡面。
- `来源清单.json`：九份原 PDF 与一张地图的 SHA-256。
- [构建与来源报告](构建与来源报告.md)：**含完整剧透**，记录来源、删改与冲突。
- `验收/`：隔离测试脚本、机器结果与截图。

重建命令（仓库根目录）：

```sh
python3 'data/角色卡/窗边的女人/世界卡/构建.py'
```

只重写本目录生成产物，不导入数据库，不调用模型，不修改原始 PDF 和地图。
